# 1장 — 메시는 두 번째 HTTP 구현이다

- 기간: 2026-10-21 ~ 2026-11-12
- 관련: 공개 회고 PDR-001(`docs/chapters/01-architecture.md`), 아키텍처 기록(`docs/architecture/chapter-1.md`), 리뷰 원문 `reviews/ch1-r1~r4-review.md`, 측정 원본 `measurements/`

## 결정과 이유

### 1. HTTP 계약 범위를 사용자가 정했다 (2026-10-22)

3라운드 리뷰에서 경계 조건이 끝없이 나왔다. 0장 Perl 파서는 요청줄만 읽고 헤더를 거의 보지 않는데, Envoy는 RFC 9112를 엄격하게 지킨다. 비정상 바이트 조합은 무한하다.

→ **RFC 9112 origin-form 정상 요청은 0장과 완전히 같게, 비정상·non-origin-form 입력은 C-14 하나로 일괄 등록.** 이후 챕터도 이 경계를 따른다.

이 결정 뒤에도 4라운드에서 HIGH 3건이 나왔지만, 전부 경계 안쪽(정상 요청)의 진짜 차이였다(HTTP/1.2 수락, 웹소켓 업그레이드가 CSV 바이트를 바꿈, 8KB 초과 헤더). 경계가 리뷰를 수렴시켰다.

### 2. 구현은 Codex, 리뷰는 Claude (2026-10-21~)

메모리 규칙대로 구현 6라운드를 전부 `codex exec gpt-6.1-sol max + priority`로 위임했다. 라운드마다 새 프로세스, 지시서와 리뷰 원문 경로만 넘김. 리뷰는 Claude opus 서브에이전트로 매번 새로 띄웠다.

- 메인(나)은 docker·kubectl이 필요한 일(클러스터 구축, 배포, parity, 소크, 부하)과 판단만 맡았다.
- Codex 자체 리뷰의 "PASS"는 그대로 믿지 않고 항상 테스트를 다시 돌렸다.
- 3라운드는 세션 종료로 Codex가 중간에 끊겼다 → `codex exec resume <session id>`로 이어서 살렸다.

### 3. 게이트웨이 자원을 부하 테스트 전에 늘리지 않았다

5,000명에서 게이트웨이가 OOMKilled됐을 때 자원을 늘리고 다시 재는 선택지도 있었다. 하지 않았다. 늘리는 건 새 구현 결정이라 리뷰 루프가 다시 필요하고, T6의 목적은 "무엇이 먼저 죽는가"의 기록이다. 결과적으로 **"How is this scalable?"의 실측 답 = 게이트웨이 파드 하나(0.2코어·256MiB)**라는 명확한 결론이 남았다.

## 배운 것

### 기본값이 계약을 조용히 바꾼다

가장 비싼 발견은 구현 버그가 아니라 플랫폼 기본값이었다: Istio 경로 정규화, Envoy 웹소켓 업그레이드, Neo4j 이미지의 환경변수 해석, Kubernetes service links. 각각은 합리적이고 보안상 좋은 기본값인데, 오류를 내지 않고 **다른 숫자**를 냈다.

→ 다음 챕터 체크리스트: 새 계층(런타임·프록시·플랫폼)이 들어오면 parity 원시 케이스를 먼저 돌려 기본값 차이를 잡는다. 기능이 아니라 기본값부터 의심한다.

### 0장 계약이 부하의 천장이 된다

"연결당 요청 하나"를 정확히 재현하자 모든 요청이 새 TCP 연결이 됐고, 맥 → colima VM 포워더가 1,000명에서 먼저 무너졌다. 계약을 지킨 결과가 성능 상한을 정했다. 부하 생성기는 클러스터 안으로 옮겨야 클러스터 자체를 잴 수 있었다.

### 노트북 위 k8s는 전원 관리에 약하다

VM이 비정상 종료되자 etcd WAL CRC 불일치로 컨트롤 플레인이 영구히 못 뜨게 됐다. 볼륨을 tar로 백업(594MB → 13MB)한 뒤 `up.sh`로 재구축(7분 10초). 이후 VM 재시작은 반드시 `colima stop`으로 정상 종료한다.

### 이벤트 로그가 두 번 살렸다

etcd 재구축 후에도, 포워더 붕괴 후 VM 재시작에도 수치와 카운터가 그대로 돌아왔다(투영이 오프셋 0부터 재생). S-01 아키텍처의 가장 강한 근거이면서, S-01 아키텍처 때문에만 필요했던 것.

## 운영 메모

- 클러스터 재기동 후 kubeconfig 포트가 어긋나면 `kind export kubeconfig --name shipping-a-button`.
- 부하 테스트는 `tools/load/in-cluster.sh`(k6 파드, 4GiB 한도). 호스트에서 쏘는 `step.sh`는 포워더를 무너뜨린다.
- colima `default` 프로필은 1장 동안 6 CPU / 12GB로 바뀌어 있다(원래 2 CPU / 2GB).
