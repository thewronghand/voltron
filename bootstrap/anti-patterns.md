# 하네스 설계 안티 패턴

다음은 best practice인 줄 알고 도입했다가 후회하는 패턴들.

## 1. 가상 미래 대비 규칙 (YAGNI 위반)

**증상**: "혹시 모르니까", "나중에 X 상황 올 수 있으니까" 추가한 규칙·훅·에이전트.

**문제**: 일어나지 않은 일에 대한 가드는 어텐션·인지 부담만 늘리고 효과는 0. 진짜 일어났을 때 추가하면 늦지 않음.

**대신**: 실제 발생한 lessons에서 패턴 추출해서 추가.

## 2. 박물관 운영

**증상**: 한 번 추가한 규칙·훅·에이전트를 절대 빼지 않음. 6개월 전 컨벤션이 지금도 CLAUDE.md에 박혀 있음.

**문제**: 죽은 규칙은 살아있는 규칙의 신뢰도까지 떨어뜨림 ("아 이것도 무시해도 되는 거지" 학습됨).

**대신**: 분기마다 점검. 작동 안 하는 규칙은 회수.

## 3. 자동화 만능주의

**증상**: 모든 결정 지점을 자동화. 사용자 컨펌 단계를 다 빼버림.

**문제**: 신입이 자동화에 의존하면 머릿속에 안 남음. 같은 결정을 매번 AI가 대신해주면 학습 곡선이 평평해짐.

**대신**: 결정적 작업만 자동화. 판단·학습 가치 있는 작업은 사용자 게이트 유지.

## 4. 한 컨텍스트 비대화

**증상**: 메인 컨텍스트가 모든 일을 직접 처리. 에이전트 위임 안 함. 컨텍스트가 가득 차서 lost-in-the-middle 시작.

**문제**: 결정 품질 저하. 긴 세션 후반엔 초반 결정을 잊음.

**대신**: 무거운 탐색·외부 검색·리뷰는 에이전트로 격리. 메인은 결정과 통합에 집중.

## 5. 자기 평가 (자기 코드 자기 리뷰)

**증상**: 같은 컨텍스트에서 코드 짜고 그 코드 검토. 또는 같은 CLAUDE.md/규칙을 공유한 서브 에이전트로 검토.

**문제**: 사각지대가 같음. 메인이 OK라고 생각하는 패턴은 reviewer도 OK. **자기 코드는 아니지만 같은 잣대를 공유**한 상태에서의 평가.

**대신**: 중대한 결정은 외부 시각 (사람 리뷰, 다른 시스템 프롬프트의 도구). 일상 리뷰는 서브 에이전트로 충분.

## 6. CLAUDE.md 비대

**증상**: CLAUDE.md가 한 화면을 넘어 200줄, 500줄로 자라남. 모든 규칙이 다 중요해 보임.

**문제**: 어텐션이 분산. 정작 중요한 Critical Rules가 눈에 안 띔. 매 세션 시작마다 토큰 비용.

**대신**: CLAUDE.md는 한 화면. 상세는 가이드 문서로 분리. 인덱스 역할만.

## 7. 차단형 훅 일색

**증상**: 모든 훅이 `exit 2`로 작업 멈춤. 사용자가 매번 개입해서 우회.

**문제**: Claude가 자가 교정 못 하니 흐름이 끊김. 사용자가 훅을 끄고 싶어짐.

**대신**: stderr에 구체 재시도 명령 같이 보내서 Claude가 자가 교정.

## 8. 도구 중복

**증상**: 비슷한 일을 하는 에이전트·스킬이 여러 개. "어느 걸 써야 하지?" 매번 고민.

**문제**: 위임 결정에 토큰·시간 소비. 에이전트들 간 책임 경계가 흐려짐.

**대신**: 새 에이전트 추가 전에 "기존 에이전트로 안 되는 게 뭔가" 명시. 답이 모호하면 기존 것을 보강.

## 9. 외부 트렌드 무비판 도입

**증상**: 블로그·트위터에서 좋다고 한 패턴을 프로젝트 맥락 검토 없이 그대로 도입.

**문제**: 다른 사람의 환경·팀 규모·도메인에서 유용했던 게 여기선 노이즈일 수 있음.

**대신**: 트렌드는 영감으로만 받아들이고, "이게 이 프로젝트에서 막을 실패가 뭔가"부터 검증.

## 10. 메모리 오염 (Memory Poisoning)

**증상**: lessons 또는 메모리에 한 번 잘못 기록된 교훈이 이후 세션에서 계속 인용되며 잘못된 패턴을 유도.

**문제**: 메모리는 "검증된 사실"로 취급되기 쉬워서, 한 번 들어간 잘못된 정보는 자가 강화된다. 단 한 번의 실수가 반복 실수 머신이 됨.

**대신**:
- lessons 작성 시 **재현 가능한 사실**과 **추론된 일반화**를 구분해서 쓰기
- 일반화는 "다음에도 이럴 가능성 높음" 정도로 약하게 표현
- 메모리·lessons에서 정보 인용 시 **"이게 지금도 맞는지"** 검증부터
- 같은 메모리가 의심받는 일이 두 번째라면 즉시 회수·갱신

## 11. 메모리·문서 분산

**증상**: 같은 종류 정보가 CLAUDE.md, 가이드, 메모리, 쿡북, lessons에 흩어져 있음. "이거 어디 있더라?" 매번 검색.

**문제**: 일관성 깨지기 쉬움. 한 곳 갱신하고 다른 곳 까먹음.

**대신**: 정보 종류별로 한 위치 확정. 다른 곳에선 링크만. ([`adding-rules.md`](adding-rules.md)의 "어디에 둬야 하나" 참조)
