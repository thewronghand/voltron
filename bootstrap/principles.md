# 하네스 진화의 원칙

## 1. Ratchet 원칙

**모든 규칙은 실제 실패 사례로 소급 추적 가능해야 한다.**

새 규칙을 추가할 때 다음 중 하나를 명시할 수 있어야 한다:
- 이 규칙이 막았을 과거 실수 (lessons에 있는 게 이상적)
- 이 규칙이 없어서 발생한 혼동/낭비
- 외부에서 검증된 베스트 프랙티스 + 해당 프로젝트 맥락에서 적용한 이유

**금지**: "이렇게 하면 좋을 것 같아서", "일반적으로 이렇게 한다더라"만 가지고 추가하지 말 것. 가상의 문제에 대비한 규칙은 노이즈가 된다.

## 2. 다이어트 원칙

**규칙이 많을수록 어텐션이 분산된다.** 60줄·100줄 같은 절대 기준은 없지만, CLAUDE.md가 한 화면을 넘어가면 점검 시점이다.

점검 기준:
- 이 규칙이 마지막으로 작동한 게 언제인가? (3개월 넘게 작동 안 한 규칙은 후보)
- 이 규칙을 빼면 무슨 일이 벌어지나? (아무 일도 안 벌어지면 빼도 됨)
- 다른 규칙으로 흡수 가능한가? (중복 통합)
- **Claude가 이 규칙 없이도 이미 잘 하는가?** (이미 하는 일을 명시하면 다른 규칙의 신호 대 잡음비를 떨어뜨릴 뿐)

**금지**: 한 번 추가한 규칙을 절대 빼지 않는 박물관 운영. 진화하지 않는 하네스는 곧 무거운 짐이 된다.

## 3. 차단보다 교정

훅·가드는 **막는 것**보다 **교정하는 것**이 강력하다.

- 나쁨: "develop 편집 금지" → 작업 멈춤
- 좋음: "develop 편집 금지. `git checkout -b feat/X origin/develop`로 분기 후 재시도" → Claude가 자가 교정

훅이 `exit 2` 할 때 stderr에 **무엇을, 어떻게** 고치면 되는지 구체 명령을 함께 보낼 것. 단순 "안 됨" 메시지는 사용자 개입을 강제할 뿐이다.

## 4. 컨텍스트 분리

**한 컨텍스트 = 한 책임.** 같은 컨텍스트에서 코드를 짜고 그 코드를 검토하면 같은 사각지대를 둘 다 못 본다.

- 메인 컨텍스트: 사용자와 대화, 결정, 통합
- 서브 에이전트 컨텍스트: 격리된 책임 (구조 분석, 백엔드 추적, 외부 검색, 리뷰)
- 외부 도구: 같은 모델이라도 다른 시스템 프롬프트·다른 컨텍스트로 호출

**주의**: 서브 에이전트도 같은 CLAUDE.md를 공유하면 **획일화 편향**이 남는다. 중대한 결정은 외부 시각(사람 리뷰, 다른 시스템 프롬프트의 도구)을 끌어올 것.

## 5. 진화는 작고 자주

하네스 변경은 **한 번에 하나, 작게**. 큰 리팩토링은 위험이 누적된다.

- 새 훅 추가 → 며칠 써보고 효과 확인 → 다음 변경
- 새 가이드 추가 → 실제로 참조되는지 관찰 → 안 쓰이면 회수
- 새 에이전트 추가 → 첫 사용 시 메인 컨텍스트가 잘 위임하는지 확인

**금지**: 하루에 훅 5개 + 가이드 3개 + 에이전트 1개 추가. 어느 게 효과 있고 어느 게 노이즈인지 분리 불가.

## 6. U자 어텐션 활용

LLM의 어텐션은 **U자형** — 파일의 맨 앞과 맨 뒤에 가장 강하게 작동한다. 중간은 약함.

적용:
- CLAUDE.md에서 절대 어기면 안 되는 규칙은 **상단 + 하단** 양쪽에 두거나, Critical Rules 섹션을 상단 가까이 배치
- 긴 가이드 문서 작성 시 결론·핵심 규칙을 마지막에 한 번 더 요약
- 인덱스(목차)도 상단·하단 둘 다 두면 어텐션 가능성 상승

## 7. 사용자 개입의 가치

하네스가 자동화할수록 **사용자가 사고할 기회가 줄어든다**. 모든 자동화에는 트레이드오프가 있다.

- 자동화 OK: 반복적이고 결정적인 작업 (커밋 push, 빌드 트리거, 폴더 이동)
- 자동화 신중: 판단이 들어가는 작업 (어떤 todo를 흡수할지, 어떤 문서를 쓸지)
- 자동화하되 가시성 확보: 사용자 학습에 중요한 작업 (코드 리뷰 결과, 아키텍처 선택)
  → 자동으로 처리하되, **결과를 사용자에게 보여주고 판단 근거를 기록**(Synapse 등)해서 나중에 소화할 수 있게

"멈춰서 생각하게"가 이상적이지만, 1인 다프로젝트 상황에서는 비현실적이다. **일단 굴리고, 핵심 결정은 기록으로 남겨서 복기**하는 것이 현실적 전략.
