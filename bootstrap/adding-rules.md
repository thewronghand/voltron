# 새 규칙 추가 시 기준

CLAUDE.md, 가이드 문서에 새 규칙을 추가할 때 따른다.

## 추가 전 자가 점검

다음 질문에 모두 답할 수 있어야 한다.

1. **이 규칙이 막은(또는 막을) 실패는 무엇인가?**
   - 구체적 사례 1개 이상 (lessons 폴더에 있는지 확인)
   - 없으면 가상의 규칙 — 추가 보류

2. **이 규칙은 어디에 둬야 하나?**
   - 전역 (`~/.claude/CLAUDE.md`): 모든 프로젝트에 적용되는 사용자 정체성·언어·취향
   - voltron (`voltron/CLAUDE.md`): 모든 개인 프로젝트에 적용되는 코딩 원칙·공통 컨벤션
   - 프로젝트 (`{project}/CLAUDE.md`): 프로젝트 도메인·아키텍처·핵심 컨벤션 (한 화면 분량)
   - 가이드 (`{project}-workflow/guides/*.md`): 상세 절차·이유·예시
   - 메모리 (`~/.claude/.../memory/`): 사용자 피드백·반복 실수 차단
   - 쿡북 (`{project}-workflow/cookbook/`): 컴포넌트 사용법·반복 작업 체크리스트
   - 어디에 둘지 모호하면 → 기존 비슷한 항목이 어디 있는지 먼저 찾을 것

3. **이 규칙이 기존 규칙과 충돌·중복하나?**
   - 충돌: 어느 게 우선인지 명시 또는 한 쪽 폐기
   - 중복: 통합

4. **이 규칙이 강제될 수 있나?**
   - 훅으로 강제 가능 → 가이드 문서 + 훅 모두 추가
   - 강제 불가 → 가이드 문서로 명시. 사용자/Claude가 의식적으로 따라야 함

5. **이미 텍스트 규칙으로 명시했는데도 어기는 일이 반복되는가?**
   - 그렇다면 이 규칙은 **훅으로 승격**시켜야 한다 (Rule-to-Hook Promotion)
   - 텍스트 지시는 컨텍스트가 길어지거나 어텐션이 분산되면 무시될 수 있음. 훅은 결정론적으로 매번 작동
   - 승격 절차: 가이드 문서는 그대로 두되, 같은 규칙을 강제하는 훅을 추가. 가이드는 "왜", 훅은 "어떻게"

## 추가 시 형식

규칙 옆에 **이유**를 함께 적는다. "왜?"를 묻지 않게.

나쁨:
```
- import 절대경로 강제. 상대경로 금지
```

좋음:
```
- **import 절대경로 `@/` 강제**. 상대경로 금지
  → 파일 이동 시 import 깨짐, 레이어 의존 위반 자동 감지 어려움
```

(단, CLAUDE.md는 한 화면 유지를 위해 압축형. 이유는 가이드/lessons로 링크)

## 추가 후 체크

- 규칙이 새로 추가됐다면 관련 작업·리뷰에서 **3회 이상 실제로 작동하는지** 관찰
- 작동 안 하면 회수 (자동 무시되는 규칙은 다른 규칙의 신뢰도까지 깎음)
- 작동하면 lessons에 "이 규칙이 막은 실수" 기록

## 안티 패턴

- **남들이 한다고 따라 추가**: 다른 회사·블로그에서 좋다고 해도, 해당 프로젝트에서 막을 실패가 없으면 노이즈
- **"혹시 모르니까"**: 가상 위험 대비 규칙은 거의 다 노이즈
- **선언적 규칙만 추가하고 강제 안 함**: 훅으로 막을 수 있는 건 훅으로. 문서만으로 강제되는 건 결국 안 지켜짐
