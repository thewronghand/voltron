# 토큰 체계를 avocado 방식으로 재설계 (2026-11-13)

## 상황

`@thewrong/ui`는 monify `shared/ui`를 복사해 만들었고, 이후 avocado `packages/ui`가 같은 뿌리에서 훨씬 다듬어졌다. avocado의 컴포넌트·개선을 이쪽으로 옮기려 하니 토큰 체계가 달라 클래스 문자열을 전부 번역해야 했다.

실측(2026-11-13, HEAD 6f3d969 기준, 스토리 제외):

- 토큰은 색뿐이다(원시 77 + 시맨틱 22). radius·크기·그림자·z·모션 토큰은 0개.
- 컴포넌트 색 클래스: 시맨틱 288회 대 시맨틱 밖 587회(원시 직접 257, `neutral-N` 217, white/black 82, 기본 팔레트 18, hex 13).
- `dark:` variant 227회(38파일). `button/utils.ts`에 원시 104 + `dark:` 43, `table/components/ColumnSettingsTable.tsx`에 neutral 54 + `dark:` 29.
- 다크 트리거가 둘이다: 시맨틱 토큰은 `.dark` 클래스, `dark:` 유틸은 `prefers-color-scheme`(빌드된 `dist/ui.css`로 확인).
- 소스가 쓰는데 규칙이 없는 CSS 클래스 3개: `scrollbar-table`, `scrollbar-brand`, `search-box-date-input`.
- Storybook에 다크·테마 토글이 없다. 배포 CSS에 스토리 전용 유틸이 섞인다.

## 결정

1. **층**: 프리미티브(`--p-*`, 유틸 미생성) → 시맨틱(변수명 = 유틸명). 컴포넌트는 시맨틱만 쓴다. `dark:`와 프리미티브·기본 팔레트 직접 참조는 금지.
2. **이름은 avocado와 동일하게.** `fg-danger`/`info-fg` 같은 비대칭도 그대로 둔다 — 이름이 같아야 이후 이관·역반영이 복사에 가까워지고, 그게 이 재설계의 목적이다.
3. **기본 값도 avocado 값**(radius 3/5/7px, 글자 크기 px 재정의, control 28/36/44/48px). 의현님 결정(2026-11-13). 이관한 컴포넌트를 avocado 화면과 나란히 놓고 검증할 수 있고, 취향이 달라지면 프리미티브만 바꾸면 된다.
4. **가져오지 않는 것**: 제품 전용 토큰(가상로그인 `impersonation-*`, 로그인 히어로, 위자드 입력창 radius, `z-overlay-priority`·`z-overlay-confirm`, `border-splitter-track`, `bg-toast-image-tile`), Pretendard 폰트 파일, 실험용 테마(`dev`·`brand-x`·`radical`), 모노레포 경로가 박힌 체크 스크립트. 프리미티브의 이름·값 불일치(`blue` 슬롯에 violet 값)는 이름을 값에 맞춘다.
5. **다크·테마**: `.dark` 클래스 하나로 통일하고 시맨틱만 재정의한다. 임의 조상 요소에 붙여도 동작하는 현재 성질은 유지한다(avocado는 `html.dark` 강제 — 프리미티브 교체 테마 때문인데 여기서는 그런 테마를 두지 않는다). 테마는 `data-theme` + 시맨틱 재정의만.
6. **배포**: 자체포함 `styles.css` 유지 + 토큰 소스를 `./tokens.css`로 추가 export(소비자가 자기 Tailwind에서 `bg-bg-surface` 등을 쓸 수 있게 — avocado 명명상 `--color-bg-surface`의 유틸은 `bg-bg-surface`다). 스토리는 Tailwind 스캔에서 뺀다.
7. **강제**: `cn` 커스텀 그룹 + 테스트, 체크 스크립트(`dark:`·프리미티브·기본 팔레트 금지, 정의 없는 토큰 유틸 탐지). 대비비 계약 테스트는 테마를 실제로 늘릴 때.
8. **소비자 호환은 고려하지 않는다.** 소비자가 거의 없고 개발자가 의현님 한 명이다(2026-11-13).

## 순서

1. Storybook 다크·테마 토글 + 현재 화면 기준 스크린샷(라이트·다크)
2. 토큰 CSS·`cn`·체크 스크립트. 기존 이름은 임시 별칭으로 유지(이 단계에서는 화면이 바뀌지 않아야 한다)
3. 컴포넌트 계열별 치환(button → input·select → 오버레이 → toast → table), 계열마다 1의 스크린샷과 대조
4. 임시 별칭·`neutral-*` 중복·미사용 토큰 제거
5. 신규 컴포넌트 이관 시작

1~2는 브랜치 `feat/token-foundation`(worktree `thewrong-ui-code-2`). 3은 avocado 역반영 브랜치(`feat/backport-avocado-fixes`)가 통합된 뒤 시작한다 — modal·select·toast 파일이 겹친다.

## 미정

- `bg-white`와 `bg-card`는 다크에서 값이 갈리는데 avocado는 `bg-surface` 하나다. 합칠지 `bg-surface-raised`를 둘지는 3단계에서 사용처를 보고 정한다.
- 모션의 JS 쪽 값(스프링 stiffness·damping) 토큰화 여부 — avocado `motion/` 미조사.
