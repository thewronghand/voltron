# thebooth 기획

## 배경

- 한국 노래방 음원은 대부분 TJ미디어 것을 쓴다. TJ가 안 낸 곡은 노래방에서 부를 수도, 연습하기도 어렵다.
- TJ·금영 반주기에는 USB에 담은 MP3로 노래하는 **'나의 MP3'** 기능이 있다 (TJ 질러 S20/L20/C20~, 금영 필통 600~. 구형 기기·TJ B80 불가).
- TJ M1 제품 소개 기준 USB **mp4 동영상 재생**도 지원한다. 기종별 실제 지원 여부는 미확인.
- 후기 기준 USB 재생 중에는 **키 조절·간주 점프가 안 된다** → 키는 파일에 미리 반영해 가야 한다.
- USB 곡에 가사를 붙이는 반주기 기능은 찾지 못했다 → 가사는 영상에 자막으로 입히는 방식이 유일한 경로로 보인다.

## 핵심 아이디어

반주기가 못 하는 것(키 변경·멜로디·가사)을 **사전 렌더링**으로 메운다.
음원 → 보컬 제거 → 키 변경 → 멜로디 가이드 합성 → 가사 자막 → MP3/MP4 내보내기 → USB → 반주기.

## 기능과 후보 기술

| 기능 | 후보 | 난이도 |
|------|------|--------|
| 보컬 제거 | Demucs(htdemucs, 기본), Mel-Band RoFormer(일반·가라오케, 옵트인) | 낮음 |
| 키 변경 | rubberband (템포 유지 피치 시프트) | 낮음 |
| 멜로디 가이드 | 리드 보컬에서 피치 추출(FCPE 기본, RMVPE 선택) → 반음 음표화 → 배음 사인 합성 → MR에 믹스. 키 변경은 음표를 옮겨 재합성 | 중간 |
| 가사 | 사용자가 가사 텍스트 입력 → 분리 보컬에 WhisperX 강제 정렬 → 단어 단위 타이밍 → 노래방식 자막 | 중간~높음 (한국어 정렬 정확도 실측 필요, 수동 보정 편집기 필요) |
| 내보내기 | MP3(오디오만), MP4(자막 영상) — ffmpeg | 낮음 |

가사 자막은 ASS 자막의 `\k` 노래방 태그로 만들고 ffmpeg(libass)로 영상에 입힌다 — 글자가 차오르는 효과를 직접 렌더링할 필요가 없다.

## 아키텍처

- **셸**: Electron (TS). 렌더러는 React.
- **처리 코어**: Python 사이드카. Electron main이 자식 프로세스로 띄우고 로컬 HTTP(FastAPI)로 통신, 오래 걸리는 작업의 진행률은 SSE(또는 WebSocket)로 스트리밍.
- **Python 환경**: 앱에 `uv`만 넣고 첫 실행 시 Python·패키지를 구성 (PyInstaller 단일 바이너리 X).
- **모델**: 앱 패키지에 포함하지 않는다. 앱 안 다운로드 UI로 받는다.
  - 저장 위치 하나로 고정 — 개발·패키징 앱·CLI가 같은 폴더(예: `~/Library/Application Support/thebooth/models`)를 공유.
  - 라이브러리 자동 다운로드(torch hub·HF 캐시)는 끄고, **앱이 명시적으로 받아 경로를 코어에 넘긴다** — 앱이 설치 상태를 정확히 알아야 한다.
  - 모델 목록은 manifest JSON 하나 (id·용도·URL·크기·sha256·라이선스). 다운로드는 이어받기 + 체크섬 검증.
  - CLI로도 받을 수 있게 (`thebooth models pull <id>`). 앱 다운로드 UI는 같은 로직을 호출.
  - Python 환경 구성과 모델 다운로드는 **"준비" 화면 하나**에서.
  - 처음엔 용도당 모델 하나. 모델 비교·전환 UI는 두 번째 모델이 실제로 필요해질 때.
  - 라이선스는 모델마다 확인 후 manifest에 기재 (UVR 계열·한국어 정렬 모델은 제각각).
- **지원 OS**: macOS(arm64)·Windows(x64) 정식 지원. 개발 기기는 Mac(M4), Windows는 개인 데스크탑에서 검증.
  - 장치 선택 `cuda → mps → cpu`. Windows NVIDIA는 CUDA용 torch가 따로라 첫 실행 환경 구성이 GPU를 감지해 고른다.
  - 경로는 platformdirs, OS 전용 명령 금지.
- **배포**: 본인 사용 기준. 코드 서명·공증은 남에게 배포할 때 붙인다.

## 단계

1. Python 코어 CLI: 보컬 제거 + 키 변경 + MP3 내보내기 + `models pull` → **매장 반주기에서 실제로 틀어보기**
2. Electron 셸 + 사이드카 연결: 준비 화면(환경·모델) → 파일 넣기 → 진행률 → 내보내기
3. 멜로디 가이드
4. 가사 정렬 + 타이밍 편집기(React) + MP4 렌더링 → 반주기 MP4 재생 확인

## 참고·경쟁

- **Moises**: 음원 분리·키 변경·가사 싱크를 이미 지원하는 상용 앱. 차별점은 한국어 가사, 반주기 USB용 MP4 내보내기, 멜로디 가이드의 조합.

## 미정

- 사이드카 통신 세부 (FastAPI+SSE vs WebSocket) — 2단계에서
- 내가 쓸 매장 반주기 기종의 MP4 지원 여부 → 1단계에서 실측

## 결정 기록

- **2026-11-12 로컬 앱으로 간다 (웹 서비스 X)** — 웹 서비스는 남의 음원이 운영자 서버에 복제·저장되고 결과물을 서버가 만들어 내려주는 구조라, 운영자가 복제·전송 주체로 엮이기 쉽다(공유·캐싱 시 공중송신, 유료화 시 영리성까지). 로컬 앱은 음원 구매·처리 주체가 사용자 본인이라 사적 이용 복제 여지가 크고, 개발자는 편집 도구를 배포하는 위치다. 단 결과물을 매장에서 트는 것·온라인 업로드는 사용자 행동의 문제로 남는다. 공개 배포·수익화를 검토할 때 전문가 확인.
- **2026-11-12 이름 `thebooth`** — 보컬 녹음 부스 + 노래방 부스. 버스 접두사 `booth`.
- **2026-11-12 처리 코어는 Python** — 보컬 분리(Demucs)·피치 추출(CREPE·basic-pitch)·가사 정렬(WhisperX)이 전부 PyTorch 생태계. 전부 JS(ONNX·transformers.js·whisper.cpp) 경로는 한국어 강제 정렬 대안이 마땅치 않고 포팅 품질 검증 부담이 커서 보류 — 1단계 코어가 돈 뒤 재검토 가능.
- **2026-11-12 데스크탑 앱, 셸은 Electron (Tauri X)** — Tauri의 용량 이점은 모델(수백 MB~수 GB) 앞에서 무의미하고, Rust가 붙으면 언어가 셋(TS·Python·Rust)이 된다. Synapse에서 Electron 경험이 있다.
- **2026-11-12 Python 환경은 uv로 첫 실행 시 구성** — PyInstaller로 PyTorch를 묶는 빌드는 무겁고 깨지기 쉽다. 본인 사용이라 첫 실행 다운로드 비용은 감수.
- **2026-11-12 모델은 앱 내 다운로드 UI로, 패키지에 미포함** — 패키지가 가볍고, 모델 추가 시 앱 재배포 불필요. 개발 불편은 저장 위치 단일화 + CLI `models pull`로 해소. 다중 모델은 manifest 구조로 열어두되 처음엔 용도당 하나(YAGNI).
- **2026-11-12 모델 출처는 HuggingFace (리비전 고정)** — demucs 4.1.0의 기본 경로. HF API가 파일별 sha256·크기를 줘 manifest와 맞는다. 레거시 Meta 서버(dl.fbaipublicfiles.com)는 같은 날 인증서 만료(2026-11-11 23:59 GMT)를 실측 — 대체 URL은 필요해질 때.
- **2026-11-12 키 변경·오디오 IO는 pedalboard** — Rubber Band 내장이라 rubberband·ffmpeg 별도 설치 불필요(ffmpeg는 MP4 단계부터).
- **2026-11-12 MR 기본 방식은 stems(드럼+베이스+other 합)** — 폭탄마 청취 비교에서 subtract(원곡−보컬)보다 깨끗했다. 남은 문제: 큰 보컬 뒤 반주가 얇은 순간 MR만 10~20dB 꺼지는 짧은 구간(0.2~0.6초). htdemucs_ft로 바꿔도 동일(49프레임 vs 49프레임, 분리 3배 이상 느림)이라 모델 문제보다 원곡 구조로 추정 → ft는 manifest에 넣지 않음. 레벨러(컴프레서/구간 보정)는 청취 후 결정, 정공법은 3단계 멜로디 가이드.
- **2026-11-12 MP3 저장은 피크 정규화(-1dBFS), 클립·pedalboard Limiter 금지** — 음압 높은 마스터는 디코딩 시 +4dBFS까지 나와 `np.clip`이 곡당 수만 샘플을 잘랐다. pedalboard `Limiter`는 메이크업 게인(작은 소리 +4.8dB)으로 다이내믹을 눌러서 부적합(실측).
- **2026-11-12 Windows 정식 지원** — 사용자 개인 데스크탑이 Windows. 처음부터 크로스플랫폼으로 짜는 비용은 작고(경로·장치 선택·uv 대상 플랫폼), 나중에 걷어내는 비용이 크다.
- **2026-11-12 Mel-Band RoFormer 두 모델을 옵트인으로 추가 (`--model`), 기본은 htdemucs 유지** — 폭탄마 실측: 간주 구간 보컬 누설 htdemucs −43dB → RoFormer −90dB대, 보컬·간주 MR 음량 차는 가라오케 모델만 −2.1 → −1.4dB. 대신 느리다(3분 36초 곡, M4 MPS 기준 htdemucs 17초, 일반 약 3분, 가라오케 약 12분).
  - **가라오케 = becruily** (`melband-roformer-karaoke`) — 리드 보컬만 빼고 코러스·백보컬을 MR에 남긴다. Gabox 가라오케와 수치는 같았지만 청취에서 Gabox는 코러스 일부가 제대로 분리되지 않아 becruily로. "가라오케 모드"는 별도 플래그가 아니라 이 모델을 고르는 것 — 앱 UI에서는 토글로 보여준다.
  - **일반 = Kim Mel-Band RoFormer** (`melband-roformer`, MIT). 겹침은 저자 공식 설정값 2 (audio-separator 설정의 1은 구간 경계 불연속 위험 — 리뷰에서 발견).
  - **라이선스**: becruily는 HF 레포에 표기 없음. 커뮤니티에서 널리 쓰이는 걸 "굳이 안 적은 것"으로 보고 개인 사용 기준으로 채택, manifest에 그대로 적는다. 공개 배포 시 저자 확인.
  - **audio-separator는 쓰지 않는다** — 입력을 피크 0.9로 줄여 넣어 출력 음량이 0.567배로 나오고 MP3 디코딩 차로 25ms(1105샘플) 앞당겨지며, 자체 다운로드를 해서 Critical Rule 4와 부딪힌다. 모델 코드는 `bs-roformer==0.3.10`(MIT, 체크포인트 키가 정확히 맞는 마지막 버전 — 0.4 이후는 구조 변경으로 로드 불가), 구간 나누기·겹쳐 더하기는 직접 구현. 입력 피크 0.9 축소는 청취한 결과와 같은 조건이라 따라 한다(출력에서 복원). audio-separator 결과와는 −31dB 차이(창 함수·모델 코드 변형 차).
  - **출처는 원 저자 HF 레포 리비전 고정** — 두 체크포인트 sha256이 audio-separator 미러와 같음을 확인. 원본 yaml은 `!!python/tuple`이라 안전 로드가 안 돼 필요한 값만 manifest `config`에 옮긴다(캐시 키에도 포함).
  - **속도 조정은 보류** — fp16은 MPS에서 이득 없음(247→258초). 가라오케 겹침 8→4는 2.1배 빠르고 MR 차이 −36dB. 청취로 판정 전까지 저자 기본값 8.
- **2026-11-12 멜로디 가이드: 리드 보컬 → f0 → 반음 음표 → 합성 → MR에 믹스** — 폭탄마 스파이크(becruily 가라오케 리드 보컬). 추출기 비교: RMVPE 11초·FCPE 0.9초·CREPE 216초(M4), 서로 cents 차 중앙값 3~8, 반음 이상 갈림 1~3%. 청취에서 FCPE가 더 정확하게 들려 **기본 FCPE, `--pitch rmvpe` 선택 가능**(다른 곡으로 더 비교 후 기본값 재검토). CREPE는 느려서, basic-pitch는 Python 3.12 휠이 없어 제외.
  - 피치 곡선이 아니라 **반음 음표**로 — 비브라토·슬라이드를 따라가면 가이드로 듣기 어렵다. 중앙값 필터(90ms) 후 반올림, 80ms 미만 음 버림, 같은 음 사이 50ms 이하 틈 잇기(스파이크값, 청취로 조정).
  - **키 변경은 음표를 반음만큼 옮겨 재합성** — 가이드는 피치 시프트 음질 저하가 없다. MR만 Rubber Band.
  - **가이드 음량 조절 필요** (노래방 멜로디 볼륨처럼) — 원래 보컬 RMS 대비 dB, 기본 −6dB. 반주기 USB 재생 중엔 못 바꾸므로 파일 생성 시 정한다.
  - **Critical Rule 4 예외: FCPE 가중치는 `torchfcpe` pip 동봉본(43MB, MIT)** — 공식 단독 배포처가 없다(HF `ChiTu/FCPE`는 다른 모델·CC BY-NC-SA). 앱 패키지에는 안 들어가고(uv가 첫 실행 때 설치), 패키지 버전 고정 + 로드 전 sha256 검사 + 경로 명시 로드로 "앱이 설치 상태를 정확히 안다"는 규칙 취지를 지킨다. RMVPE(RVC, MIT)는 manifest(HF `lj1995/VoiceConversionWebUI` 리비전 고정).
- **2026-11-12 (다음 작업) 키 조절 = 남/여 전환 + 숫자 단계** — 최종 반음 = 남/여 전환량 + `-k`, 합계 ±12 제한. 방향(남→여/여→남)은 사용자가 고른다(원곡 성별을 알 수 없음). TJ 전환량은 자료가 엇갈린다(나무위키 현행 ±5, 다른 판 ±7, 곡별 기준 키 차 존재) → 상수 하나로 두고 일단 5, 매장에서 남/여 버튼 표시값으로 확정.
