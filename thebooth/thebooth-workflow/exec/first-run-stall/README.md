## 배경 (메인 실측, 2026-11-13~15)
- 패키징 `.app` 빈 HOME 첫 실행에서 Python(약 66MB) 뒤 `uv sync`가 약 15분 진행 없음(uv 캐시 76KB 고정, CPU 0%, PyPI 파일 서버와 TCP 연결 하나 ESTABLISHED, 같은 시각 `curl pypi.org` 0.85초). 첫 시도는 10분 넘게 멈춰 강제 종료, 재시도는 15분 정지 뒤 1분에 약 800MB를 받고 끝남(곡 목록까지 1058초). 그동안 준비 화면은 '설치 중'과 경과 시간뿐.

## 메인이 실측한 것
- **완전 정지(데이터 0)**: 응답 없는 로컬 프록시를 `HTTPS_PROXY`로 넣은 패키징 앱 → 90초 만에 "패키지 설치에 실패했습니다(종료 코드 2). 네트워크 연결을 확인하고 다시 시도해 주세요." + '다시 시도'(uv 읽기 30초 × 재시도). 이번 수정 전에도 같은 동작 — 정지 안내가 필요한 건 데이터가 조금씩 오다 끊기는(시간 제한에 안 걸리는) 경우뿐이고, 이 경우는 재현 수단이 없어 단위 테스트로만 확인.
- **오탐 없음**: r2 빌드로 빈 HOME 정상 첫 실행 → 115초 만에 곡 보관함, 정지 안내 한 번도 안 뜸.
- 스크립트 `e2e/stall.mjs`(`STALL_PROXY=0`이면 정상 실행 오탐 확인), 화면 `screens/`.

## 남은 것
- 같은 볼륨에 다른 프로세스가 쓰면 정지를 놓칠 수 있음, 3분에 1MiB 미만의 아주 느린 진행은 정지로 보임(안내는 참고용). Windows 실기 미검증.
