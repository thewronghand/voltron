# 작업: thebooth 앱 UX 개편 1단계 r1 — Python 코어 분리 + 곡 보관함 + 사이드카 곡 API

레포 `thebooth-code`, 브랜치 `feat/song-library`(main 기준, 이미 만들어 둠). 이번 라운드는 **Python 쪽만** 한다. `app/`은 건드리지 않는다(다음 라운드).

## 배경 (사용자 승인 사항)
앱이 "한 번 실행하고 끝"에서 **곡 단위 보관함**으로 바뀐다. 곡 하나에 원곡 복사본·분리 결과·음표·가사·정렬 결과·설정이 묶인다. 처리는 두 가지로 나뉜다.
- **만들기**: 오래 걸리는 처리(보컬 분리, 음표 추출, 가사 정렬). 곡을 추가하고 한 번 한다.
- **내보내기**: 가벼운 처리(키 변경·남녀 전환·가이드 합성·MP3, ASS·MP4 렌더). **여러 키를 한 번에** 내보낸다. MP3와 MP4를 둘 다 고를 수 있다.

## 1. 코어 단계 함수 분리 (`pipeline.py`)
지금 `pipeline.make()` 한 덩어리를 재사용 가능한 단계 함수로 나눈다. 예: 분리(`Stems` 반환), 음표 추출(`list[Note]`), 가사 정렬(`Alignment`), 내보내기 렌더(믹스·스템·음표·정렬·반음·가이드 옵션·MR 방식 → MP3/보컬 MP3/ASS/MP4). 이름과 경계는 판단에 맡기되 CLI `make`와 곡 만들기·내보내기가 **같은 함수**를 쓰게 한다.
- **CLI `make`의 동작·출력·종료 코드·출력 문구와 결과 파일 바이트는 바꾸지 않는다.** 호출 순서(캐시 조회·저장, 진행 단계 보고 순서, 취소 지점, partial 경로 처리)를 유지한다. 메인이 폭탄마로 전후 sha256을 비교한다(MR·보컬·MP4·ASS).
- 기존 `/jobs/make` 엔드포인트도 이번 라운드에서는 그대로 동작해야 한다(앱이 아직 쓴다).

## 2. 곡 보관함 (`library.py` 신규)
저장 위치: `paths.data_dir() / "songs"` (지울 수 없는 사용자 자료라 캐시 폴더 아님). `paths.py`에 `songs_dir()` 추가. 테스트·서버는 루트를 주입받는다.

```
songs/<곡id>/
  song.json             형식 버전·제목·원곡 정보·만들기 설정·내보내기 기본값·결과 기록
  source.<원래 확장자>   원곡 복사본 (확장자는 소문자)
  stems/vocals.npy, stems/accompaniment.npy   분리 결과 (float32, 캐시와 같은 형식)
  notes.json            멜로디 음표
  lyrics/lyrics.txt, lyrics/lyrics-extra.txt  가사·보조 파일 복사본
  alignment.json        정렬 결과
```
- 곡 id는 ASCII만: `YYYYMMDD-` + 무작위 hex 6자리(충돌 시 재생성). id 형식 정규식으로 검증하고, id로 경로를 만들 때 경로 탈출이 없게 한다.
- `song.json` 쓰기는 임시 파일 + `os.replace`로 원자적으로. 읽을 때 형식 버전·필드를 검사하고 깨진 곡은 목록에서 "읽을 수 없는 곡"으로 표시(예외로 목록 전체가 죽지 않게).
- **만들기 설정**(song.json): `model_id`(기본 htdemucs), `pitch_extractor`(fcpe|rmvpe, 기본 fcpe), `lyrics_lang`(기본 ja).
- **결과 기록과 신선도**: 각 결과에 무엇으로 만들었는지 키를 남긴다 — 분리: 원곡 sha + 모델 키(`_cache_key`), 음표: + 추출기 키·음표 버전, 정렬: + 가사 sha·언어·정렬 모델 sha·정렬 버전(지금 `align_key`와 같은 구성). 현재 설정·가사로 계산한 키와 기록이 다르면 "낡음". 곡 조회 응답에 단계별 상태(`none`|`ready`|`stale`)를 준다.
- **만들기 작업**: 낡았거나 없는 단계만 다시 한다(분리 → 음표 → 가사가 있으면 정렬). 음표 추출은 가이드 사용 여부와 무관하게 **항상** 한다(내보낼 때 가이드를 켤지 고른다). 분리 전에 기존 캐시(`cache.load`)를 찾아 있으면 곡 폴더로 복사하고 분리를 건너뛴다(캐시 적중 표시). 새로 분리한 결과는 곡 폴더에만 저장한다(캐시에는 쓰지 않는다). 음표·정렬도 같은 방식으로 캐시를 먼저 본다. 진행 단계 이름은 기존과 같게(`load`, `separate`, `pitch`, `align`).
- **가사**: 가사 파일·보조 파일(선택)·언어를 받아 `lyrics.load`로 검증한 뒤 곡 폴더로 복사한다. 가사를 바꾸면 정렬이 낡음이 된다. 가사 지우기도 가능.
- **원곡 추가**: 파일을 곡 폴더로 복사(임시 이름으로 복사 후 이름 바꾸기), sha256 계산, 제목 기본값은 파일 이름(확장자 제외). 복사 실패 시 반쪽 곡 폴더가 남지 않게.
- **삭제**: 실행 중·대기 중 작업이 있는 곡은 거부. 삭제는 곡 폴더를 `songs/.deleted/<곡id>`로 옮겨 목록에서 빼는 것까지(OS 휴지통 보내기는 다음 라운드에 Electron main이 한다). `.`으로 시작하는 폴더는 목록에서 무시.

## 3. 내보내기
요청: 형식(`mp3`, `mp4` 중 하나 이상), 변형 목록(각각 `key` -12~12 + `gender` null|m2f|f2m, 합계 ±12, 1~12개, 같은 (gender,key) 중복은 거부), 가이드(켬/끔, 음량 dB 범위는 기존과 같음), 고급: MR 방식(stems|subtract), 보컬도 저장(bool), 저장 폴더(절대 경로, 존재하는 폴더).
- 사전 조건: 분리·음표(가이드 켬일 때)가 `ready`, MP4는 가사와 정렬 `ready` + ffmpeg 설치. 아니면 400과 한국어 이유("먼저 만들기를 하세요" 등).
- **파일 이름은 서버가 만든다**: `<제목> - <키 표시>.mp3` / `.mp4`(+ 같은 이름 `.ass`) / 보컬 `<제목> - <키 표시> 보컬.mp3`. 키 표시는 원키·`키 +2`·`여→남 -5`·`남→여 +5 키 -1`처럼 사람이 읽는 형태. 제목은 OS 금지 문자(`<>:"/\|?*`, 제어문자)를 바꾸고 끝 점·공백을 제거하고 Windows 예약 이름을 피하며 길이를 제한한다.
- **이미 같은 이름이 있으면 덮어쓰지 않고 번호를 붙인다**(`... (2).mp3`). 번호는 한 변형의 파일 묶음(mp3·mp4·ass·보컬) 전체가 비어 있는 첫 번호로 고르고, 작업 실행 시점에 정한다(대기 중에 파일이 생길 수 있음). ASS 백업 로직이 끼지 않게.
- 진행: 한 작업으로 처리. `stage("export", total=항목 수)`, 항목마다 `advance`, 항목마다 `message`("2/3 · 여→남 -5 · MP4 렌더 중" 같은 사람용 안내 — 앱은 파싱하지 않고 그대로 보여준다). 항목 안의 렌더 진행(`video.render`의 stage/advance)이 바깥 진행을 되감지 않게 감싼다. 취소 시 완성된 파일 경로를 partial로 남기고 만들다 만 파일은 지운다(기존 make 정책과 같게).
- 결과: 변형별 생성 경로 목록. 마지막 내보내기 설정(형식·변형·가이드·폴더·고급)을 song.json에 기본값으로 저장한다.

## 4. 사이드카 API (`server.py`)
- `GET /songs` — 목록(최신 추가 순): id, 제목, 추가 시각, 단계별 상태, 가사 유무, 진행 중 작업(`{job_id, kind, status}` 또는 null). 진행 중 작업은 서버 메모리에서 곡↔작업을 추적해 채운다.
- `POST /songs` `{source_path, title?}` → 곡 생성(201, 곡 상세).
- `GET /songs/{id}` — 상세(설정·상태·가사 파일 유무·언어·내보내기 기본값·진행 중 작업).
- `PATCH /songs/{id}` — 제목, 만들기 설정. 진행 중인 만들기 작업이 있으면 만들기 설정 변경은 409.
- `PUT /songs/{id}/lyrics` `{lyrics_path, lyrics_extra_path?, lyrics_lang}` / `DELETE /songs/{id}/lyrics`.
- `POST /songs/{id}/make` (202, job_id), `POST /songs/{id}/export` (202, job_id). 같은 곡에 이미 대기·실행 중인 작업이 있으면 409.
- `DELETE /songs/{id}` — 위 2의 삭제. 응답에 옮긴 폴더 경로.
- 기존 인증·CORS·오류 형식(`{"error": "..."}` 한 줄, 한국어)·검증(절대 경로, extra forbid)을 그대로 따른다. CORS 허용 메서드에 `PATCH, PUT, DELETE` 추가.
- 요청 시 무거운 사전 검사, 작업 실행 시 존재·크기 재확인 패턴은 기존 `/jobs/make`를 따른다.
