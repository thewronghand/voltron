# r2 — r1 리뷰 반영 + 앱 화면 개편

## A. r1 리뷰 반영 (Python, 먼저)
1. **[HIGH] 빈·잘린 npy 하나로 목록 전체가 500**: 빈 `.npy`는 numpy가 `EOFError`를 던져 `status()`·`cache.load`(load_stems)가 못 잡는다(메인 재현). 스템 읽기 실패는 종류와 무관하게 해당 결과를 낡음/없음으로 보고(목록·상세·make 사전 검사), make는 재분리로 복구되게. `list()`는 곡 하나에서 나는 모든 예외(외부에서 폴더가 사라진 `SongNotFound` 포함)를 그 곡만 "읽을 수 없는 곡"으로 바꾼다. 회귀 테스트: 빈 `vocals.npy`·잘린 npy로 `list()`·`GET /songs`·`POST make`가 각각 정상 목록·`stale`·재분리.
2. **OSError 메시지가 errno 숫자로 나감**: `server.py`의 `except (..., OSError) as exc: _error(str(exc.args[0]))` — KeyError만 `args[0]`, 나머지는 `str(exc)`(기존 `/jobs/make` 방식). 테스트 하나.
3. **목록 조회마다 모든 원곡 전체 해시 + 전역 락 장시간 점유**: 상태 계산은 `song.source.sha256`에 원곡 크기·mtime 비교로 대신하고(어긋나면 그때만 해시하거나 stale), 전체 해시는 make·export 실행 시점에만. 원곡 추가의 복사·해시는 락 밖에서.
4. **반쪽 곡 폴더**: 추가는 `songs/.incoming-<id>/`에서 복사·해시·song.json까지 끝낸 뒤 `os.rename`으로 `songs/<id>`. 예외 정리는 `rmtree(..., ignore_errors=True)`. 시작 시 오래된 `.incoming-*`는 무시(목록에서 이미 제외).
5. **내보내기 기본값 검증 때문에 곡 전체가 무효가 될 수 있음**: `export_defaults`는 읽을 때 실패하면 `None`으로 떨어뜨린다(곡은 계속 읽힌다). 테스트.
6. **fsync**: song.json·스템 tmp는 replace 전에 flush+fsync.
7. LOW 중 반영: 제목의 앞쪽 점 제거, 파일 이름은 NFC로 정규화(macOS NFD 제목이 반주기에서 자모로 풀릴 수 있음), 목록 항목에 항상 `unreadable` 키(정상 곡은 false), 저장 폴더의 `.thebooth-export-*` 임시 폴더는 다음 내보내기 시작 때 같은 폴더의 1시간 넘은 것만 정리(안 되면 무시). 나머지 LOW는 손대지 않는다.

## 화면 구조 (사용자 승인)
지금의 "준비 / 만들기" 탭 두 개를 다음으로 바꾼다.
1. **곡 목록(기본 화면)** — `GET /songs`. 행마다 제목, 상태(만들기 전 / 만드는 중(진행률) / 대기 중 / 만들기 완료 / 다시 만들기 필요(stale) / 실패한 경우 마지막 오류는 상세에서), 가사 유무, 추가한 날짜. 읽을 수 없는 곡은 그렇게 표시하고 삭제만 가능. 빈 목록이면 '추가'를 안내하는 빈 상태. 행을 누르면 곡 상세.
   - 헤더 오른쪽: **'추가'**(주 버튼)와 **'준비'**(보조 버튼, 실행 환경·모델 받기 화면). 지금의 준비 화면 기능(실행 환경 구성·처리 엔진 상태·모델 받기/취소/다시 받기·재구성)은 그대로 유지한 채 이 자리로 옮긴다.
   - 실행 환경이 준비되지 않았으면(지금 `appView` 규칙) 목록 대신 준비 화면을 먼저 보여준다. 기본 분리 모델(htdemucs)이 설치되지 않았으면 목록 위에 준비 화면으로 가는 안내.
2. **추가** — 파일 선택 대화상자(오디오 확장자 필터: mp3, m4a, wav, flac, ogg, webm, mp4) 또는 목록 화면에 파일을 끌어다 놓기 → `POST /songs` → 곧바로 그 곡의 상세로 이동. 복사 중에는 버튼 비활성·"추가하는 중…".
3. **곡 상세** — 뒤로(목록) / 제목(그 자리에서 편집, `PATCH`) / 원곡 정보(원래 파일 이름).
   - **만들기** 영역: 분리 모델 선택과 가라오케 모드(지금 MakeOptions의 모델 선택·가라오케 토글 동작을 그대로 옮김), 음높이 추출기(FCPE/RMVPE, 고급으로 접기), 가사 파일·보조 파일·언어(`PUT /songs/{id}/lyrics`, 지우기는 `DELETE`), 단계별 상태(분리·음표·가사 정렬: 없음/완료/다시 필요), '만들기' 버튼(낡았거나 없는 단계만 한다는 걸 버튼 문구로: 처음엔 "만들기", 일부만 필요하면 "다시 만들기"류 — 판단에 맡김), 진행(기존 `JobProgress`·SSE 스트림 재사용), 취소, 실패 오류. 설정을 바꿔 결과가 낡으면 그 사실을 보여준다. 모델이 미설치면 준비 화면 안내.
   - 곡 상세를 떠났다 돌아와도 진행 중 작업을 다시 붙잡는다(목록·상세 응답의 `job`).
   - **내보내기** 영역(만들기가 끝나야 활성):
     - 형식: MP3 / MP4 체크박스(둘 다 가능). MP4는 가사·정렬이 준비돼야 활성(이유 표시), ffmpeg 미설치면 준비 화면 안내.
     - 키 목록: 키 단계(−/+)와 남/여 전환(없음/남→여 +5/여→남 −5)으로 하나를 만들어 '키 추가' → 칩 목록(최종 반음 표시, 칩마다 삭제). 1~12개, 같은 조합 중복 불가. 기본은 원키 하나.
     - 멜로디 가이드 켬/끔 + 음량(지금 슬라이더·숫자 입력 동작을 옮김).
     - 고급(접기): MR 방식(스템/원곡에서 보컬 빼기), 분리한 보컬도 저장.
     - 저장 폴더: 폴더 선택 대화상자(새 IPC). 기본값은 곡의 지난 내보내기 폴더, 없으면 비어 있어 선택을 요구.
     - 파일 이름은 서버가 정한다는 것과 같은 이름이 있으면 번호를 붙인다는 것을 한 줄로 안내.
     - '내보내기' → `POST /songs/{id}/export` → 진행(항목 n/전체, 서버 message 그대로 표시) → 결과: 만들어진 파일 목록과 각각 "Finder에서 보기"(Windows는 탐색기 — 기존 `showInFolder`). 취소 시 완성된 파일은 남는다는 안내와 partial 목록.
     - 지난 내보내기 설정(`export_defaults`)으로 폼을 채운다.
   - **곡 삭제**: 확인 대화(되살리려면 휴지통에서 꺼낸다는 안내) → `DELETE /songs/{id}` → 응답 경로를 새 IPC로 OS 휴지통에 보냄 → 목록으로. 휴지통 보내기 실패 시 안내(곡은 이미 목록에서 빠졌음을 정확히).
4. 기존 "만들기" 화면(`features/make/` 중 곡 구조에서 안 쓰게 되는 것)과 `makeJob`·`MakeRequest` 클라이언트, 사이드카 `/jobs/make` 엔드포인트와 그 전용 서버 테스트는 제거한다(CLI `make`와 `pipeline.make`는 유지). 재사용하는 조각(진행 표시, 키·가이드 입력, 경로 선택 등)은 새 기능 폴더로 옮기고 이름을 맞춘다.

## main·preload
- IPC 추가: 폴더 선택(`dialog.showOpenDialog` `openDirectory`, `createDirectory`), 곡 휴지통 보내기. 휴지통 IPC는 **임의 경로를 받지 않는다** — 곡 id만 받아 id 형식(`^\d{8}-[0-9a-f]{6}$`)을 검사하고, main이 `dataRoot()`로 계산한 `<데이터>/songs/.deleted/<id>`만 `shell.trashItem`한다. 경로가 없으면 오류.
