# r4 — 곡 목록을 Table로, 곡 추가·만들기 설정을 Modal로 (사용자 요청)

같은 레포·브랜치, 누적 미커밋 변경 위에서. 사용자 요청 원문: "Table로 바꿔주고, 곡 만드는 UI는 Modal로 분기."

먼저 `app/node_modules/@thewrong/ui/llms.txt`와 패키지 타입 정의(`dist`의 Table·Modal)를 읽고 그 사용 규칙을 따른다(예: Table을 `p-4` 박스에 직접 넣지 말 것).

1. **곡 목록 → `@thewrong/ui`의 `Table`**(페이지 없음). 열: 제목, 상태(지금 `songStatus` 표시 그대로 — 진행률 포함), 가사(있음/없음), 추가한 날짜. 기본 정렬은 추가한 날짜 최신순, 제목·날짜 열 정렬 가능. 행 클릭으로 곡 상세. 빈 목록은 `emptyMessage`(추가 안내). 읽을 수 없는 곡도 행으로 보이고 상세 대신 삭제만 가능하게(행 안 삭제 버튼 등, 판단에 맡김). `getRowId`는 곡 id.
2. **곡 추가 → `Modal`**. 목록의 '추가'(그리고 목록 화면에 파일 끌어다 놓기)는 Modal을 연다(끌어다 놓은 파일은 원곡으로 미리 채움). Modal 안: 원곡 파일(선택/변경), 제목(기본은 파일 이름, 편집 가능), 분리 모델·가라오케 모드, 음높이 추출기(고급 접기), 가사 파일·보조 파일·언어(선택). 확인 버튼 '추가하고 만들기' → `POST /songs` → (가사가 있으면) `PUT lyrics` → (설정이 기본과 다르면) `PATCH` → `POST make` → 그 곡 상세로 이동. 중간 단계가 실패하면 곡은 이미 생겼다는 사실과 무엇이 실패했는지 보여주고 상세로 보낸다(곡이 사라지거나 중복 추가되지 않게). 처리 중엔 버튼 비활성·"추가하는 중…". 모델 미설치면 Modal 안에서 준비 화면 안내.
3. **곡 상세의 만들기 영역**은 단계별 상태·진행·취소·마지막 오류와 '만들기'/'다시 만들기' 버튼만 남긴다. 설정(분리 모델·가라오케·추출기·가사·언어)은 '만들기 설정' 버튼으로 **같은 Modal 컴포넌트**를 편집 모드로 열어 바꾼다(원곡 파일 칸은 편집 모드에서 읽기 전용, 확인 버튼은 '저장' — 저장 후 낡은 단계가 생기면 상세에 그대로 보인다). 진행 중 작업이 있으면 설정 버튼 비활성(서버 409와 일치).
4. 테스트: 추가 흐름의 요청 순서와 중간 실패 처리, 편집 모드 저장 요청, 목록 열 정렬·행 클릭 규칙(로직 함수 단위). 기존 테스트 유지.
