# r5 — 리뷰 지적 + 실제 앱 화면 확인에서 나온 수정

같은 레포·브랜치, 누적 미커밋 변경 위에서. 메인이 r4 뒤에 직접 고친 것(네이티브 select 세 곳 → `@thewrong/ui` Select, id·라벨 연결, 남녀 전환 Select 폭 `w-40`)은 유지한다. `@thewrong/ui` Select는 `aria-label`을 트리거에 넘기지 않으므로 이름은 `id`+`label`(또는 숨은 `<label htmlFor>`)로만 붙는다. 트리거 역할은 combobox다.

## 리뷰 지적
1. **곡 추가 중 가사 저장 실패 시 만들기 설정(PATCH)까지 건너뜀** (`songSetup.ts`): 가사가 실패해도 설정 저장은 계속하고, 오류에는 무엇이 저장되지 않았는지 정확히(가사만인지, 설정도인지). 테스트 기대값 갱신.
2. **앱의 내보내기 사전 조건이 서버보다 엄격** (`songLogic.ts` `made`/`exportProblem`, `ExportForm.tsx`): 서버 규칙 그대로 — 분리 ready 필수, 가이드 켬이면 음표 ready, MP4면 가사·정렬 ready + ffmpeg. MP4가 안 되면 MP4 체크박스만 비활성(이유 표시), 폼 전체를 막지 않는다. 도달 불가 분기 정리. 테스트: "가사가 있고 정렬이 stale이면 MP3는 가능, MP4는 불가".
3. **내보내기 실패 시 partial 테스트 공백**: `fake_ffmpeg`로 두 번째 변형에서 렌더 실패 → 작업 `failed`, partial에 첫 변형 파일(`export_1_*` 키 형태)이 남는지 확인하는 Python 테스트 추가.
4. 목록 조회가 전역 락 안에서 곡별 상태(가사 해시·JSON 파싱·npy 열기)를 계산: 곡별 read만 락 안에서, 상태 계산은 락 밖에서(같은 곡 쓰기와의 경합은 결과가 다음 조회에서 바로잡히는 수준이면 충분 — 판단과 근거를 보고).
5. LOW 반영: 같은 이름 파일 동시 생성(`FileExistsError`)을 한국어 오류로 감싸기 / 원곡 추가 시 확장자 검사(mp3·m4a·wav·flac·ogg·webm·mp4, 대소문자 무시, 아니면 400 한국어) / 화면 표기의 마이너스 기호를 서버 파일 이름과 같은 `-`로 통일 / 키 값 `<output>`에 `aria-label="키 단계"` / 곡 추가 중간 실패 안내를 상세를 떠날 때 지우기.

## 실제 앱 화면에서 메인이 본 것 (스크린샷: `../thebooth-workflow/exec/song-library/screens/`)
6. **내보내기 완료 뒤에도 마지막 진행 안내가 남음**: "내보내기 완료" 아래 "3/3 · 여→남 -5 키 +1 · MP4 렌더 중"이 그대로 보인다. 끝난 작업(done·failed·cancelled)에서는 진행 message를 숨긴다(만들기 쪽도 같은 규칙인지 확인).
7. **결과 파일 목록이 읽기 어려움**: 파일마다 전체 경로 + 버튼이라 경로 길이에 따라 버튼이 줄바꿈되고 9줄이 길게 늘어진다. 저장 폴더 경로는 한 번만 보여주고, 변형(키)별로 묶어 파일 이름만(확장자 표시) 나열, "Finder에서 보기"는 변형 묶음마다 하나(첫 파일 기준) — 버튼 문구는 macOS "Finder에서 보기" / Windows "탐색기에서 보기"를 플랫폼으로 고른다(지금 고정 문구라면). 긴 이름은 줄바꿈되더라도 버튼 위치가 흔들리지 않게.
8. **목록 Table의 제목 열이 잘림**: 네 열이 같은 폭이라 제목이 잘린다. 제목 열을 넓게(나머지는 내용 폭에 맞게 고정 폭), 잘리면 말줄임 + 전체 제목 `title` 속성.
9. **추가 Modal에서 가사·보조 파일을 골랐는데 "가사가 없습니다."가 보임**: 저장된 상태 문구와 이번에 고른 파일을 구분해, 고른 파일이 있으면 그 문구를 보이지 않게(예: "추가할 가사: …").
10. **곡 상세에서 헤더 '추가' 버튼이 비활성으로 보임**: 의도라면 이유가 보이게, 아니면 상세에서도 추가 Modal을 열 수 있게(판단과 근거 보고).
