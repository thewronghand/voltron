# r4: 네 번째 독립 리뷰 지적 반영

r3 이후 호출 세션(메인)이 직접 바꾼 것이 있다(`git diff`로 확인):
- LyricsEditor: clearLyrics의 효과 없던 `pendingRequest.current = true` 대입 제거, 취소 effect 의존성에서 `song.id` 제거.
- TimingEditor: 취소 effect 의존성에서 `songId` 제거, `choose()` 가드에 `busy` 추가(← 아래 1번에서 되돌림).
- 테스트: 곡 ID 변경 테스트 2건 삭제(부모가 key로 다시 마운트해 일어날 수 없음), '이전 콜백' 테스트 이름을 실제 범위에 맞게 변경, 저장하고 정렬 중복 호출 테스트와 작업 중 이동 테스트 추가.

테스트 기준: 실제 화면에서 React는 최신 렌더 핸들러를 부른다. 오래된 클로저를 일부러 부르는 경우는 범위 밖, 같은 렌더에서 두 번 누름·API 대기 중 재호출은 범위 안. 마운트된 채로 바뀔 수 없는 의존성은 넣지 않는다.

## 고칠 것
1. **[HIGH] TimingEditor 작업 중 블록 이동 회귀** — `choose()` 첫 가드의 `busy` 때문에 곡 작업 중에는 수정이 없어도 이전/다음·목록 이동이 소리 없이 막힌다(원래는 이동 가능, 저장·되돌리기만 비활성). 원래 동작으로 되돌린다: 수정 없는 이동은 작업 중에도 된다. 확인 창이 필요한(수정 있음) 경로의 처리는 단순하게 판단(예: 작업 중이면 확인 창을 열지 않고 이동도 하지 않을지, 확인 창을 열고 취소 effect에 맡길지)하고 이유를 보고. 메인이 넣은 '작업 중에는 이동 확인을 열지 않는다' 테스트는 결정에 맞게 고치고, "작업 중 수정 없는 이동은 된다" 테스트를 추가.
2. **[MEDIUM] visible 연결 테스트** — `SongDetail.tsx`의 `visible={visible && tab === 'lyrics'}`(LyricsEditor로), `LyricsEditor.tsx`의 `visible={visible}`(TimingEditor로) 연결이 끊겨도 테스트가 실패하지 않는다. SongDetail 수준에서 숨김·탭 전환 시 하위 확인 창이 닫히는지(또는 하위로 전달된 visible이 false가 되는지) 고정하는 연결 테스트를 1~2개 추가. 세 변이(`visible={true}` 전달, `tab === 'lyrics'` 제거, `visible &&` 제거) 각각에서 실패 확인.
3. **[MEDIUM] 곡 삭제 확인 창과 api 변경** — SongDetail(SongEditor)·SongList는 처리 엔진 재연결로 `api` prop만 바뀌어도(마운트 유지) 삭제 확인 창이 열린 채 남아 이전 api로 삭제를 보낸다. LyricsEditor·TimingEditor처럼 api가 바뀌면 취소. 테스트와 변이 확인.
4. **[LOW] timingConfirmation의 `pending` 의존성 테스트** — 지금은 "확인 창 열림 → 이전 렌더 저장 콜백 호출"(범위 밖 경로)로만 지킨다. 범위 안의 실제 경로로 바꾼다(예: 같은 렌더에서 저장을 시작한 뒤 이동 시도, 또는 저장 응답이 늦게 와서 rows/chars가 바뀌는 경로). `pending` 의존성이 그 경로에서 필요 없다면 의존성을 빼고 이유를 보고.
5. **[LOW] SongList 대상 곡이 읽을 수 있게 바뀌면** — 확인 창이 열린 동안 목록 갱신으로 대상 곡이 `unreadable=false`가 되어 삭제 버튼이 사라지는 곡이 되면 창을 닫는다. (삭제 버튼이 어떤 조건에서 보이는지 먼저 확인하고, 조건이 다르면 그 조건에 맞춘다.) 테스트.

손대지 않음: Stepper 건너뛴 단계 표시, 확인 창 첫 포커스·Enter, useConfirm 위치, 드롭 테스트 방식, 불확정 막대 클래스.
