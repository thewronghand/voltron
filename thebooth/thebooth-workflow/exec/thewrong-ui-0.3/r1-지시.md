## 범위 (사용자 승인된 분류 — 이 목록 밖의 UI는 건드리지 않는다)

교체:
1. **진행 막대** `app/src/renderer/src/components/ProgressBar.tsx` — `value`가 숫자일 때만 라이브러리 `Progress`(0~100 스케일. 지금 `value`는 0~1이니 변환해 넘긴다, `aria-label`=label)로 렌더링. `value === null`(불확정)은 지금 마크업·`.progress-indeterminate` 애니메이션을 그대로 유지한다(라이브러리에 불확정 상태가 없음). 호출부 시그니처는 그대로.
2. **제목 입력 2곳** — `SongDetail.tsx`의 `#song-title`, `SongSetupModal.tsx`의 제목 input → `Input`(variant `box`). id·접근성 이름·값/저장 동작·disabled 조건 유지.
3. **가사 textarea** — `LyricsEditor.tsx`의 `#lyrics-text` → `Textarea`. id, `maxLength`, placeholder, 최소 높이(지금 min-h-80 수준), 사용자 크기 조절 가능(`resize`) 유지. 기존 `<label htmlFor>` 연결이 깨지지 않게.
4. **체크박스 전부** (renderer 안 `type="checkbox"` — ExportForm·SongSetupModal·LyricsEditor 등) → `Checkbox.Line`. 화면 문구 = 접근성 이름 유지(테스트·E2E가 `getByRole('checkbox', { name })`로 찾는다). checked/disabled/onChange 동작 유지.
5. **라디오 2묶음** (`name="mr-method"`, `name="setup-extractor"`) → `Radio.Group` + `Radio.Item`. 바깥 fieldset/legend, name, value, 선택 동작 유지.
6. **키 −/+ 버튼** (`ExportForm.tsx`, aria-label "키 한 반음 낮추기/높이기") → `Button` (secondary, outlined, small). aria-label 유지.
7. **알약 라벨** — `features/prepare/ModelRow.tsx`의 용도 표시, `ExportForm.tsx`의 키 변형 칩 → `Badge`(weak 계열, 색은 판단해서 고르고 보고). 칩 안의 제거 버튼(IconAction close)과 그 aria-label·동작은 유지.
8. **확인 창 4곳** `window.confirm` (SongList 곡 삭제, SongDetail 곡 삭제, LyricsEditor 가사 지우기, TimingEditor 저장 안 한 타이밍 버리고 이동) → 라이브러리 `Modal` 기반 확인 창. 4곳이므로 공용 컴포넌트/훅 하나로 만든다(예: `useAwaitableOverlay` 활용). 요구:
   - 문구는 지금 confirm 문구 그대로 본문에 쓴다. 제목·버튼 문구는 동작에 맞게(삭제는 위험 색 버튼 "삭제", 가사는 "지우기", 타이밍은 "버리고 이동") + "취소".
   - ESC·바깥 클릭·취소는 모두 취소로 끝난다(열린 Promise가 남지 않게). 확인했을 때만 지금과 같은 동작이 실행된다.
   - 비동기로 바뀌면서 생길 수 있는 경합(확인 창이 떠 있는 동안 상태가 바뀌거나 컴포넌트가 사라짐, 두 번 누름)을 살펴 지금과 같은 결과가 나오게 한다.
9. **가사 단계 표시** `LyricsEditor.tsx`의 `<ol aria-label="가사 편집 단계">` → `Stepper`(표시 전용, 클릭 이동 추가하지 않음). "(건너뜀)" 표시는 단계 description 등으로 유지. 현재 단계가 보조기술에 드러나는지(Stepper가 aria-current 등을 주는지) 확인해 보고하고, 없으면 접근성 이름을 잃지 않는 범위에서 보완.
