# r3: 두 번째 독립 리뷰 지적 반영

범위·금지 사항은 r1·r2와 같다. 아래만 고친다.

1. **TimingEditor 확인 중 작업 시작** — `choose()`에는 busy 가드가 없고 취소 effect의 `busy` 의존성이 유일한 방어선인데, `busy`를 의존성에서 빼도 테스트가 통과한다. "확인 창이 떠 있는 동안 busy=true로 다시 렌더하면 창이 닫히고 블록이 바뀌지 않는다" 테스트를 `timingConfirmation.test.tsx`에 추가. `busy` 의존성 제거 변이로 실패 확인.
2. **LyricsEditor `clearLyrics`의 `pending` 가드** — `pending ||`를 빼도 테스트가 통과한다. "저장하고 정렬"(saveLyricsEditor)을 미완료 Promise로 잡아 둔 채 이전 렌더의 지우기 콜백을 호출하면 확인 창이 열리지 않는 테스트를 추가. 변이로 실패 확인.
3. **취소 effect 의존성 정리** — `LyricsEditor.tsx`(취소 effect: `pending`, `song.has_lyrics`, `step`, `language` 등)와 `TimingEditor.tsx`(`rows`, `chars`, `pending`, `songId`, `index` 등) 의존성 중, 확인 창이 열린 동안(포커스 트랩·백드롭 때문에) 실제로 바뀔 수 없는 값은 의존성에서 뺀다(YAGNI). 서버 갱신·prop 변경으로 실제 바뀔 수 있는 값(예: `song.has_lyrics`, `rows`, `songId`)은 남기고 테스트로 고정(각각 제거 변이에서 실패). 남긴 것·뺀 것과 이유를 보고. 단, 빼서 실제 경합이 생기면 남긴다.
4. **TimingEditor 블록 목록 버튼** — 저장 중(`pending`)에는 `choose()`가 무시하는데 목록 버튼은 활성으로 보인다. 이전·다음 버튼처럼 블록 목록 버튼에도 `disabled={pending}`을 준다. 테스트로 고정.

손대지 않음: Stepper의 건너뛴 단계 표시(사용자 판단 대기), 확인 창 첫 포커스·Enter 동작, `useConfirm` 파일 위치.
