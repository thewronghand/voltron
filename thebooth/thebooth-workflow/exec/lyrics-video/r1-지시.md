  - license `MIT (OpenAI Whisper)`
- `ffmpeg-macos-arm64`: arch `ffmpeg`, purpose `tool`.
  - 파일 `ffmpeg.zip`
  - url `https://ffmpeg.martin-riedl.de/download/macos/arm64/1789931890_9.0.2/ffmpeg.zip`
  - size `28395699`
  - sha256 `c8ed4c4e6978a03c485edbfe4e0a5dc2380f8a30bba5150531b31b094492d924`
  - license `GPLv3 빌드 (FFmpeg 9.0.2 + libass·libx264, Martin Riedl 정적 빌드) — 남에게 배포 시 소스 제공 의무`

    - 풀린 파일의 sha256 `2e11c6f90993cdb79fff84d3f90044d28316b310e75b3e030cfc9a54f2c9d384`도 검증한다. manifest에 해제 대상 이름과 sha256을 적는 필드를 둔다.

    - zip 안 경로가 `..`·절대경로면 거부한다.
    - `is_installed`는 해제된 실행 파일까지 있어야 참이다.

- 렌더 전에 `ffmpeg -hide_banner -filters` 출력에 `ass` 필터가 있는지 확인한다. 없으면 설명이 담긴 ValueError를 낸다.

### 3. `src/thebooth/lyrics.py`: 가사 입력과 짝짓기
- **가사 파일**(필수): UTF-8 텍스트. 빈 줄은 무시하고, 줄마다 화면 한 줄의 기본 단위다.
- **보조 파일**(선택, 나무위키 붙여넣기 형식):
  - 빈 줄로 나뉜 단위마다 `[원문(루비 섞임), 발음, 번역]` 세 줄이다. 번역이 없는 두 줄 단위도 허용한다.
  - `[Verse 1]`처럼 대괄호만 있는 줄은 섹션 표시라 제거한다. 줄 안의 `[숫자]` 각주는 지운다.
- **짝짓기**: 스파이크 `triple_spike.py`와 같은 알고리즘이다.
  - 각 보조 단위의 원문(공백 제거)에 대해, 가사 파일의 연속 줄을 이어 붙인 것(공백 제거)이 부분열이 되는 동안 줄을 계속 이어 붙인다(탐욕).
  - 실패하면 "보조 파일 N번째 단위와 가사 M번째 줄이 맞지 않음"을 위치와 함께 담아 ValueError를 낸다. 가사 내용은 메시지에 넣지 않는다.
  - 마지막에 가사 줄이 남거나 보조 단위가 남아도 같은 오류다.
- **음절 가중치**: 스파이크와 같다.
  - 가사 글자가 보조 원문에서 차지하는 위치 사이에 끼어든 가나 = 앞 글자(한자)의 루비다. 루비가 있으면 그 가나 수(작은 가나 ゃゅょぁぃぅぇぉャュョァィゥェォゎ는 0)를 가중치로 쓴다.
  - 가나·장음(ー)은 1(작은 가나는 0), 나머지(문장부호 등)는 0이다.
- 결과 자료형: 화면 단위 목록. 단위마다 `가사 원문(이어 붙인 줄은 공백 하나로 연결)`, `가사 줄 번호들`, `발음 | None`, `번역 | None`, `글자별 가중치`를 담는다.
- 보조 파일이 없으면 가사 줄 하나가 화면 단위 하나다(발음·번역 None).

### 4. `src/thebooth/align.py`: 강제 정렬
- 입력: 분리 결과의 `stems.vocals`(가라오케 모델이면 리드 보컬), 가사 줄 목록, 언어 코드.
- 처리(스파이크와 같은 값):
  - 모노로 만들어 16kHz로 리샘플하고, 피크가 0.9를 넘으면 0.9로 줄인다.
  - `stable_whisper.load_model(<manifest 경로의 large-v3.pt 파일 경로>, device=...)`로 **명시 경로**에서 로드한다. 다운로드 경로가 생기지 않게 한다.
  - `model.align(audio, "\n".join(lines), language=lang, original_split=True)`
- 장치: 스파이크는 CPU였다(whisper가 MPS에서 sparse 연산 문제). `cuda`가 있으면 cuda, 아니면 cpu로 한다. mps는 쓰지 않는다.
- 결과: 줄마다 단어 목록 `(text, start, end, probability)`. 줄 수가 입력과 다르면 ValueError.
- **캐시**: 정렬 결과 JSON을 저장한다. 키는 입력 sha256 + 분리 모델 캐시 키 + 가사 줄 목록의 sha256 + 언어 + 정렬 모델 sha256 + 정렬 처리 버전 상수다. 경로는 음표 캐시처럼 **짧은 해시 디렉터리**로 하고, JSON 안에 원문 키를 두고 대조한다.

### 5. `src/thebooth/subtitles.py`: ASS 생성
- 해상도 1280×720. 위 블록(왼쪽 정렬, `\an7`)과 아래 블록(오른쪽 정렬, `\an9`)이 단위마다 번갈아 나온다.
- 각 블록은 단위 첫 글자 시작 **1초 전**에 나타나고, 마지막 글자 끝 **0.6초 뒤**에 사라진다.
- 스타일·위치는 스파이크 값이다.
  - 가사: 54px 굵게. PrimaryColour `&H00FF9A3D`, SecondaryColour `&H00FFFFFF`, 외곽선 4.
  - 발음: 38px 굵게. 같은 채움색, 미채움 `&H00E6E6E6`, 외곽선 3.
  - 번역: 30px 보통. `&H00B4B4B4`, 외곽선 2.
  - 위치: 위 블록 x=80, y=90(가사)/162(발음)/212(번역). 아래 블록 x=1200, y=400/472/522. `\pos`를 쓴다.
- 가사 줄: 단어를 글자로 균등 분할한 시각으로 글자마다 `\kf`를 단다. 공백은 시간 0이다. 블록 등장부터 첫 글자까지와 글자 사이 틈은 `\k`로 채운다. 스파이크 `kara()`와 같다.
- 발음 줄: 가중치 누적값 → 시각의 구간 선형 함수를 만들고, 발음 음절(공백·`,.!?、。` 제외)을 전체 가중치에 비례 배치한다. 스파이크와 같다. 가중치 합이 0이면 줄 전체에 균등 배치한다.
- 번역 줄: 채움 없이 고정이다.
- 글꼴은 OS별로 정한다. macOS: 가사 `Hiragino Sans`, 발음·번역 `Apple SD Gothic Neo`. Windows: `Yu Gothic` / `Malgun Gothic`. 그 외: `Noto Sans CJK JP` / `Noto Sans CJK KR`.
- 사용자 텍스트의 `{`, `}`, `\`는 ASS 태그로 해석되지 않게 이스케이프한다(`\{`, `\}`, 백슬래시는 전각 `＼`로 바꾸는 등). 줄바꿈 문자는 없다.
- 언어 코드는 정렬에만 쓴다. 표시는 언어와 무관하다.

### 6. 렌더 (`src/thebooth/video.py`)
- 명령(스파이크에서 동작 확인):
  ```
  ffmpeg -hide_banner -loglevel error -y -f lavfi -i color=c=0x101418:s=1280x720:r=30 -i <MR 오디오> -vf ass=<ASS 파일명> -map 0:v -map 1:a -c:v libx264 -preset veryfast -crf 20 -pix_fmt yuv420p -profile:v high -level 4.0 -c:a aac -b:a 256k -ar 44100 -movflags +faststart -shortest <출력.mp4>
  ```
- **ASS 경로 이스케이프 문제를 피한다**: 필터 인자에 절대경로를 넣지 말고, ffmpeg를 ASS 파일이 있는 폴더를 cwd로 실행하고 파일명만 넘긴다. Windows 드라이브 문자 콜론이 필터 문법과 충돌하기 때문이다. 파일명은 안전한 고정 이름으로 임시 복사해도 된다.
- 출력은 임시 이름에 쓴 뒤 `os.replace`로 원자적으로 옮긴다. ffmpeg 실패 시 stderr 마지막 몇 줄을 담은 ValueError를 낸다.
- `subprocess.run`은 리스트 인자로 호출하고 `shell=False`로 둔다.

### 7. 파이프라인·CLI
- `pipeline.make`에 키워드 인자를 추가한다.
  - `lyrics: Path | None`, `lyrics_extra: Path | None`, `lyrics_lang: str = "ja"`, `video_output: Path | None`
  - 주입용 `aligner_factory`, `video_renderer`
- `video_output`이 있으면 `lyrics`는 필수다(분리 전에 검사).
  - 가사·보조 파일 파싱과 짝짓기 검사도 **오디오를 읽기 전에** 한다. 짝이 안 맞으면 몇 분짜리 분리 뒤가 아니라 즉시 실패해야 한다.
  - 정렬 모델·ffmpeg 설치 확인(+ass 필터 확인)도 분리 전에 한다. 주입 경로에서는 건너뛴다(기존 `pitch_factory`와 같은 원칙).
- 흐름: 기존대로 MP3(MR+가이드+키)를 쓴다 → 정렬(캐시 우선) → ASS 생성 → 그 MP3를 오디오로 MP4를 렌더한다.
  - **ASS 파일은 MP4 옆에 같은 이름 `.ass`로 항상 남긴다**(Aegisub 편집용).
  - 키 변경은 가사 타이밍에 영향이 없다.
- 경로 충돌 검사(`_check_paths`)에 영상·ASS 출력도 넣는다. 원곡·MR·보컬 출력과 같으면 거부한다.
- `MakeResult`에 영상 경로, ASS 경로, 정렬 캐시 적중 여부를 추가한다.
- CLI `make` 옵션:
  - `--lyrics PATH`, `--lyrics-extra PATH`
  - `--lyrics-lang TEXT`(기본 `ja`. Whisper 언어 코드라 `ja`·`ko`·`en` 정도로 검증할 필요는 없다. 단 빈 문자열은 거부)
  - `--video PATH`(.mp4만)
  - 완료 메시지에 영상·ASS 경로를 출력한다.
  - `--lyrics` 없이 `--video`면 exit 2. `--video` 없이 `--lyrics`·`--lyrics-extra`면 "적용되지 않습니다" 안내만 하고 진행한다(가이드 옵션과 같은 원칙).
- 새 명령 `thebooth video --ass 편집한.ass --audio MR.mp3 -o out.mp4`: Aegisub로 고친 ASS를 다시 렌더한다. 정렬·분리 없이 렌더만 한다.

  - 발음 채움이 가중치 비례(예: 루비 2음절 한자 뒤 가나 1개 → 발음 3음절 중 앞 2음절이 한자 구간)
  - 가중치 0 균등 배치
  - `{}` 이스케이프
  - OS별 글꼴 선택(sys.platform monkeypatch)
- models/tools:
  - zip 해제: 정상, `..` 경로 거부, 해제 파일 sha 불일치 거부. 로컬 HTTP fixture `tests/conftest.py`를 쓴다.
  - `THEBOOTH_FFMPEG` 우선
  - 미설치 안내 메시지
  - 플랫폼 불일치 표시
- pipeline:
  - 가짜 분리기 + 가짜 정렬기 + 가짜 렌더러로 `.ass`가 영상 옆에 생기고, 렌더러가 MP3 경로와 ASS 경로를 받는지
  - 두 번째 실행은 정렬 캐시가 적중하는지
  - 가사가 바뀌면 다시 정렬하는지
  - 짝 오류·`--video` 단독은 분리 전에 실패하는지(가짜 분리기 호출 0)
- video: 명령 인자 목록 구성(cwd·파일명만 넘기는지). 실제 ffmpeg 호출은 slow 테스트로 한다.
- CLI: 위 옵션 조합의 exit code, `video` 명령.
- slow(설치돼 있을 때만, 미설치면 skip):
  - 실제 ffmpeg로 2초짜리 지어낸 ASS + 사인파 오디오를 렌더한다. 결과 mp4를 다시 ffmpeg로 열어 길이·스트림 2개를 확인한다.
  - Whisper large-v3를 명시 경로에서 로드한다(로드만, 정렬 X — 오래 걸린다).
