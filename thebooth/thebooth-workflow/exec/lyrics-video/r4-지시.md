# r4: 3차 리뷰 지적 반영

r3 이후 호출 세션은 코드를 고치지 않았다. 실곡 재실행에서 짝짓기는 정상이었고 언어 코드 오타는 분리 전에 거부됐다.

## 1. [MEDIUM] 단어 단위 루비 무게 (lyrics.py)
- 문제: 나무위키는 루비를 단어 단위로 붙인다(`運命うんめい`). 지금은 루비를 마지막 한자에만 붙여, 가사 `運命の日` + 보조 `運命うんめいの日ひ` → `(0, 4, 1, 1)`이 된다. 기대값은 `(2, 2, 1, 1)`이다.
- 정책: 루비 없는 한자가 연속하다가 루비가 붙은 한자에서 끝나면, 그 루비 음절 수를 **한자 묶음 전체에 고르게 나눈다**. 나머지는 앞쪽 한자부터 1씩 더 준다(예: 3음절 / 2한자 → (2, 1)).
- 한자 하나에 루비가 붙은 기존 경우와 오쿠리가나 경우(`今まで`/`今いままで` → (2,1,1))는 그대로다.
- 테스트: 위 사례, 홀수 나눔, 한자 세 개 묶음, 묶음 사이에 가나가 끼는 경우(별개 묶음).

## 2. 남는 글자 허용 범위 (lyrics.py)
- 보조 원문에만 있는 **기호(유니코드 S\* 범주, 예: ♪ ☆ ♡ →)**도 문장부호처럼 남아도 되는 글자로 허용한다.
- 각주 제거 확장: `[숫자]`뿐 아니라 줄 안의 짧은 대괄호 표기 `[a]`·`[*A]`·`[주 1]`(대괄호 안 10자 이하이고, 줄 전체가 아닌 것)와 전각 `［1］`도 지운다. 줄 전체가 대괄호인 섹션 표시는 지금처럼 줄째 지운다.
- "한자 뒤 남는 가나는 루비로 간주한다"는 모호성(예: 보조 원문에만 있는 조사가 루비로 흡수될 수 있음)을 해당 함수 docstring에 "알려진 한계 + 이유(표기만으로 구분 불가)"로 적는다.
- 테스트: `♪` 허용, 각주 변형 제거.

## 3. 짝짓기 견고성 (lyrics.py)
- 재귀를 반복문(또는 명시적 스택/DP 테이블)으로 바꿔, 단위 수에 따른 RecursionError가 나지 않게 한다. 테스트: 2000단위 합성 입력이 정상 처리된다.
- 오류 메시지 위치: 가사 줄이 남으면 "가사 X번째 줄부터 대응하는 보조 단위가 없음", 보조 단위가 남으면 "보조 파일 N번째 단위부터 대응하는 가사 줄이 없음"으로 실제로 있는 위치를 가리킨다. 기존 테스트 문구도 갱신한다.

## 4. 기타
- `subtitles.py`: 발음 음절에서 빼는 부호에 전각 부호(`！？…～・「」『』（）`)와 유니코드 P\*·S\* 범주 전반을 포함한다(공통 판정 함수로).
- `align.py`: `stable_whisper.load_model`·체크포인트 로드 단계의 예외(RuntimeError·pickle 오류 등)도 "모델 파일을 읽지 못했습니다(<예외 클래스 이름>). 모델 폴더를 지우고 `thebooth models pull whisper-large-v3`로 다시 받으세요"로 감싼 ValueError로 바꾼다. 테스트는 손상 파일로 확인한다.
