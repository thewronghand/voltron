# r3: 2차 리뷰 지적 반영

r2 이후 호출 세션은 코드를 고치지 않았다. 실곡 재실행은 새 실패 기준을 통과했다(경고 기타 1건, 중단·실패 0).

## 1. 보조 원문의 남는 글자 검사 (lyrics.py)
- 문제: 짝짓기가 "가사 줄이 보조 원문의 부분열인가"만 본다.
  - 가사 파일이 구절을 빠뜨려도 통과한다. 그러면 1행(일본어)과 2·3행(발음·번역)이 서로 다른 내용을 보여준다.
  - 다음 가사 줄이 앞 단위의 루비 꼬리 안에 부분열로 들어가면 잘못 합쳐진다.
- 정책: 단위마다 매칭이 끝나면, 보조 원문에서 짝지어지지 않은 글자가 다음 셋 중 하나인지 확인한다.
  - (a) 한자 바로 뒤에 이어지는 가나. 루비이고, 매칭된 가사 글자 사이에 있다.
  - (b) 공백
  - (c) 문장부호(`、。，．,.!?！？…～~ー・「」『』()（）` 등)
  - 아니면 "보조 파일 N번째 단위에 가사 파일에 없는 글자가 있음(가사 M번째 줄 부근)"처럼 위치만 담은 ValueError를 낸다.
- 탐욕적 이어붙이기는 이 검사로 판정한다. 다음 줄을 붙였을 때 위 검사를 통과하는 쪽(남는 글자가 루비·공백·부호뿐)만 받아들인다. 이렇게 하면 루비 꼬리에 끼는 짧은 줄을 흡수하지 않는다.
- 짝짓기 비교에만 **NFKC 정규화**를 적용한다. 반각·전각 차이(`!`/`！`, `~`/`～`)로 실패하지 않게 하기 위해서다. 표시 텍스트는 원문을 유지한다.
- 테스트: 가사 줄에서 구절이 빠진 경우(중간·끝)는 오류가 난다. 루비 꼬리에 들어가는 짧은 다음 줄은 흡수하지 않는다. 반각·전각 차이는 통과한다. 기존 정상 사례는 그대로 통과한다.

## 2. 언어 코드 사전 검증 (pipeline.py·cli.py)
- 분리 전에 `whisper.tokenizer.LANGUAGES`(코드)와 `TO_LANGUAGE_CODE`(이름)로 검사한다. 지원하지 않으면 "지원하지 않는 언어 코드: jp"로 실패한다(CLI exit 2). 언어 코드는 가사가 아니라 메시지에 넣어도 된다.
- whisper import가 무거우면 이 검사 때만 지연 import한다.

## 3. subprocess 인코딩 (video.py·tools.py)
- `text=True`를 쓰는 곳에 `encoding="utf-8", errors="replace"`를 지정한다. Windows cp949 로캘에서 ffmpeg의 UTF-8 경로 출력 때문에 실제 오류가 가려지는 것을 막는다.

## 4. 정렬 헤드 실검증과 버전 고정
- slow 테스트(`tests/test_align.py`의 실제 Whisper 테스트)에 검사를 추가한다. 로드된 모델의 `alignment_heads.to_dense()`가 `whisper._ALIGNMENT_HEADS["large-v3"]`로 만든 기준(whisper `set_alignment_heads`와 같은 디코딩)과 같은지 본다.
- `pyproject.toml`에 `openai-whisper==20250625`를 직접 의존성으로 고정한다. 비공개 API `_ALIGNMENT_HEADS`에 기대고 있어서다. 이유를 주석으로 남긴다.

## 5. 정리 (LOW)
- ASS 이스케이프: `{`·`}`는 전각 `｛`·`｝`로 바꾼다. Aegisub가 `\{`를 모르기 때문이다. 기존 이스케이프 테스트를 갱신한다.
- `pipeline`: 정렬 검증(실패 기준)을 통과하면 ASS 생성(`subtitles.write`) **전에** 캐시에 저장한다. 테스트로 ASS 단계 오류 뒤에도 캐시가 남는지 확인한다.
- `align.py`의 정렬 실패 감싸기 메시지에 예외 클래스 이름(`type(e).__name__`)만 덧붙인다. 원 메시지는 가사가 섞일 수 있어 넣지 않는다.
- README 보조 파일 형식 절: 단위는 빈 줄로 구분하고, 섹션 표시는 대괄호 형식(`[Verse 1]`)만 지운다는 제약과 오류 예를 명시한다.
