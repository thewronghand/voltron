## 범위 (사용자 승인된 분류 — 이 목록 밖의 UI는 건드리지 않는다)

1. **곡 상세 탭 → `Tabs keepMounted`** (`app/src/renderer/src/features/songs/SongDetail.tsx`)
   - 직접 만든 tablist/tab/tabpanel을 `<Tabs keepMounted value={tab} onValueChange=… aria-label="곡 상세" items=[…]>`로 바꾼다. 탭 라벨 '만들기·내보내기', '가사'는 그대로.
   - 가사 패널 내용은 지금처럼 처음 가사 탭을 고를 때 만들어지게 한다: `lyricsOpened && <LyricsEditor … />`를 content에 그대로 넣고, `onValueChange`에서 'lyrics'가 오면 `setLyricsOpened(true)`. 클릭뿐 아니라 화살표 키(activation auto)로 고를 때도 같은 경로를 탄다.
   - `visible && tab === 'lyrics'`를 LyricsEditor `visible`로 넘기는 것을 유지한다(탭 전환 때 열린 확인 창을 실행 없이 닫는 기존 동작). 이 동작을 지키는 기존 테스트가 있으면 계속 통과해야 한다.
   - 패널의 기존 간격 클래스(`space-y-6`, `space-y-4`)는 content를 div로 감싸 유지한다. 라이브러리 TabItem에는 패널 className이 없다.
   - 패널 내부 SongJobProgress 배치 등 다른 내용은 바꾸지 않는다.
2. **곡 목록 정렬 → 라이브러리 정렬 + 제어 상태** (`SongList.tsx`, `songListLogic.ts`)
   - `title` 열에 `sortValue: (song) => song.title`, `added_at` 열에 `sortValue: (song) => song.added_at`(ISO 문자열 또는 null; 문자열이 한국어 numeric 비교에서 시간 순서를 지키는지 확인하고, 아니면 `new Date(...)`를 쓴다. null은 라이브러리가 양방향 맨 뒤로 보낸다).
   - Table에서 `serverSideSorting`·`initialSort`를 빼고 `sort={sort}` + `onSortChange`로 앱 상태를 갱신한다. `sortCycle="toggle"` 유지. data는 `songs` 그대로(라이브러리가 정렬).
   - `onSortChange`가 null을 주면 `DEFAULT_SONG_SORT`, key가 'title'|'added_at'가 아니면 무시(지금 로직 유지). `any`·단언 남용 없이 좁힌다.
   - `sortSongs`는 더 쓰이지 않으면 지우고, `tests/songList.test.ts`의 `sortSongs` 테스트 의도(기본 추가일 내림차순, null 맨 뒤, 제목 가나다 오름·내림, 숫자 인식)를 실제 SongList 렌더 테스트(기존 `songListSort.test.tsx` 등)로 옮긴다. 의도를 약하게 만들지 않는다.
   - 위의 "정렬 상태 두 곳" 주석은 지운다.
3. **슬라이더 2곳** (`BoxOpacityInput.tsx`, `ExportForm.tsx`): `style={{ width: '8rem' }}` → `className="w-32"`. 렌더 결과에서 Tailwind 폭 클래스가 실제로 이기는지(라이브러리 `ui.css`의 `.ui-slider`가 `@layer components` 안인지) 확인한다.
4. **남녀 전환 Select** (`ExportForm.tsx`): `<div className="w-40">` 래퍼를 지우고 `containerProps={{ className: 'w-40' }}`. `TimingEditor.tsx`의 `w-40` 래퍼는 라벨까지 묶고 있으므로 바꾸지 않는다.
5. **가사 편집 단계** (`LyricsEditor.tsx`): 루비 단계 라벨을 항상 '루비 확인'으로 하고, 루비 단계를 건너뛸 때 `skipped: true`를 준다. 그 위 0.5.0 주석과 `className="[&_.truncate]..."` 우회를 지운다(라벨이 짧아져 필요 없음). `tests/uiMigration.test.tsx`의 '루비 확인 (건너뜀)' 기대를 새 표시(라이브러리 aria-label의 "(건너뜀 예정)", 보이는 "건너뜀 예정")로 바꾸고, 지난 단계가 됐을 때 "(건너뜀)"도 확인한다.
6. **링크 버튼 5곳** (`SongDetail.tsx` 2, `SongList.tsx` 2, `ExportForm.tsx` 1): `className="text-inherit"` → `color="inherit"`. `font-semibold` 같은 다른 클래스는 className에 남긴다. `RubyPreview.tsx`의 `text-amber-800` 버튼은 바꾸지 않는다. 렌더 결과에 `text-primary-fg`가 남지 않고 상속 색인지 기존 테스트(uiRender 등)로 확인한다.
7. **Input `containerProps` 병합 확인** (`SongDetail.tsx` 곡 제목 `containerProps={{ className: 'min-w-0 flex-1' }}`): 0.6.0에서 기본 클래스와 병합되도록 바뀌었다. 병합 결과 클래스를 dist로 확인해 제목줄 배치(입력칸이 남는 폭을 채우고 '제목 저장' 버튼이 같은 줄)에 영향이 있는지 보고한다. 문제가 보이면 고치지 말고 보고만 한다.
