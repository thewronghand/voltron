- 파일 머리에 출처(레포·경로)·MIT 라이선스·변경 사항을 한국어로 적는다.

### 4. `src/thebooth/pitch.py` (새 파일)
- 공통 출력: 10ms 간격 f0 배열(Hz, float32, 무성은 0)을 담는 자료형 `F0Track`(f0, hop_seconds).
- 입력: `(2, N)` 44.1kHz 보컬 → 모노 → 16kHz (`scipy.signal.resample_poly`). 모노 피크가 0.9를 넘으면 0.9로 줄여 넣는다(FCPE가 ±1을 넘는 입력에 에러 로그를 낸다. 음높이는 음량과 무관하다).
- `extractor`: `"fcpe" | "rmvpe"`
  - **fcpe**: `torchfcpe` 패키지 안 `assets/fcpe_c_v001.pt`의 경로를 찾아 **로드 전에 sha256이 `b9aeaeb673436eeda50ceafd632aa681aa63417e52eae4207503d180c9b10015`인지 확인**한다. 다르면 설명이 담긴 ValueError를 낸다(패키지 버전이 바뀐 것). 그다음 `torchfcpe.spawn_infer_model_from_pt(path, device, bundled_model=True)`로 로드한다. 추론 파라미터는 스파이크와 같다: `decoder_mode="local_argmax"`, `threshold=0.006`, `f0_min=60`, `f0_max=1200`, `interp_uv=False`, `output_interp_target_length=len(mono16)//160+1`.
  - **rmvpe**: manifest의 `rmvpe`가 설치돼 있어야 한다(없으면 `ModelNotInstalledError`, 메시지에 `thebooth models pull rmvpe`). `thred=0.03`.
- 장치는 `devices.select_device()`.

### 5. `src/thebooth/melody.py` (새 파일)
- `Note`(start 초, end 초, midi 정수) frozen dataclass.
- `to_notes(track) -> list[Note]`: 스파이크 `to_notes`와 같은 알고리즘·기본값이다. midi 변환 → `scipy.signal.medfilt` 9프레임 → 무성 0 유지 → 반올림 → 같은 값 연속 구간을 음표로 → 같은 음 사이 50ms 이하 틈 잇기 → 80ms 미만 버리기. 값은 모듈 상수로 둔다.
- `synth(notes, length, semitones, sample_rate) -> 모노 float32`: 스파이크 `synth`와 같은 음색(기본음 + 0.3×2배음 + 0.12×3배음)과 엔벨로프(어택 10ms 선형, 음 끝부터 50ms 선형 릴리스)를 쓴다. **키 변경은 음표 midi에 semitones를 더해서** 반영한다(오디오 피치 시프트 아님).
- `guide_track(notes, reference_vocals, semitones, level_db) -> (2, N) float32`: 합성 결과에서 |값| > 1e-4인 샘플을 "가이드가 울리는 구간"으로 잡는다. 그 구간에서 가이드 RMS가 같은 구간 원래 보컬(모노) RMS × 10^(level_db/20)이 되도록 맞추고 스테레오로 복제한다. 음표가 없거나 보컬이 무음이면 0 배열을 돌려준다(0으로 나누지 않는다).

### 6. 캐시
- 음표 결과를 캐시한다. 키 = 입력 sha256 + 분리 모델 캐시 키(`_cache_key(model_id)`) + 추출기 키 + 멜로디 처리 버전. 추출기 키에는 fcpe는 동봉 sha256, rmvpe는 manifest 파일 sha256을 넣는다.
- 저장 위치: `cache_root/"melody"/...` 아래 JSON(`[[start, end, midi], ...]`), `cache.py`처럼 임시 파일 → `os.replace`로 원자적으로 쓴다. 깨진 JSON은 없는 것으로 본다. `cache.py`에 함수를 더하는 방식이 자연스러우면 그렇게 한다.
- 음표 처리 상수(`to_notes`의 기본값)를 바꾸면 캐시가 무효화되게 버전 상수를 둔다. 기존 `SEPARATION_CACHE_VERSION`을 참고한다.

### 7. 파이프라인·CLI
- `pipeline.make`에 키워드 인자를 추가한다: `guide: bool = False`, `guide_level_db: float = -6.0`, `pitch_extractor: Literal["fcpe","rmvpe"] = "fcpe"`, 그리고 테스트 주입용 `pitch_factory`. 분리기 주입(`separator_factory`)과 같은 방식으로, 가짜 f0 추출기를 끼울 수 있게 한다.
- guide가 켜지면 분리 결과의 `vocals`로 음표를 얻는다(캐시 우선). 최종 MR = `shift_key(mr, semitones) + guide_track(notes, stems.vocals, semitones, guide_level_db)`. 그다음 기존처럼 `write_mp3`(피크 정규화)로 저장한다.
- `--vocals` 출력은 지금과 같다(가이드를 섞지 않는다).
- guide가 꺼져 있으면 동작·출력이 지금과 완전히 같아야 한다. f0 추출기를 로드하지 않는다.

## 테스트 (최소한 이것들, `tests/test_melody.py`·`tests/test_pitch.py` 등)

- `to_notes`: 일정한 음 → 음표 1개(정확한 midi). ±40센트 비브라토(5~6Hz)는 같은 음 1개로 유지. 30ms짜리 다른 음 끼어듦은 버려짐. 같은 음 사이 40ms 무성 틈은 하나로 이어지고, 100ms 틈은 둘로 갈림. 전부 무성이면 빈 목록.
- `synth`: 음표 하나를 합성했을 때 기본 주파수가 맞는지(FFT 최대 피크 대신 기본음 근처 대역 에너지나 자기상관을 쓴다. 배음 때문에 최대 피크만 보면 틀릴 수 있다). `semitones=+2`면 정확히 2반음 위. 길이가 `length`와 같다.
- `guide_track`: level_db=−6이면 울리는 구간 RMS 비율이 0.5±1%. 음표가 없거나 보컬이 무음이면 0이고 NaN이 없다.
- 파이프라인: 가짜 분리기 + 가짜 f0 추출기로
  - guide off면 추출기 팩토리가 호출되지 않는다.
  - guide on이면 출력이 MR만 있을 때와 달라진다.
  - 두 번째 실행(키만 다름)은 음표 캐시를 적중하고 추출기를 다시 부르지 않는다. 추출기·분리 모델을 바꾸면 다시 부른다.
  - 키 +2 출력의 가이드 음이 키 0보다 정확히 2반음 위다. MR을 0으로 두는 가짜 분리기로 가이드만 남겨 확인한다.
- FCPE 동봉 가중치 sha256이 다르면 ValueError(파일을 직접 건드리지 말고 경로 함수를 monkeypatch해 가짜 파일로 확인).
- manifest: `rmvpe` 고정값(리비전 URL·크기·sha256·purpose).
- CLI: `--pitch nope` → exit 2. `--model rmvpe` → exit 2. `--guide-level 7` → exit 2. help에 권장 문구가 있다(`env={"COLUMNS": "200"}`로 줄바꿈 방지 — 기존 테스트 참고).
- slow(설치돼 있을 때만): fcpe·rmvpe 각각 220Hz 사인파 2초(스테레오, 44.1kHz) → 유성 프레임의 f0 중앙값이 220Hz ±1%. RMVPE 실제 가중치 strict 로드 성공.
