# r2: 리뷰 지적 반영

r1 이후 호출 세션이 작업 트리를 직접 고쳤다(가이드 음량 범위 검사, f0 60~1200Hz 마스킹, 추론 설정을 캐시 키에 포함, `--guide` 없이 준 옵션 경고, librosa 상한, README 한 줄). **먼저 `git diff`와 새 파일들을 다시 읽어 현재 상태를 파악한다.** r1 때 기억과 다를 수 있다.

아래 항목을 모두 반영한다. 각 항목의 "정책"은 호출 세션이 이미 결정한 것이다. 그대로 따른다.

## 1. [HIGH] Windows 경로 길이 — 음표 캐시 디렉터리 이름 단축
- 현재 `cache_root/melody/<분리키>/<extractor_key>/<input_sha>.json` 형태다. extractor_key가 sha256 64자를 그대로 담아 Windows 경로가 260자(MAX_PATH)를 넘을 수 있다(사용자명 8자 + `melband-roformer-karaoke` + fcpe 기준 260자).
- 정책: 디렉터리 이름에는 **extractor_key(+멜로디 버전) 전체 문자열의 sha256 앞 12자**만 쓴다(`pipeline._cache_key`의 짧은 해시 방식과 같다). 원문 키는 JSON 안에 함께 저장하고, 로드할 때 원문이 다르면 캐시 미스로 본다(해시 충돌 방어).
- 테스트: 가장 긴 조합(`melband-roformer-karaoke` × fcpe/rmvpe)의 캐시 파일 경로에서 `cache_root` 이후 상대 경로 길이 상한을 단언한다. 기준은 Windows 캐시 루트 `C:\Users\<20자 사용자명>\AppData\Local\thebooth\Cache` 길이 + 상대 경로 ≤ 240이다. 키 원문이 다르면 미스가 되는 테스트도 둔다.

## 2. [MEDIUM] FCPE 상한이 무성 처리되지 않음
- 원인: `model.infer(..., f0_max=F0_MAX_HZ)`가 torchfcpe 내부에서 1200 초과 값을 1200.0으로 잘라내고(models_infer.py:89-90), `_mask_range`는 `> 1200`만 지운다. 그래서 잘린 값이 유성 1200Hz로 남는다.
- 정책: `infer`에 **`f0_max`를 넘기지 않는다**(None, 자르기 없음). 범위 처리는 `_mask_range` 하나로만 한다. `f0_min`은 넘겨도 무해하지만 혼동을 줄이려고 넘기지 않는다.
- 테스트: FCPE 모델 객체를 가짜로 바꿔(1300Hz·50Hz·440Hz 프레임을 내게) `extractor_for("fcpe")`가 돌려준 추출 함수의 결과에서 1300·50은 0, 440은 유지되는지 확인한다. sha256 검사·`torchfcpe.spawn_infer_model_from_pt`는 monkeypatch한다. 테스트하기 쉽게 후처리 함수를 분리해도 된다.

## 3. [MEDIUM] 캐시 키와 주석 불일치
- 정책: `F0_SAMPLE_RATE`, `F0_HOP`, FCPE `decoder_mode`, `interp_uv`도 상수로 빼서 extractor_key에 넣는다. pitch.py 주석은 "이 파일의 추론 상수는 전부 extractor_key에 들어간다. 키에 없는 처리(음표화 등)를 바꾸면 melody.MELODY_CACHE_VERSION을 올린다"는 뜻으로 사실대로 고친다.
- 테스트: 기존 `test_extractor_key_includes_inference_settings`를 새 상수까지 포함하도록 확장한다.

## 4. [MEDIUM] 가이드 준비 상태를 분리 전에 확인
- 정책: `guide=True`면 **오디오를 읽기 전에** 다음을 확인한다.
  - rmvpe: 설치 여부. 미설치면 `ModelNotInstalledError`이고, 메시지에 `thebooth models pull rmvpe`를 넣는다.
  - fcpe: 동봉 가중치 sha256. 다르면 ValueError.
- 모델 로드 자체는 지금처럼 나중에(음표 캐시 미스일 때만) 한다. `pitch_factory`가 주입된 테스트 경로에서는 이 사전 확인을 건너뛴다. 주입된 가짜와 실제 설치 상태가 무관하기 때문이다.
- 테스트: rmvpe 미설치(`models_root=tmp_path/"empty"`) + guide on이면, 가짜 분리기가 한 번도 불리지 않고 `ModelNotInstalledError`가 난다. 이 테스트에서는 `pitch_factory`를 넘기지 않아야 사전 확인이 돈다.

## 5. [MEDIUM] 가이드 off 회귀 테스트
- 두 가지를 모두 추가한다.
  - (a) `write_mp3`를 monkeypatch해 기록된 배열을 잡는다. 가이드 off 결과가 `audio.shift_key(make_mr(mix, stems, method), k)`와 정확히 같아야 한다(가짜 분리기, k=0과 k=2).
  - (b) 새 서브프로세스(`sys.executable -c ...`)에서 가짜 분리기로 guide off `pipeline.make`를 실행한 뒤 `thebooth.pitch`·`thebooth.melody`·`torchfcpe`가 `sys.modules`에 없는지 확인한다. 테스트용 가짜는 서브프로세스 코드 안에 정의한다.

## 6. [LOW] 정리
- `--guide` 없이 준 옵션 경고: 가이드가 꺼져 있으면 `pipeline.make`가 `guide_level_db`를 검증하지 않게 한다. 그래야 "무시됩니다" 문구가 사실이 된다. 테스트: guide off + `guide_level_db=nan`이 정상 완료.
- pipeline.py의 "모르는 모델 id면 여기서 KeyError" 주석이 낡았다. 실제로 KeyError가 나는 줄로 옮기거나 고친다.
- `pipeline._installed_spec`를 `models.py`의 공개 함수(예: `models.require_installed(model_id, root)`)로 옮긴다. 예외 클래스 `ModelNotInstalledError`도 models.py로 옮기고, `pipeline.ModelNotInstalledError`는 기존 import 호환을 위해 같은 클래스를 가리키게 둔다. pitch.py가 pipeline의 private 함수를 import하지 않게 한다.
- `melody.to_notes` 순서: **80ms 미만 음표를 먼저 버리고, 그다음 같은 음 사이 50ms 이하 틈을 잇는다.** "A(길게) – B(30ms) – A"가 A 하나로 이어지게 하는 것이다. `MELODY_CACHE_VERSION`을 2로 올린다. 테스트: 이 경우와, 다른 음 사이에 긴 다른 음이 끼면 잇지 않는 경우.
