# 작업: thebooth 2b r3 — r2 리뷰 반영

같은 레포·브랜치(`feat/app-packaging`), r1·r2 미커밋 변경 위에서. 
**중요: 메인이 지금 `app/dist/mac-arm64/thebooth.app`을 실제로 띄워 긴 확인을 돌리고 있다. `pnpm dist:mac`·`pnpm dist:win`을 실행하지 말고 `app/dist/`를 건드리지 말 것.** 패키징 앱 실행도 하지 않는다(메인이 다음에 다시 빌드·확인한다).

## 반영할 것
1. **깨진 실행 환경에서 빠져나올 길** (runtime.ts·index.ts): 패키징 모드에서 실행 환경이 `ready`인데 사이드카가 시작에 실패하거나(failed) 예기치 않게 종료되면(exited), 화면에 "실행 환경 다시 구성" 동작을 준다(상태 기록 삭제 → 다시 동기화 → 사이드카 시작). 기존 "다시 시작"(사이드카만)은 그대로 두고 둘을 구분되는 문구로. IPC는 기존과 같이 `assertRenderer`. 개발 모드에는 보이지 않게.
2. **실패 메시지에 원인 한 줄** (runtime.ts:108 부근): 단계별(동봉 uv 확인·실행 실패 / 파일 준비 / 패키지 설치(uv 종료 코드) / 기록 저장)로 사람이 이해할 한국어 한 줄을 고른다. 예: "처리 엔진 설치 도구(uv)를 찾지 못했습니다.", "패키지 설치에 실패했습니다(종료 코드 2). 네트워크 연결을 확인하고 다시 시도해 주세요." uv 출력 문구를 파싱해 원인을 추측하지는 않는다(종료 코드·우리 단계까지만). 상세는 지금처럼 로그.
3. **엔진 상태 표시 회귀** (App.tsx): 실행 환경이 ready일 때 `EngineStatus`를 준비·만들기 두 탭 모두에서 보여준다(r2 이전 동작 복원). 실행 환경 미준비 시에는 RuntimePanel과 겹치지 않게 지금처럼.
4. **취소 테스트 보강** (runtime.integration.test.ts): 가짜 빌드 백엔드(손자 프로세스)가 자기 pid를 파일에 쓰게 하고, 취소 후 그 pid도 죽었는지, `cancel()`이 수 초(예: 10초) 안에 끝나는지를 검사. `detached` false 변이·`child.kill()` 변이에서 실패하는지 실제로 돌려 확인하고 보고(변이는 되돌릴 것).
5. **Windows 변형 흔들림 방지** (runtime.ts·runtimeConfig.ts): `nvidia-smi` 판단을 세 갈래로: (a) 실행 파일 없음(ENOENT) → `cpu`, (b) 정상 출력에서 CUDA 버전 판독 → 13.2 이상 `cu132` / 미만 `cpu`, (c) 실행 실패·타임아웃·버전 판독 불가 → **기록된 변형이 있으면 그대로 유지**, 없으면 `cpu`. 순수 함수 + 테스트. README의 CUDA 규칙도 맞춘다.
6. **지문에 동기화 명령 포함** (runtimeConfig.ts): `syncArgs` 결과(변형 반영 후)의 해시를 상태 기록에 넣어, 앱 업데이트로 명령만 바뀌어도 다시 동기화.
7. **남은 임시 폴더 정리** (runtime.ts): 동기화 시작 때 `runtime/.project-*` 잔여물을 지운다(실패해도 진행).
8. **재구성 안내 유지** (runtime.ts:192 부근): 업데이트 재구성을 취소·실패한 뒤 다시 시도해도 "앱이 바뀌어 다시 맞추는 중" 안내가 유지되게(예: 기록을 지우기 전에 '이전 구성 있음'을 별도 표식으로 남기거나 비교 결과를 보존).
9. **"처음 큰 다운로드" 안내는 `syncing`에서만** (RuntimePanel.tsx:27).
10. **App 탭 로직 테스트**: 실행 환경 미준비 → 준비 탭 시작·만들기 탭 안내, 준비됨 → 두 탭 EngineStatus를 가능한 범위에서 테스트(기존 테스트 방식에 맞게; 무리하면 로직을 순수 함수로 빼서 테스트).
11. `runtime.integration.test.ts:91`의 효과 없는 `UV_OFFLINE: '1'`은 지우거나, 제거된다는 것을 단언하는 테스트로 바꾼다.
