# 작업: thebooth 2b r4 — r3 리뷰 반영

같은 레포·브랜치, 누적 미커밋 변경 위에서. **`pnpm dist:*` 실행 금지, `app/dist/` 건드리지 말 것, 패키징 앱 실행 금지**(메인이 실제 앱 확인 중).

1. **"실행 환경 다시 구성"이 깨진 패키지를 실제로 고치게**: 지금 강제 경로는 기록 삭제 + 평소 `uv sync`라, uv가 dist-info만 보고 손상된 torch 등은 그대로 둔다. 강제 재구성일 때 동기화 전에 `runtime/venv`를 통째로 지운다(uv 캐시가 남아 재설치 비용은 작음). `runtime/python`(uv가 받은 인터프리터)도 손상됐을 수 있으니 같이 지운다 — 다시 받는 비용(수십 MB)은 감수. 지우기 실패(Windows 파일 잠금 등)는 원인 한 줄로 실패 처리. 통합 테스트로 강제 재구성 후 venv가 새로 만들어졌음(예: 미리 넣어둔 표식 파일이 사라짐)을 확인.
2. **재구성 안내 문구 구분**: 재구성 표식에 원인(`update` | `rebuild`)을 기록하고, 상태·화면 문구를 나눈다. 앱 업데이트·형식 변경으로 다시 맞출 때 "앱이 바뀌어 실행 환경을 다시 맞추고 있습니다.", 사용자가 누른 재구성은 "실행 환경을 다시 구성하고 있습니다." 취소·실패 후 재시도·앱 재시작에도 원인이 유지돼야 한다. 테스트(통합 테스트의 기존 단언 수정 포함).
3. **재구성 중 앱 종료**: 이전 사이드카 stop 약속을 모듈 변수로 들고 `before-quit`에서 함께 기다린다.
4. **묵은 사이드카 상태**: `onState` 콜백에서 현재 `sidecar`가 아닌 매니저의 상태는 무시.
5. **도달 불가 분기 정리**: `runtimeConfig.ts`의 `phase === 'install' && missingUv` 분기 — 실제로 도달하지 않으면 지우고 테스트도 맞춘다(도달 경로가 있으면 주석으로 근거).
6. **재구성 버튼 중복 클릭**: 요청 중 비활성화.
7. **README**: 앱 패키징 절에 "실행 환경 다시 구성"(무엇을 지우고 다시 하는지)과 `runtime/.runtime-update.json` 표식 한 줄.
