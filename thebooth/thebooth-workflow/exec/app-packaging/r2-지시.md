## 요구사항

### 1. 실행 환경 위치 (사용자 데이터 비우면 처음부터 다시 되는 구조)
- 모든 경로는 r1의 `dataRoot()`(platformdirs `user_data_path` 대응) 기준. 캐시용으로 platformdirs `user_cache_path("thebooth", appauthor=False)` 대응 함수도 같은 방식으로 추가(macOS `~/Library/Caches/thebooth`, Windows `%LOCALAPPDATA%\thebooth\Cache` — 설치된 platformdirs 4.14.5 실제 동작에 맞춰 확인, 테스트).
  - 가상환경: `<dataRoot>/runtime/venv` (`UV_PROJECT_ENVIRONMENT`)
  - uv가 받는 Python: `<dataRoot>/runtime/python` (`UV_PYTHON_INSTALL_DIR`)
  - uv 캐시: `<cacheRoot>/uv` (`UV_CACHE_DIR`)
  - 상태 기록: `<dataRoot>/runtime/state.json`
- **앱 번들(`process.resourcesPath`) 안에는 아무것도 쓰지 않는다.** 앱 리소스의 `python/`을 `<dataRoot>/runtime/project`로 복사해(임시 폴더에 복사 후 교체) 거기서 동기화하는 방식을 권장한다. 다른 방식이면 번들에 쓰지 않음을 테스트로 보이고 이유를 보고.
- 사용자의 uv 설정·환경이 끼어들지 않게: `UV_NO_CONFIG=1`, `--managed-python`(시스템 Python 사용 안 함), `--python 3.12`, `VIRTUAL_ENV`·`PYTHONPATH`·`PYTHONHOME`·`CONDA_PREFIX`·`UV_*`(우리가 넣는 것 제외) 제거.

### 2. 동기화
- 명령: 앱 동봉 uv(`<resourcesPath>/uv/uv` 또는 `uv.exe`)로 `uv sync --frozen --no-dev --managed-python --python 3.12 --no-editable --project <runtime/project>` (+ Windows는 아래 extra). `--no-editable`로 thebooth 패키지 자체를 가상환경에 설치한다.
- `state.json`(형식 버전 포함)에 `uv.lock` sha256, Python 리소스 전체 해시(소스 변경 시 재설치 — 앱 업데이트 대응), uv 버전, 변형(`default`/`cpu`/`cu132`), 완료 시각을 **성공 후에만** 원자적으로 쓴다. 앱 시작 시 기록과 현재 값이 다르거나 가상환경의 `thebooth` 실행 파일이 없으면 다시 동기화한다. 같으면 바로 사이드카를 띄운다.
- 사이드카 실행: 가상환경의 실행 파일 직접(macOS `<venv>/bin/thebooth`, Windows `<venv>\Scripts\thebooth.exe`) `serve --port 0`, cwd는 `<dataRoot>/runtime`. 개발 모드는 지금처럼 레포 루트 `uv run thebooth serve`(변경 없음).
- 패키징 모드 사이드카 시작 제한 시간은 첫 실행 import가 느릴 수 있으니 개발 모드보다 넉넉하게(예: 120초).

### 3. Windows CUDA 선택 (macOS에는 영향 없어야 함)
- 메인 실측: PyPI torch 2.15.0(현재 lock). `download.pytorch.org/whl/cu132`에 `torch-2.15.0+cu132-cp312-cp312-win_amd64`가 있고, `whl/cpu`에 `2.15.0+cpu`가 있다. cu128·cu130은 2.15 빌드가 없다. torchaudio는 CUDA 인덱스에 2.11까지만 있어 **torchaudio는 PyPI 그대로** 둔다.
- `pyproject.toml`에 uv 공식 방식의 충돌 extras: `[project.optional-dependencies] cpu = ["torch==2.15.0"]`, `cu132 = ["torch==2.15.0"]`(버전은 현재 lock과 같게), `[tool.uv] conflicts = [[{extra="cpu"},{extra="cu132"}]]`, `[tool.uv.sources] torch`를 extra별·`sys_platform == 'win32'` 마커로 `pytorch-cpu`·`pytorch-cu132` 인덱스(`explicit = true`)에 연결. `uv lock`으로 갱신.
  - **macOS arm64 해석이 바뀌지 않음**을 확인: lock 전후 macOS용 torch가 PyPI 2.15.0 그대로, `uv sync`(개발, extra 없음) 결과 패키지 목록 동일. 기존 개발 흐름(`uv run thebooth ...`, 게이트) 그대로 통과.
  - Windows extra 없이 `uv sync`(CLI 개발용)는 지금처럼 PyPI torch(CPU) — 동작 유지.
- 앱(Windows)은 변형을 고른다: `nvidia-smi`(타임아웃 5초)를 실행해 출력의 `CUDA Version: X.Y`가 **13.2 이상이면 `cu132`, 아니면(없음·실패·낮음) `cpu`**. 판단은 `electron` import 없는 순수 함수(출력 문자열 → 변형)로 두고 단위 테스트. macOS는 항상 `default`(extra 없음). 변형이 기록과 다르면 다시 동기화.
- 화면에 고른 변형을 사람 말로 표시(예: "NVIDIA GPU(CUDA 13.2) 사용", "CPU 사용 — NVIDIA 드라이버가 CUDA 13.2를 지원하지 않거나 GPU가 없습니다"). macOS는 "Apple Silicon(MPS)" 정도.
- 이 맥에서는 Windows를 실행할 수 없다. Windows 경로는 단위 테스트와 `uv lock`·`uv export`/`uv pip compile` 류로 Windows 해석 결과(cu132 extra 선택 시 torch가 cu132 인덱스에서 오는지)를 확인할 수 있는 만큼 확인하고, 실행은 미검증으로 보고.

### 4. 진행·실패·재시도·취소 (준비 화면)
- 메인 프로세스에 실행 환경 상태를 두고 IPC로 화면에 보낸다(기존 `sidecar:*`와 같은 방식, `assertRenderer` 검사 동일). 예시 상태: `checking`, `syncing`(단계: 파일 준비 / Python·패키지 설치), `ready`, `failed`(한국어 한 줄 + 로그 끝 N줄), `cancelled`. 개발 모드는 항상 `ready`(개발 모드 표시).
- 진행률: **uv의 사람용 출력을 파싱해 퍼센트를 만들지 않는다**(2a 교훈: 화면이 문구를 추측하면 깨진다). 단계 + 경과 시간 + 불확정 진행 표시 + 접을 수 있는 "자세히"(uv 출력 마지막 20줄 정도)로 보여준다.
- 첫 실행이면 앱이 열리자마자 자동으로 시작한다. 처음 한 번 큰 다운로드(수백 MB, Windows NVIDIA는 수 GB)가 있다는 안내를 같이 보여준다. 앱 업데이트로 다시 맞출 때는 "앱이 바뀌어 실행 환경을 다시 맞추는 중" 류 안내.
- 취소: uv 프로세스 트리 종료(r1·2a의 트리 종료 함수 재사용, Windows `taskkill /T /F`) → `cancelled` + "다시 시작" 버튼. 실패: 원인 한 줄 + 로그 + "다시 시도". 이미 받은 것은 uv 캐시에 남아 다시 시도가 빨라야 한다.
- 동기화 중 앱을 종료하면 uv 트리를 정리하고 종료(기존 `before-quit` 흐름에 합류). 동시에 두 번 돌지 않게.
- 화면:
  - 준비 화면 맨 위에 "실행 환경" 구역. 그 아래 모델 목록은 사이드카가 준비된 뒤에만(지금 동작 유지).
  - 실행 환경이 준비되지 않았으면 앱을 준비 탭으로 연다. 만들기 탭은 "준비 화면에서 실행 환경 구성을 먼저 마치세요" 안내만 보여준다.
  - 기존 상단 엔진 상태 표시(`EngineStatus`)와 겹치지 않게 정리. 사용자에게 보이는 문구는 전부 한국어, 존댓말 체로 기존 화면과 통일.
- r1의 임시 문구("실행 환경 구성은 아직 지원하지 않습니다")는 없앤다.
