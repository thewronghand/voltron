# r2 — 리뷰 지적 + 메인 실측(박스 폭) 반영

같은 레포·브랜치, 누적 미커밋 변경 위에서.

## 메인 실측: 박스가 글자보다 훨씬 넓다 (최우선)
폭탄마 전곡 1080p·4:3 합성 배경·박스 60%로 실제 렌더해 프레임을 봤다. 위 블록(an7) 박스가 글자 끝보다 오른쪽으로 약 400px, 아래 블록(an9) 박스가 글자 시작보다 왼쪽으로 약 500px 더 나간다. 원인: 박스 폭에 `_fit_font`의 폭 계수(전각 1.0·그 외 0.55·공백 0.3 × 글자 크기)를 그대로 썼는데, libass에서 ASS 글자 크기는 em이 아니라 줄 높이 기준이라 실제 글자 진행폭이 그보다 작다(측정: 일본어 1080p 81px 줄 15.3자 ≈ 860px, 추정 ≈ 1180px — 약 0.73배. 한글 발음 줄도 비슷).
- **`_fit_font`(축소 판단)는 건드리지 않는다** — 기본 경로 바이트가 바뀐다. 박스 폭 전용 추정을 따로 둔다.
- 이 Mac의 설치 ffmpeg(libass)로 macOS 기본 글꼴(Hiragino Sans, Apple SD Gothic Neo — `subtitles.fonts()`)의 글자 종류별(전각 한자·가나, 한글, 반각 영숫자·기호, 공백) 실제 진행폭 비율을 **측정해서** 상수로 정한다. 측정 방법(예: 투명 배경에 줄 하나씩 렌더해 글자 영역 bbox를 재는 스크립트)은 `tests/` 밖 개발용 스크립트로 레포에 남기지 말고 보고에 방법과 수치만 적는다. 스타일 Spacing·외곽선·`\fs` 축소를 반영한다.
- Windows 글꼴(Yu Gothic, Malgun Gothic)은 측정할 수 없으니 macOS 값에 여유를 더한 보수적 값을 쓰거나 같은 값을 쓰되, 어느 쪽인지와 이유를 코드 주석·보고에 남긴다(미검증 표시).
- 결과 기준: 박스 좌우 여백이 글자 실제 끝에서 720p 기준 약 24px(1080은 비례) 안팎으로 보이고, 가장 긴 줄이 박스 밖으로 나가지 않는다. 실제 렌더로 확인할 수 있는 테스트(설치 ffmpeg가 있을 때만, 합성 가사 문자열로)를 추가한다: 박스 영역 밖에 글자 픽셀이 없고, 박스 오른쪽(왼쪽) 끝과 글자 끝 사이 여백이 정해진 범위 안.

## 리뷰 지적
1. **[HIGH] JPEG 배경이면 MP4가 full range(`yuvj420p(pc)`)로 나온다** (메인 재현 확인): 필터 체인에서 tv range로 변환(`scale=...:out_range=tv` 등)해 결과가 항상 `yuv420p`(limited)가 되게. 실제 ffmpeg 테스트에 JPEG 배경 결과가 `pc` 범위가 아님을 단언(ffmpeg 출력의 스트림 정보 파싱).
2. **[MEDIUM] `video` 명령이 Aegisub에서 고친 박스를 덮어씀**: ASS에 BOX 스타일·이벤트가 이미 있으면, `--box`/`--no-box`/`--box-opacity`를 **명시했을 때만** 바꾼다. 생략하면 손대지 않는다. ASS에 BOX가 없고 옵션도 생략하면 지금 규칙(배경 유무). README에 규칙 명시. 테스트.
3. **[MEDIUM] 불투명도 숫자 칸이 키 입력마다 10~100으로 보정돼 "50"을 칠 수 없음** (`ExportForm.tsx`): 입력 중엔 문자열로 두고 blur/Enter에서 보정, 슬라이더와 동기화. 테스트.
4. **[MEDIUM] 이미지 배경 렌더가 단색보다 약 8배 느림**(프레임마다 디코딩·스케일): 한 번 스케일한 프레임을 반복하도록 바꾼다(예: `-loop 1 -framerate 1` 또는 단일 프레임 입력 + `loop`/`fps=30` 필터 — 결과 길이·프레임 수·30fps·시작 시각이 지금과 같아야 함). 전후 렌더 시간을 실측해 보고. 단색 경로는 바이트 동일 유지.
5. LOW: BOX 판별을 Style 필드로(`split(",", 9)[3]`), BOX 스타일 삽입 위치를 `[V4+ Styles]` 섹션의 마지막 Style 줄 뒤로, 출력 경로가 배경 이미지와 같을 때의 오류 문구, `make`에서 `--video` 없이 `--background`/`--box`/`--box-opacity`/`--resolution`을 주면 기존 `--lyrics` 규칙과 같게 처리(지금 `--lyrics`가 경고인지 거부인지 코드 확인 후 같은 방식), `--background` 파일 이름의 `%d` 해석 방지(`-pattern_type none` 등), 배경 이미지 저장 시 내용이 이미지인지 간단히 확인(설치 ffmpeg가 있으면 한 프레임 디코딩, 없으면 매직 바이트로 jpg/png/webp 판별 — 실패하면 400 한국어), `pipeline.write_subtitles`의 의미 없는 분기 정리.
