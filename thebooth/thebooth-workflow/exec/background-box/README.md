## 메인 결정 (사용자 승인 방향 안에서)
- 1080p 비례는 ASS `PlayRes`를 영상 해상도와 같게 쓰고 모든 크기·좌표를 1.5배 — Aegisub에서 스크립트·영상 해상도가 같아 재조정 안내가 없게.
- 배경 이미지는 곡 단위(곡 폴더에 복사). 내보내기 설정은 `resolution`·`box`(null=배경 유무 따름)·`box_opacity`(기본 60).

## 메인이 실측한 것
- r1 후 게이트 8종 EXIT=0, CLI 기본 경로(720p·박스 없음·단색) 폭탄마 세 조합 바이트 동일.
- 폭탄마 전곡 1080p·4:3 합성 배경(ffmpeg `gradients`+`drawgrid`)·박스 60% 실제 렌더: 1920×1080 30fps, PlayRes 1920×1080, 배경 cover 자르기(격자 정사각형 유지)·어둡게 안 함, 박스는 블록마다 하나·글자 아래. **박스 폭이 과대** — `_fit_font` 폭 계수를 그대로 써서 실제 글자 폭의 약 1.4배(libass의 ASS 글자 크기는 em이 아니라 줄 높이 기준). → r2.
- r1 리뷰 HIGH(JPEG 배경 → `yuvj420p(pc)`) 메인 재현: 같은 필터 체인에서 PNG는 `yuv420p`, JPEG는 `yuvj420p(pc, bt470bg)`.
- 실측 프레임은 가사가 보이므로 스크래치에만 두고 기록에 넣지 않는다.
- r2 후: 게이트 8종 EXIT=0, CLI 기본 경로 바이트 동일. 폭탄마 1080p·JPEG 배경 실제 렌더 21초(전곡), `yuv420p(tv)`, 박스가 글자에 맞음(1080p 기준 좌우 여백 약 36~46px).
- 실제 앱(`e2e/background.mjs`, 1단계 launch 재사용): MP4 미선택 시 배경·박스·해상도 비활성 안내 → MP4 선택 → 3:4 합성 JPEG 배경 지정 시 자막 박스 기본값이 꺼짐→켬으로 바뀜 → 1920×1080 선택 → 내보내기 19초 → 결과 1920×1080 30fps `yuv420p(tv)`, 세로 이미지가 16:9로 가운데 잘림. 스크린샷 `screens/`(가사 없는 화면만).
- r4: 사용자가 사용량 초기화 전에 속도를 내자며 메인 직접 진행을 요청 → Codex를 멈춤. 이미 r4 항목이 반영되고 pytest까지 통과한 상태라 버리지 않고 메인이 검증: 게이트 8종 EXIT=0, CLI 기본 경로 바이트 동일, 리뷰어 재현 스크립트(exp1·exp3)에서 블록을 옮겨도 BOX 6개 유지, 폭 계수 분기를 r3로 되돌리는 변이에서 실제 렌더 테스트 10개 실패, 1·2단계 E2E 통과, 삭제류 버튼 아이콘(배경 지우기·곡 삭제 `Trash2`, 칩 `X`) 화면 확인.
- 렌더 시간: r4 후 1080p·JPEG 배경 전곡 64초(r2 직후 21초). ASS가 r2와 바이트 동일하고 명령도 같으며, 측정 중 다른 세션의 vitest·headless 브라우저가 CPU 300%대를 쓰고 있었다 → 코드 회귀가 아니라 외부 부하로 판단.
- 사용자 보고 "스크롤이 끝까지 안 내려감": E2E가 760px 창에 뷰포트만 900px로 강제(`setViewportSize`)해 아래 140px가 닿지 않던 것(사용자가 본 창은 E2E 창). 앱 셸 문제 아님. `launch.mjs`를 창 크기 변경(`setContentSize`)으로 고치고 3000px 채운 페이지에서 끝까지 스크롤됨 확인.
- 남은 것: Windows 실기(글꼴 폭 계수 0.725 미검증 포함), 반주기 재생, 리뷰 LOW 2건(보류).
