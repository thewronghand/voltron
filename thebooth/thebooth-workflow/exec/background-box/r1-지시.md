## 사용자 결정 (바꾸지 않는다)
- **배경 이미지**: 단색 대신 사용자 이미지. 16:9가 아니면 **화면을 채우도록 잘라낸다**(cover: 비율 유지 확대 후 가운데 자르기). **이미지를 어둡게 하지 않는다.** 동영상 배경은 넣지 않는다.
- **자막 배경 박스**: 세 줄 블록(일본어·발음·번역) 뒤에 **둥근 사각형 하나**를 ASS 드로잉(`{\p1}` 벡터)으로 따로 그린다. ASS 기본 박스(`BorderStyle: 3`)는 쓰지 않는다(줄마다 폭이 달라 계단처럼 보이고 글자 외곽선을 못 씀). 폭은 기존 글자 폭 추정(`_fit_font`의 폭 계수)을 재사용하고 여백을 넉넉히. 옵션: 박스 켬/끔, 불투명도(기본 60%). **기본값: 배경 이미지가 있으면 켬, 단색이면 끔.**
- **해상도**: 1280×720에 1920×1080 선택지 추가. 글자 크기·위치·외곽선·그림자·박스가 해상도에 비례해야 한다.
- 결과 ASS는 Aegisub로 열어 고칠 수 있어야 한다(표준 ASS만, 박스는 별도 이벤트·스타일로 구분돼 사용자가 지우거나 고칠 수 있게).

## 메인이 정한 설계
1. **해상도 비례는 ASS 좌표계로**: ASS `PlayResX/PlayResY`를 영상 해상도와 같게 쓰고(1080이면 1920×1080), 글자 크기·`\pos`·여백·외곽선·그림자·`_fit_font`의 폭 한계(1120)·박스 좌표를 같은 비율(1.5)로 곱한다. Aegisub에서 스크립트 해상도와 영상 해상도가 같아 다시 맞추라는 안내가 뜨지 않게 하려는 것이다. 정수 좌표가 필요한 곳은 반올림 규칙을 하나로.
2. **720p·박스 끔·배경 없음의 기본 경로는 지금과 바이트가 같아야 한다**(ASS 텍스트와 MP4). CLI `make`·곡 내보내기 모두. 메인이 폭탄마로 전후 sha256을 비교한다.
3. **박스 이벤트**: 블록마다 `Dialogue` 하나, 같은 표시 시간, 전용 스타일(예: `BOX`, 검정, 외곽선·그림자 0), 레이어는 글자보다 아래(텍스트 이벤트보다 먼저 그려지게 레이어 번호로 보장 — 순서에만 기대지 않는다). 불투명도는 ASS 알파(`&HAA` 형식, 00이 불투명)로 변환, 반올림 규칙 명시. 모서리 반지름은 해상도 비례 상수. 박스 높이는 실제 있는 줄(발음·번역이 없는 블록 포함)에 맞춘다. 위 블록(왼쪽 정렬)과 아래 블록(오른쪽 정렬) 각각의 앵커에 맞춰 위치. 화면 밖으로 나가지 않게 자른다.
4. **배경 이미지는 곡 단위**로 저장한다: 곡 폴더 `background.<원래 확장자 소문자>` 복사본(jpg·jpeg·png·webp만, 대소문자 무시, 그 밖은 400 한국어). song.json에 배경 정보(원래 파일 이름 등)를 넣고 형식 버전 처리를 기존 규칙대로(옛 곡은 배경 없음으로 읽힘). 설정·교체·지우기 API(`PUT /songs/{id}/background` `{image_path}`, `DELETE /songs/{id}/background`), 진행 중 작업이 있으면 409. 쓰기는 기존 원자적 쓰기 규칙.
5. **내보내기 설정 추가**: `resolution`(`"1280x720"`|`"1920x1080"`, 기본 1280x720), `box`(bool, 요청에서 생략하면 "배경 이미지 있음"이면 켬), `box_opacity`(10~100 정수 %, 기본 60). `export_defaults`에 저장. MP4가 없는 내보내기에서는 무시. 결과 파일 이름 규칙은 그대로(해상도는 이름에 넣지 않는다).
6. **렌더(`video.render`)**: 배경 이미지가 있으면 `-loop 1 -framerate 30 -i <이미지>`로 넣고 `scale=W:H:force_original_aspect_ratio=increase,crop=W:H,setsar=1` 후 `ass` 필터. 길이는 오디오 길이에 맞춘다(지금 color 소스의 `d=` 방식과 같은 결과 길이). 밝기·색 보정 없음. 픽셀 형식·코덱·`-level 4.0` 등 나머지는 그대로(H.264 High@4.0은 1080p30을 지원). **JPEG EXIF 회전**: 휴대폰 사진(Orientation 6 등)이 옆으로 눕지 않는지 이 ffmpeg(manifest의 9.0.2 정적 빌드, 없으면 `THEBOOTH_FFMPEG`)로 실측하고, 안 되면 처리 방법을 보고(의존성 추가 금지 — 필요하면 멈추고 보고).
7. **CLI**: `make`와 `video` 명령에 `--background 이미지`, `--box/--no-box`, `--box-opacity`, `--resolution 1280x720|1920x1080` 추가(기본값은 지금 동작 그대로 — 박스 기본은 배경 유무 규칙). `video` 명령은 편집한 ASS를 다시 렌더하는 용도라 ASS의 PlayRes와 `--resolution`이 다르면 한국어로 거부.
8. **앱 화면**(곡 상세 → 내보내기 영역): 
   - "배경" 묶음: 현재 배경 이미지(파일 이름 + 작은 미리보기 — 렌더러가 로컬 파일을 직접 읽지 못하면 main이 곡 id만 받아 곡 폴더의 배경 파일을 data URL 등으로 돌려주는 IPC를 둔다, 임의 경로 금지), '이미지 선택'/'바꾸기'/'지우기'. 이미지 없으면 "단색 배경" 표시.
   - "자막 박스" 켬/끔 + 불투명도(슬라이더 + 숫자, %). 사용자가 직접 건드리기 전에는 배경 유무를 따라 기본값이 바뀐다.
   - "해상도" Select: 1280×720 / 1920×1080(1920×1080 옆에 "TJ 이동식 M1·M2 화면" 정도의 짧은 도움말).
   - 위 셋은 MP4를 고르지 않으면 비활성(이유 한 줄).
   - 문구 전부 한국어.

## 검증·테스트
- Python: ASS 생성 — 720 기본 경로 문자열이 기존과 동일(골든 비교), 1080 비례(크기·좌표·외곽선·폭 한계 1.5배), 박스 이벤트(개수=블록 수, 레이어가 글자보다 아래, 알파 변환, 줄 수에 따른 높이, 화면 밖 자르기), 박스 끔이면 박스 없음. 렌더 명령 — 배경 유무·해상도별 ffmpeg 인자(`fake_ffmpeg.py` 방식). 곡 보관함 — 배경 설정·교체·지우기·확장자 거부·409·옛 song.json 호환·export_defaults 저장. CLI — 새 옵션과 `video`의 해상도 불일치 거부.
- 실제 ffmpeg가 있으면(manifest 설치본) 짧은 합성 오디오 + 합성 이미지(예: ffmpeg `testsrc2`로 만든 4:3·9:16 PNG, EXIF 회전 JPEG)로 1080 렌더를 실제로 해서 결과 해상도·길이를 `ffprobe` 대신 이 ffmpeg로 확인하는 테스트(없으면 skip). 음원·사진 파일을 레포에 넣지 않는다(테스트 안에서 만든다).
- 앱 vitest: 내보내기 요청 본문(해상도·박스·불투명도 기본값과 배경 유무 연동), MP4 미선택 시 비활성, 배경 IPC id 검증.
