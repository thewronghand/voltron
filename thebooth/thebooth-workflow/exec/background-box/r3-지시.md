# r3 — r2 리뷰 지적 반영 (편집한 ASS 견고성 중심)

같은 레포·브랜치, 누적 미커밋 변경 위에서. 720p·박스 없음·단색 기본 경로 바이트 불변 유지.

1. **[MEDIUM] 암묵적 박스가 렌더를 막음** (`subtitles.py` 편집 ASS에 박스 붙이기): 박스가 기본값으로 켜진 경우(배경 있음·`--box` 생략·ASS에 BOX 없음) 위치를 읽을 수 없는 이벤트(`\pos` 없음, `\an7`/`\an9` 아님, 음수 좌표 등)가 있으면 그 블록만 박스를 건너뛰고 경고(몇 줄 건너뛰었는지 한국어 한 줄)한다. 거부(exit 2)는 `--box`를 명시했을 때만. 위치 정규식이 음수·소수를 받게. 테스트.
2. **[MEDIUM] 박스 묶음 키가 `(Start, End, an, x)` 정확 비교**: 편집으로 한 줄의 시간·위치가 조금 바뀌면 그 줄만 따로 묶여 겹친 박스(진해짐)가 생긴다. JP 줄을 기준으로 같은 앵커이고 시간이 겹치며 세로로 가까운(정해진 범위 안) PRON·TRANS 줄을 붙이는 방식으로 바꾼다. 같은 시간대에 박스가 겹치지 않는지 테스트(시간 몇 cs·x 몇 px 바꾼 경우 포함). README의 해당 설명 갱신.
3. LOW 반영:
   - 반각 가나(`east_asian_width == "H"`)와 Latin-1 등 ASCII 표 밖 반각 문자의 박스 폭 계수를 반각 기본값으로(전각 0.725 적용 금지). 넘치지 않는지는 기존 실제 렌더 테스트 방식으로.
   - Windows 글꼴에 같은 계수를 쓰는 이유를 주석에(libass는 글꼴 줄 높이 기준이라 비율이 글꼴마다 다를 수 있음, Windows 실측 전까지 미검증) — README의 미검증 목록에도 한 줄.
   - 편집 ASS에 넣는 BOX 스타일 글꼴을 `generate`와 같게(`subtitles.fonts()`의 일본어 글꼴).
   - `video` 명령: ASS에 BOX가 없고 박스도 꺼질 때 `--box-opacity`만 주면 무시된다는 안내. PlayRes가 없는 ASS는 libass 기본(PlayRes 없음 → 384×288이 아니라 실제 동작 확인)에 맞춰 720p로 렌더할 때는 예전처럼 허용하고 1080p만 거부할지 판단해 보고(이전 `video` 동작과의 호환을 우선).
   - CLI `make`: `validate_make`에서 배경 이미지 내용 검사(`validate_image_content`)를 해서 분리·정렬 전에 실패하게. 서버의 배경 PUT은 ffmpeg 디코딩을 `song_library.lock` 밖에서 하고(임시 사본 검증 후 락 안에서 교체), 락 안에서는 파일 교체와 song.json 저장만.
   - 앱: `exportForm.test.tsx`에 불투명도 입력→blur→내보내기 요청 본문 경로 테스트, 배경 미리보기 effect 의존성을 `song.background?.filename`·`original_name`으로(같은 배경을 매번 다시 읽지 않게).
   - 색 범위 테스트가 PNG 배경에서도 limited 범위를 실제로 확인하게(표시 문자열이 아니라 평평한 흑·백 영역 휘도 16/235 같은 데이터 기준, 설치 ffmpeg로).
