# r4: 사용자 결정 반영 + 렌더 결정성

r3 이후 호출 세션은 코드를 고치지 않았다.

## 1. 사전 검사 메시지에 입력값 포함 (사용자 결정)
- 사용자 결정: 사전 검사 실패는 지금처럼 **종료 코드 2**, 옵션 이름을 넣지 않는 **공용 문구**(CLI·앱 공유)를 유지한다. "보컬 분리 중..." 안내 줄도 유지한다.
- 다만 r2에서 문구를 바꾸며 사용자가 넣은 값이 메시지에서 빠졌다. 다시 넣는다.
  - MR 방식: `MR 방식은 stems 또는 subtract여야 합니다: <입력값>`
  - 음높이 추출기: `음높이 추출기는 fcpe 또는 rmvpe여야 합니다: <입력값>`
  - 같은 종류의 "허용값 중 하나여야 함" 검사(남/여 전환 값 등)가 있으면 같은 형식으로 맞춘다.
- 넣는 값은 옵션 값뿐이다. 가사·파일 내용은 넣지 않는다. 값이 길면 40자에서 자른다.
- 테스트: 위 메시지에 입력값이 들어가는지(CLI·서버 400 응답 둘 다).

## 2. 렌더 결정성 (video.py)
- 실측한 문제: 같은 ASS·오디오를 두 번 렌더하면 공통 프레임은 전부 같은데 **맨 끝 프레임 수가 실행마다 다르다**(6501·6505·6507). 배경(`lavfi color`)이 끝이 없는 입력이라 `-shortest`의 종료 시점이 흔들린다. 이 변경 이전(main)에도 같은 문제였다.
- 정책: 영상 길이를 **오디오 길이로 명시**한다.
  - 오디오 길이는 pedalboard `AudioFile`의 `frames / samplerate`로 읽는다(ffprobe 불필요).
  - 배경 입력에 `d=<길이>`(또는 출력에 `-t <길이>`)를 주어 프레임 수가 `ceil(길이 × 30)`으로 고정되게 한다. `-shortest`는 뺀다.
  - 진행률 계산에 쓰던 총 길이도 같은 값을 쓴다.
- 결과: 같은 입력이면 MP4가 **바이트 단위로 같아야** 한다. 기존 산출물과 영상 프레임 내용은 같고 끝 프레임 수만 고정된다.
- 테스트:
  - 명령 인자에 길이가 들어가고 `-shortest`가 없는지.
  - slow(실제 ffmpeg): 같은 ASS·오디오를 두 번 렌더해 두 파일의 바이트가 같은지, 영상 프레임 수가 `ceil(길이 × 30)`인지.
