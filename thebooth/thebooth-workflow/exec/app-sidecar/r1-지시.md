## 구현 범위

### 1. 진행 보고 추상화 (`src/thebooth/progress.py`)
- 지금 진행 표시는 흩어진 `print(..., file=sys.stderr)`와 demucs tqdm이다. 이를 **진행 보고 객체**로 모은다.
- 인터페이스(작게 유지):
  - `stage(name: str, total: int | None = None)`: 새 단계 시작. `total`이 None이면 진행률을 모르는 단계다.
  - `advance(done: int)`: 현재 단계의 누적 완료량.
  - `message(text: str)`: 사용자에게 보일 한 줄 안내.
  - `check_cancelled()`: 취소됐으면 `JobCancelled` 예외를 낸다.
- 단계 이름은 고정 식별자를 쓴다: `load`, `separate`, `pitch`, `align`, `render`, `write`, `download`. 화면이 이 이름으로 한국어 라벨을 붙인다.
- 기본 구현:
  - `NullProgress`: 아무것도 안 함, 취소 없음.
  - `ConsoleProgress`: 지금 CLI가 stderr에 내는 것과 같은 수준의 출력. CLI 출력 형식은 크게 바꾸지 않는다.
- `pipeline.make`와 분리기·추출기·정렬·렌더 경로가 이 객체를 받게 한다(키워드 인자 `progress`, 기본 `NullProgress`). CLI는 `ConsoleProgress`를 넘긴다.
  - RoFormer는 구간(chunk)마다 `advance`·`check_cancelled`를 부른다.
  - demucs는 `apply_model`이 콜백을 받지 않으니 진행률 없는 단계로 둔다. 단계 전후에만 취소를 확인한다.
  - 정렬은 진행률 없는 단계다.
  - 렌더는 ffmpeg를 `-progress pipe:1`로 실행해 `out_time_us`를 읽고, 곡 길이 대비 진행률을 보고한다. 파싱이 안 되면 진행률 없는 단계로 떨어진다. 취소되면 ffmpeg 프로세스를 terminate하고 임시 출력을 지운다.
  - 모델 받기는 바이트 단위 `advance`와 취소를 지원한다. 취소 시 `.part`를 남겨 이어받기가 되게 한다.
- 기존 `pipeline.make`를 호출하는 테스트·CLI 동작은 바뀌지 않아야 한다.

### 2. 작업 대기열 (`src/thebooth/jobs.py`)
- 단일 작업자 스레드 + FIFO 큐. 한 번에 한 작업만 실행한다(GPU·메모리 경쟁 방지).
- 작업 종류는 `make`(pipeline.make 한 번)와 `pull`(모델 받기) 두 가지다.
- 작업 상태: `queued` → `running` → `done` | `failed` | `cancelled`. 작업마다 id(uuid4 hex), 종류, 생성 시각, 현재 단계, 진행률(0~1 또는 None), 마지막 메시지, 결과(경로 등), 오류 메시지를 둔다.
- 이벤트: 상태가 바뀌거나 진행이 오르면 작업별 이벤트를 쌓는다. SSE 구독자가 `Last-Event-ID` 이후부터 다시 받을 수 있게 작업별로 순번을 매긴다. 메모리 상한(작업당 최근 1000개)을 둔다. 진행 이벤트는 같은 단계에서 1% 미만 변화면 합쳐도 된다.
- 취소:
  - 대기 중이면 즉시 `cancelled`.
  - 실행 중이면 취소 플래그를 세운다. 진행 객체의 `check_cancelled`가 `JobCancelled`를 내면 `cancelled`로 끝낸다.
- 실패 메시지는 CLI가 사용자에게 보여주는 한 줄과 같은 수준이다(가사 내용 금지). 예상하지 못한 예외는 "내부 오류(<예외 클래스 이름>)"로만 알리고, 서버 로그(stderr)에는 traceback을 남긴다.
- 서버 종료 시 실행 중 작업에 취소를 걸고, 작업자 스레드를 잠깐(5초) 기다린다.

### 3. HTTP 서버 (`src/thebooth/server.py`, `thebooth serve`)
- 의존성: `fastapi`, `uvicorn`(버전 고정은 lock으로). SSE는 별도 패키지 없이 `StreamingResponse(text/event-stream)`로 구현한다.
- 실행: `thebooth serve [--port 0]`.
  - **127.0.0.1에만 바인딩**한다.
  - 포트 0이면 OS가 고른다. 소켓을 직접 만들어 바인딩한 뒤 uvicorn에 넘기는 방식으로, 실제 포트를 확정한다.
  - 준비가 끝나면 **stdout에 JSON 한 줄** `{"event": "ready", "port": <포트>, "version": "<패키지 버전>"}`을 쓰고 flush한다. 그 밖의 로그는 stderr로만 보낸다. 앱이 stdout 첫 줄로 포트를 알아내기 때문이다.
- **인증**:
  - 환경변수 `THEBOOTH_TOKEN`이 필수다(없거나 32자 미만이면 시작을 거부하고 exit 2).
  - 모든 요청은 `Authorization: Bearer <토큰>`이 있어야 한다. SSE는 브라우저 `EventSource`가 헤더를 못 붙이니, 쿼리 `?token=`도 허용한다.
  - 비교는 `hmac.compare_digest`로 한다. 틀리면 401이다.
- **CORS**: 환경변수 `THEBOOTH_ALLOWED_ORIGINS`(쉼표 구분)에 있는 출처만 허용하고, 기본값은 허용 없음이다. `*`는 쓰지 않는다. Electron 개발 서버(`http://localhost:5173`)나 앱 출처를 앱이 넘겨준다.
- **엔드포인트** (JSON, 오류는 `{"error": "<한 줄>"}` + 적절한 상태 코드):
  - `GET /health` → `{"ok": true, "version": ...}`
  - `GET /models` → manifest 목록: id·arch·purpose·description·license·크기·설치 여부·이 플랫폼 지원 여부.
  - `POST /models/{id}/pull` → 작업 생성, `{"job_id": ...}` (202). 모르는 id면 404, 미지원 플랫폼이면 400.
  - `POST /jobs/make` → 본문은 `pipeline.make`의 옵션과 1:1이다: 입력 경로, MR 출력 경로, 키 단계, 남/여 전환(`m2f`·`f2m`·null), 보컬 출력, MR 방식, 분리 모델, 가이드 on/off·음량·추출기, 가사·보조 파일·언어·영상 출력. 키 합산은 `keys.total_semitones`를 쓴다.
    - **분리 전 검사**(경로 충돌, 키 범위, 모델 종류, 가사 짝짓기, 언어 코드, 모델·ffmpeg 준비)는 작업을 큐에 넣기 **전에** 동기로 실행한다. 실패하면 400으로 바로 돌려준다(CLI의 exit 2·조기 실패와 같은 정책). 지금 `pipeline.make` 안에 있는 사전 검사를 재사용할 수 있게 분리한다. 같은 검사를 두 벌 만들지 않는다.
    - 입력 파일이 없거나, 출력 확장자가 틀리면(.mp3/.mp4) 400이다.
  - `GET /jobs` → 최근 작업 목록(최대 50).
  - `GET /jobs/{id}` → 상태 스냅샷.
  - `GET /jobs/{id}/events` → SSE.
    - 이벤트 형식: `id: <순번>`, `event: <status|progress|message|done|failed|cancelled>`, `data: <JSON>`.
    - 연결 직후 현재 스냅샷을 먼저 보내고 이후 이벤트를 흘린다. 끝난 작업이면 스냅샷과 종료 이벤트를 보내고 닫는다.
    - 15초마다 `: ping` 주석을 보내 연결을 유지한다.
  - `POST /jobs/{id}/cancel` → 202. 이미 끝났으면 409.
  - `POST /shutdown` → 서버를 정상 종료한다(앱 종료용).
- 사용자 경로는 그대로 쓰지만, 서버는 받은 경로 외의 파일을 읽거나 쓰지 않는다. 디렉터리 탐색 API는 만들지 않는다.
