# r2: 요구사항 정정 + 리뷰 지적 반영

r1 이후 호출 세션은 코드를 고치지 않았다. 실곡(폭탄마)으로 변경 전후 MR·ASS·MP4가 바이트 동일함을 확인했다.

## 0. [요구사항 정정] CORS preflight는 토큰 없이 응답
- r1 지시서의 "모든 요청에 토큰"은 호출 세션의 명세 실수다. 브라우저는 preflight(OPTIONS)에 인증 헤더를 붙이지 못해서, 렌더러가 사이드카를 직접 부를 수 없게 된다.
- 정책: `OPTIONS`이면서 `Origin`이 허용 목록에 있고 `Access-Control-Request-Method`가 있으면 토큰 없이 204 + CORS 헤더로 응답한다(`Authorization` 헤더 허용 포함). 그 밖의 OPTIONS는 지금처럼 401이다. 실제 요청은 모두 토큰이 필요하다.
- 테스트(`tests/test_server.py`의 401 고정 테스트)와 README의 "main 프로세스가 HTTP를 대신 수행" 문구도 고친다. 렌더러가 직접 fetch하고, SSE는 `EventSource` + `?token=`로 받는다.
- 허용 출처에 `"null"`이 오면 `*`처럼 시작을 거부한다(file:// 렌더러는 쓰지 않는다).

## 1. 부모 프로세스 종료 감지 (server.py·video.py)
- **stdin EOF 감시**: `serve`는 stdin을 읽는 데몬 스레드를 둔다. EOF가 오면(앱이 죽거나 파이프가 닫힘) 정상 종료 절차를 밟는다(실행 중 작업 취소 → ffmpeg 종료 → 서버 종료). 앱은 stdin을 파이프로 연결해 띄운다. README에 이 계약을 적는다.
- Windows에서 앱이 사이드카를 강제 종료하면(TerminateProcess) 위 절차가 돌지 않는다. 그래서 자식 ffmpeg 정리는 앱이 프로세스 트리째 끝내야 한다. 이 내용을 README "앱과의 계약"에 적는다(다음 작업의 Electron이 그렇게 구현한다).
- ffmpeg를 띄울 때 Windows에서는 `creationflags=subprocess.CREATE_NO_WINDOW`를 준다(`video.py`·`tools.py`).

## 2. 종료·취소 가시성 (jobs.py)
- 실행 중 작업에 취소가 요청되면 즉시 `message` 이벤트("취소 요청됨 — 현재 단계가 끝나면 중단합니다")를 내고, 스냅샷에 `cancel_requested: true`를 둔다.
- 취소 확인 지점이 없는 구간(demucs 분리·음높이 추출·Whisper 정렬)을 README와 `JobQueue.shutdown` docstring에 적는다. 종료 시 5초 대기 후에는 작업자를 버리고, 그 경우 임시 파일이 남을 수 있다는 것도 함께 적는다.
- 작업자 스레드는 작업 하나가 `BaseException`으로 끝나도 죽지 않는다(`KeyboardInterrupt`·`SystemExit`은 작업 실패로 기록하고 루프를 계속한다. 종료 플래그가 섰을 때만 빠져나간다).
- 종료 중 submit은 503 `{"error": "서버가 종료 중입니다"}`로 응답한다.
- 진행 이벤트는 같은 단계에서 1% 미만 변화면 내보내지 않는다(다운로드 수천 개 방지). 단계 시작·끝과 100%는 항상 보낸다.

## 3. 쓰기 시작 후 취소 정책 (pipeline.py)
- 정책:
  - **MR·보컬 MP3 쓰기 구간은 취소를 받지 않는다**(짧다). 쓰기가 끝난 다음 확인 지점에서 취소된다.
  - 렌더는 계속 취소할 수 있다.
  - 작업이 쓰기 이후에 취소되면, **취소 이벤트와 스냅샷에 그때까지 만든 결과**(쓴 파일 경로들, `ass_backup` 경로)를 `partial`로 담는다.
- 분리 결과 캐시는 분리 직후 `check_cancelled`보다 **먼저** 저장한다(몇 분짜리 분리를 버리지 않게).
- 테스트: MP3를 쓴 뒤 취소되는 경우 `partial`에 경로가 있는지. ASS 백업 후 렌더가 취소되는 경우 `partial.ass_backup`이 있는지. 분리 직후 취소돼도 캐시가 남는지.

## 4. 검사 단일화 (cli.py)
- CLI의 확장자·`--video`/`--lyrics` 조합·언어·mr_method·pitch·모델 purpose 검사를 지우고 `pipeline.validate_make`를 한 번 부른다. `ValueError`(경로 충돌 포함)는 종료 코드 2로 바꾼다.
- CLI에는 CLI 전용 "참고:" 안내만 남긴다. 기존 CLI 테스트가 기대하는 종료 코드는 유지하고, 메시지가 바뀌는 테스트는 갱신한다.
- 서버만 `check_separator=True`인 이유("서버는 분리 캐시 여부를 입력을 읽기 전에 알 수 없어 설치를 요구한다")를 주석으로 남긴다.

## 5. CLI 출력 복원 (separate.py)
- `ConsoleProgress`일 때는 demucs `apply_model(progress=True)`를 유지해, CLI에서 htdemucs tqdm 막대가 이전처럼 보이게 한다. 서버(그 밖의 진행 객체)에서는 끈다.
- ffmpeg 실패 메시지의 stderr 줄 연결은 이전처럼 줄바꿈으로 되돌린다(작업 이벤트에는 여전히 넣지 않는다).

## 6. 경로·인증 세부 (server.py)
- `MakeRequest`의 모든 경로 필드는 **절대 경로**만 받는다. 아니면 400이다.
- Bearer 스킴 비교는 대소문자를 구분하지 않는다.
- Windows에서는 bind 전에 `SO_EXCLUSIVEADDRUSE`를 설정한다.
- README 예시 JSON을 실제 출력 형식과 맞춘다.

## 7. 테스트 보강
- 실제 서브프로세스 렌더 취소: `sys.executable`로 진행 줄을 출력하고 sleep하는 가짜 ffmpeg 스크립트를 쓴다. terminate → wait → kill 경로와 임시 파일 삭제를 확인한다.
- `serve`에 stdin을 닫으면 종료되는지. macOS·리눅스에서는 SIGTERM에도 종료되는지(Windows에서는 skip).
- 이벤트 상한을 넘긴 뒤 오래된 `Last-Event-ID`로 SSE에 재연결할 때의 동작(가능한 최신부터 받고 스냅샷을 먼저 보낸다).
- preflight: 허용 출처 + `Access-Control-Request-Method` → 204 무토큰. 비허용 출처 → 401. 실제 요청 무토큰 → 401.
