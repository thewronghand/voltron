# r6: 단계 보고를 사이드카 쪽에서 단순화 (r5 리뷰 반영)

r5의 "정렬 캐시 적중 시 두 번째 write 판별"(`makeLogic.ts`의 write 진행 이벤트 개수 세기)은 계약에 없는 `jobs.py` 내부 동작(단계 전환 때 마무리 이벤트를 한 번 더 냄, write에 advance 없음)에 기대서 깨지기 쉽다. 사이드카가 단계를 일관되게 보고하도록 바꾸고 앱의 추론을 지운다. **이번에는 아래 Python 변경을 허용한다.** 분리·가이드·키·영상 결과물은 바뀌면 안 된다.

1. **정렬 캐시 적중에도 `align` 단계 보고** (`src/thebooth/pipeline.py` 정렬 부분, 357행 부근): 영상 작업이면 정렬 캐시 적중 여부와 관계없이 `reporter.stage("align")`을 한 번 부른다. 그러면 영상 작업의 단계 순서는 항상 `… write → align → write → render`다.
   - Python 테스트: 정렬 캐시 적중 시에도 단계 순서에 `align`이 나오는지.
   - 앱: `writeProgressEvents` 같은 이벤트 개수 세기를 **지운다**. 완료 판정은 "현재 단계의 표시 위치 + 도달한 가장 먼 위치"(r4 규칙)만으로 한다. 관련 테스트를 새 순서로 고친다(정렬 캐시 적중 = write→align→write→render).
2. **단계가 바뀌면 message 비우기** (`src/thebooth/jobs.py` `_JobProgress.stage()`): 새 단계로 넘어갈 때 작업의 `message`를 `None`으로 둔다. 지난 단계 문구("음높이 추출 중…", "가사 강제 정렬 중…")가 다음 단계 내내 남는 문제. 단계 전환 뒤에 나오는 `message` 이벤트는 그대로 보인다. Python 테스트 추가.
3. README "앱용 사이드카"에 두 동작을 한 줄씩: 영상 작업은 정렬 캐시가 있어도 `align` 단계를 보고한다, `message`는 단계가 바뀌면 비워진다.
4. LOW:
   - 음원을 연달아 두 번 바꿀 때 직전 안내가 '가사·보조 파일을 비웠다'였고 아직 다시 고르지 않았다면 그 안내를 유지한다(약한 안내로 내려가지 않게).
   - "음원 파일을 이곳에 놓아 주세요" → 마침표.
