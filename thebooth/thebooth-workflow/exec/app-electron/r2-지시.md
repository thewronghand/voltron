# r2: T1 리뷰 반영 + T2 준비 화면

r1에서 만든 `app/` 위에서 이어 간다. 필독 문서·확정 결정·하지 말 것은 r1 지시서와 같다(Python 코드 수정 금지, 화면 문구 전부 한국어, `any` 금지, 폴더 밖 import는 별칭).

## A. T1 리뷰 반영

1. `sidecar.ts`: 종료가 한 번 실패하면(`stopRun` reject) `run.stopping`에 거부된 Promise가 남고 `current`도 비워지지 않아 이후 `restart()`가 영구히 실패한다. 실패한 실행은 `current`에서 떼어 내고(강제 종료를 시도한 뒤), 다음 재시작이 새로 시작될 수 있게 한다. 그 경우에도 상태는 사용자가 알 수 있게 `failed`로 둔다.
2. `jobStream.ts`: 연결이 CLOSED가 된 뒤 `GET /jobs/{id}` 복구 스냅샷이 비종료 상태(`queued`·`running`)면 다시 연결한다(무한 반복이 되지 않게 지연을 두고 횟수 상한을 둔다. 상한을 넘으면 오류 상태). 종료 상태면 그대로 끝낸다. 404면 "작업 기록을 찾을 수 없습니다" 오류 상태.
3. `main/index.ts`: `session.defaultSession`에 `setPermissionRequestHandler`·`setPermissionCheckHandler`로 권한을 기본 거부한다.
4. `sidecar.ts`: 재시작할 때 이전 실행을 멈추기 **전에** 상태를 `starting`으로 먼저 보낸다(죽어 가는 서버로 요청하지 않게).
5. 시작 제한 시간 60초는 이름 있는 상수로 두고, 개발 모드 전제(`uv run`의 첫 동기화가 길면 넘을 수 있음)를 주석 한 줄로.
6. `treeKillCommand`·`detached`가 macOS·Windows만 다룬다는 점을 주석 한 줄로(대상 OS 밖).
7. 통합 테스트: 종료 후 uv뿐 아니라 그 자식 Python 프로세스도 남지 않았는지 확인한다(macOS에서는 프로세스 그룹 id로 `process.kill(-pgid, 0)`이 `ESRCH`인지). 느린 통합 테스트는 기본 `pnpm test`에 그대로 두되, 실행 시간이 짧으면 그대로 둔다.
8. `jobStream.ts`의 별도 `subscriberCounts` Map을 없애고 스트림의 리스너 수로 센다.
9. `file:open`·`file:save` IPC 인자도 `file:show`처럼 최소 형태 검사를 한다.

## T2: 준비 화면

"준비" 탭의 자리 표시를 실제 화면으로 바꾼다. 파일은 `src/renderer/src/features/prepare/` 아래에 둔다(필요하면 `components/` 공용).

- `GET /models`로 목록을 받아 카드나 행으로 보여준다. 항목마다:
  - 이름(`id`)과 설명(`description`), 용도 라벨(`purpose` → 한국어: `vocal-separation` 보컬 분리, `pitch-extraction` 음높이 추출, `lyrics-alignment` 가사 정렬, `tool` 도구, 모르는 값이면 원문)
  - 크기(`size` 바이트 → 사람이 읽는 단위, 예: 84MB, 1.7GB. 1000 단위가 아니라 README 표와 같은 값이 나오게 맞춘다 — README는 `size/1e6` MB, 1GB 이상은 `/1e9` GB 소수 1~2자리)
  - 라이선스(`license` 원문)
  - 상태: 설치됨 / 받기 버튼 / 받는 중(진행률 막대 + 퍼센트 + 받은 양) / 대기 중 / 실패(사이드카 메시지 그대로) / 취소됨
  - `supported`가 거짓이면 받기 버튼 없이 "이 컴퓨터에서는 쓸 수 없음"만 표시한다.
- 받기: `POST /models/{id}/pull` → 받은 `job_id`를 `useJob`으로 구독한다. 진행률은 `download` 단계의 `progress`. 실행·대기 중에는 "취소" 버튼(`POST /jobs/{id}/cancel`). 취소 요청 중(`cancel_requested`)이면 버튼을 비활성화하고 "취소하는 중…"으로 표시. 취소하면 받은 부분은 이어받기로 남는다는 안내를 짧게 보인다.
- 받기가 끝나면(`done`) 목록을 다시 불러와 설치 상태를 갱신한다. `failed`·`cancelled`면 다시 받기 버튼을 보인다.
- 진행 중인 받기 작업 id는 탭을 바꿔도 사라지지 않게 App 수준(또는 작은 스토어)에 둔다. 사이드카가 재시작되면(토큰·주소가 바뀜) 이전 작업 id는 버린다.
- 사이드카가 준비 상태가 아니면 목록 대신 안내만 둔다(상단 엔진 상태가 이미 있으니 짧게).
- 목록 위에 짧은 안내: "모델은 한 번만 받으면 됩니다. 받은 모델은 CLI와 함께 씁니다." 정도. 기본 음높이 추출기 FCPE는 별도로 받을 필요가 없다는 한 줄.
- 모든 오류는 `ApiError` 메시지를 그대로 보여준다.

테스트: 크기 표기 함수, 용도 라벨, 목록/작업 상태 → 표시 상태 결정 함수(순수 함수로 분리)를 vitest로.
