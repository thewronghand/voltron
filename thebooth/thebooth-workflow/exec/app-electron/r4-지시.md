# r4: r3 리뷰 반영 + 실제 앱 실행에서 찾은 문제

필독·확정 결정·하지 말 것은 r1 지시서와 같다. 이번에는 **앱(`app/`)만** 고친다. Python은 바꾸지 않는다.

## A. 실제 실행에서 찾은 문제 (호출 세션이 실제 앱을 띄워 확인)

1. **단계 순서와 완료 표시**: 실제 pipeline 순서는 `load → separate → pitch? → write → align? → write → render?`다(`src/thebooth/pipeline.py` 279·293·313·332·360·377·383행, `video.py`). 지금 화면은 `저장`을 맨 끝에 둬서, 영상 렌더 중에 "영상 만들기: 진행 중" 아래에 "저장: 완료"가 보이고, 탭을 떠났다 돌아오면 지난 단계가 '대기'로 보일 수 있다.
   - 표시 순서를 `불러오기, 보컬 분리, 음높이 추출(가이드), 저장, 가사 정렬(영상), 영상 만들기(영상)`으로 바꾼다.
   - 완료 판정은 이력에 의존하지 않고 **현재 단계의 표시 위치**로 한다: 현재 단계보다 앞에 있는 단계는 완료. 한 번 도달한 가장 먼 위치보다 앞의 단계도 완료(정렬 뒤 두 번째 `write`가 와도 `가사 정렬`이 다시 대기로 돌아가지 않게).
   - `tests/make.test.ts`의 기존 기대(현재 align이고 이력에 write 없으면 write 대기)를 새 규칙으로 고친다.
2. **결과의 캐시 표시가 틀림**: 가이드를 켜고 새로 추출했는데 "음표 캐시: 미사용"으로 나온다. 옵션을 켰고 캐시 적중이 아니면 "새로 처리", 옵션을 끈 경우에만 "미사용"이다(음표=가이드, 정렬=영상). 결과의 `guide`·`video_output`이나 요청 옵션으로 판단한다.
3. **보조 버튼이 비활성처럼 보임**: `@thewrong/ui` `Button`의 `variant="secondary"`(filled)가 옅은 파랑이라 "파일 선택", "저장 위치 선택", "Finder에서 보기", "같은 설정으로 다시", 준비 화면 "취소"가 눌리지 않는 버튼처럼 보인다. 보조 동작은 `appearance="outlined"`로, 취소는 `variant="danger" appearance="outlined"`로 바꾼다. 실제로 비활성인 버튼과 구분돼야 한다.
4. **같은 이름의 버튼**: `PathField`의 버튼이 전부 "파일 선택"/"저장 위치 선택"이라 스크린리더·자동화에서 구분이 안 된다. 각 버튼에 `aria-label`로 항목 이름을 붙인다(예: "가사 파일 선택", "영상 저장 위치 선택", "MR 저장 위치 선택"). 음원 파일 선택 버튼은 "음원 파일 선택".
5. **오타**: 고급의 MR 방식 라디오 "스텀" → "스템(모델 반주)". 다른 쪽은 "원곡에서 보컬 빼기" 그대로.
6. **취소 문구 중복**: 취소를 요청하면 사이드카 메시지("취소 요청됨 — 현재 단계가 끝나면 중단합니다")와 앱 문구가 두 줄로 거의 같이 나온다. `cancel_requested`가 참이면 앱 문구 하나만 보이고 서버 `message`는 숨긴다.

## B. r3 리뷰 반영

1. **입력 음원을 바꿀 때**: 지금은 사용자가 고른 MR·영상·보컬 저장 경로와 가사·보조 파일이 그대로 남아, 다른 곡의 결과가 이전 곡 파일을 덮어쓸 수 있다(사이드카는 기존 파일을 덮어쓴다). 이렇게 바꾼다:
   - 입력이 바뀌면 사용자가 고른 저장 경로는 **고른 폴더는 유지하고 파일 이름만 새 곡의 기본 이름**으로 바꾼다(확장자 유지). 기본값을 쓰던 경로는 지금처럼 새 곡 기준으로 다시 계산.
   - 가사 파일·보조 파일은 곡마다 다르므로 입력이 바뀌면 비운다.
   - 바뀐 경우 폼 위에 한 줄 안내: "새 음원에 맞춰 저장 파일 이름을 바꾸고 가사 파일 선택을 비웠습니다."
   - 처음 음원을 고를 때(이전 입력 없음)는 안내하지 않는다.
2. **종료 상태 스냅샷이면 연결 닫기**: `jobStream.ts`에서 첫 `status` 스냅샷이 이미 종료 상태면 이벤트 이름과 관계없이 연결을 닫는다.
3. **완료 결과는 엔진 재시작에도 유지**: 결과 화면(`done`·`failed`·`cancelled`)이 이미 떠 있는 상태에서 사이드카가 재시작되면 결과는 그대로 두고 "진행 상황을 잃었습니다"를 보이지 않는다. 그 안내는 진행 중(`queued`·`running`)이던 작업만.
4. **플랫폼 중립 문구**: "Finder에서 보기" → "폴더에서 보기".
5. **경과 시간 기준**: `created_at`(요청 시각) 기준이므로 문구를 "요청 후 경과 시간"으로.
