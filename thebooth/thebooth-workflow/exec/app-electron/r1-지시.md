## 구현 범위

### 1. 프로젝트 구성 (`app/`)
- electron-vite 표준 구조: `src/main`, `src/preload`, `src/renderer`.
- 경로 별칭 `@/` → `src/renderer/src`(렌더러). main·preload에서 폴더 밖 참조가 필요하면 별칭을 따로 둔다(예: `@main/`, `@shared/`). 렌더러·main이 함께 쓰는 타입(IPC 계약 등)은 `src/shared/`에 둔다.
- `package.json` 스크립트: `dev`, `build`, `typecheck`(main/preload/renderer 전부), `lint`, `test`.
- 코드 레포 `.gitignore`에 `app/node_modules/`, `app/out/`, `app/dist/` 등을 추가한다.

### 2. BrowserWindow 보안
- `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, `webSecurity` 기본값 유지.
- 창 내 이동(`will-navigate`)과 새 창(`setWindowOpenHandler`)을 막는다.
- 렌더러 `index.html`에 CSP: 스크립트는 `'self'`(개발 모드 HMR에 필요한 만큼만 완화), `connect-src`는 `'self'`와 `http://127.0.0.1:*`.
- IPC 핸들러는 보낸 프레임의 출처가 렌더러 출처인지 확인한다.

### 3. 사이드카 관리 (main 프로세스, `src/main/sidecar.ts` 등)
- 개발 모드: 코드 레포 루트(= `app/`의 상위)에서 `uv run thebooth serve --port 0`을 실행한다. 레포 루트 경로는 main 소스 위치나 `app.getAppPath()`로 계산한다(하드코딩 금지).
- 토큰: `crypto.randomBytes(32).toString("hex")`(64자). 환경변수 `THEBOOTH_TOKEN`으로 넘긴다.
- 허용 출처: 개발 모드 렌더러 URL(`process.env.ELECTRON_RENDERER_URL`)의 origin을 `THEBOOTH_ALLOWED_ORIGINS`로 넘긴다.
- **stdin은 반드시 `pipe`**로 띄우고 아무것도 쓰지 않는다. stdout 첫 줄의 JSON `{"event":"ready","port":...}`에서 포트를 읽는다. 첫 줄이 그 형식이 아니거나 제한 시간(예: 60초 — `uv run`의 첫 동기화를 고려) 안에 안 오면 시작 실패로 처리한다. 이후 stdout·stderr는 main 콘솔에 접두사를 붙여 흘리고, 최근 stderr 몇십 줄을 보관한다.
- 상태: `starting` → `ready {baseUrl, token}` | `failed {message, stderrTail}`, 준비 후 예기치 않게 끝나면 `exited {code, signal, stderrTail}`. 상태가 바뀔 때마다 렌더러에 알린다.
- 재시작: 렌더러 요청으로 다시 띄운다(새 토큰). 이미 떠 있으면 먼저 종료한다.
- **종료**(앱 종료 `before-quit`, 재시작 전): 인증된 `POST /shutdown`(짧은 제한 시간) → 프로세스가 끝나길 기다림(사이드카는 작업자를 최대 5초 기다리므로 그보다 넉넉히) → 그래도 살아 있으면 **프로세스 트리 전체**를 강제 종료.
  - macOS: 자식을 `detached: true`로 띄워 프로세스 그룹을 만들고 `process.kill(-pid, "SIGKILL")`. `uv run`이 Python 자식을 띄우므로 uv만 죽이면 Python·ffmpeg가 남는다.
  - Windows: `taskkill /pid <pid> /T /F`.
  - 앱 종료는 정리가 끝난 뒤 한 번만 진행되게 한다(`before-quit`에서 `preventDefault` 후 정리 → `app.quit()` 재호출 시 통과).
- 사이드카 stderr에는 가사가 나오지 않지만, 앱도 가사 파일 내용을 읽거나 로그에 쓰지 않는다.
- 순수 로직(첫 줄 파싱, 출처 계산, 트리 종료 명령 선택 등)은 분리해 단위 테스트한다.

### 4. preload API (`window.thebooth`)
최소한만 노출한다. 타입은 `src/shared/`에 두고 렌더러에서 `window.thebooth` 타입 선언으로 쓴다.
- `getSidecar(): Promise<SidecarState>` / `onSidecar(cb): () => void`(구독 해제 함수 반환) / `restartSidecar(): Promise<void>`
- `openFile({ title, filters }): Promise<string | null>` — 파일 하나 선택, 절대 경로.
- `saveFile({ title, defaultPath, filters }): Promise<string | null>`
- `showInFolder(path): Promise<void>` — `shell.showItemInFolder`. 절대 경로이고 존재할 때만.
- `pathForFile(file: File): string` — 드래그 앤 드롭용. Electron 32+는 `File.path`가 없으므로 `webUtils.getPathForFile`을 쓴다.

### 5. 렌더러 공통 (`src/renderer/src/`)

- **작업 이벤트 상태 관리** `lib/jobEvents.ts` + 훅 `useJob(jobId)`:
  - 순수 리듀서로 만들고 단위 테스트한다. README "앱과의 계약"의 SSE 순서 규칙을 지킨다:
    - id 없는 첫 `status` 이벤트(스냅샷)를 초기 상태로 쓴다.
    - 이후 이벤트는 **마지막으로 적용한 순번보다 큰 것만** 적용한다(종료 이벤트가 이미 본 순번으로 다시 올 수 있다).
