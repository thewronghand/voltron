# r3: r2 리뷰 반영 + T3 만들기 화면

필독·확정 결정·하지 말 것은 r1 지시서와 같다. **예외: 이번에는 아래 A-1의 사이드카 SSE 변경에 한해 Python(`src/thebooth/server.py`, `src/thebooth/jobs.py`, 관련 `tests/`, `README.md`) 수정을 허용한다.** 그 밖의 Python 동작(분리·가이드·키·영상 결과)은 바꾸지 않는다.

## A. r2 리뷰 반영

1. **SSE 되감기 (사이드카 + 앱)**: 지금 사이드카는 새 연결에 id 없는 스냅샷을 보낸 뒤 커서 0부터 보관된 이벤트를 다시 보낸다. 그래서 구독할 때마다(첫 구독, 탭 전환 후 재구독, 복구 후 재연결) 화면이 과거 상태로 잠깐 되돌아간다. 이렇게 바꾼다:
   - 사이드카: 연결 시 스냅샷과 **그 시점의 마지막 이벤트 순번을 원자적으로**(같은 잠금 안에서) 얻는다. 스냅샷을 `id: <그 순번>`을 붙인 `status` 이벤트로 보내고, 그 순번 **이후** 이벤트만 보낸다. 스냅샷이 모든 과거를 담으므로 `Last-Event-ID`에 따른 재생은 하지 않는다(헤더는 무시해도 된다. 지금의 400 검증도 필요 없으면 없앤다). 이벤트가 하나도 없던 작업은 순번 0. 종료된 작업은 지금처럼 스냅샷 + 종료 이벤트 후 닫는다(종료 이벤트 순번이 스냅샷 순번 이하일 수 있다).
   - README "앱용 사이드카"의 SSE 설명과 "앱과의 계약"을 새 동작으로 고친다.
   - Python 테스트를 새 동작에 맞추고, "진행 중인 작업에 새로 연결하면 지난 이벤트가 다시 오지 않는다"를 추가한다.
   - 앱 리듀서: 스냅샷의 id를 마지막 적용 순번으로 쓴다. 이후 규칙(더 큰 순번만, 종료 후 비종료 무시)은 그대로.
2. **연결 오류 후 복구 불가**: 준비 화면 행이 `connection-error`면 버튼이 없어 사이드카 재시작 전까지 막힌다. 오류 메시지와 함께 "다시 받기"(새 pull)를 보여준다. 만들기 화면도 같은 원칙(연결 오류여도 "새로 만들기"로 빠져나올 수 있게).
3. **재연결 횟수**: 연결이 열리거나 이벤트를 정상으로 받으면 재연결 시도 횟수를 0으로 되돌린다(상한은 연속 실패 기준). 커스텀 복구는 CLOSED(HTTP 오류)에서만 돌고 네트워크 단절은 브라우저가 재연결한다는 정책을 주석으로.
4. **받은 양 문구 파싱 제거**: `receivedAmount`처럼 사이드카의 사람용 문구를 정규식으로 해석하는 코드를 없앤다. 다운로드 진행은 퍼센트만 보이고, 진행률이 1에 도달한 뒤 아직 완료가 아니면 "확인하는 중…"(sha256 검사·압축 해제)으로 표시한다. 모델 파일이 여럿이면 진행률이 파일마다 0부터 다시 시작한다는 점을 주석으로(현재 manifest는 사실상 파일 하나 — htdemucs의 둘째 파일은 수십 바이트).
5. **진행 막대**: 진행률 0%일 때 막대 전체가 채워진 것처럼 보인다(트랙과 채움의 대비 부족). 트랙은 옅게, 채움은 진하게, 진행률을 모르면 움직이는 막대. 준비·만들기 화면이 같은 막대 컴포넌트를 쓴다.
6. LOW:
   - 종료 실패 시 제목이 "시작하지 못했습니다"인데 본문은 "종료하지 못했습니다"로 어긋난다. 실패 문구를 맞춘다(제목을 일반화하거나 상태에 종류를 둔다). 재시작 IPC 실패 문구 "앱을 다시 열어 주세요"는 "다시 시작하지 못했습니다. 잠시 후 다시 시도해 주세요." 정도로.
   - `main/index.ts`의 `void sidecar.restart()`에 catch를 단다.
   - SSE `data` JSON은 최소 형태 검사(`id`·`status`·`kind`)를 거친다. 형식이 틀리면 연결 오류로.
   - 모델 행마다 `role="status"` 라이브 영역을 두지 말고 화면에 하나만(또는 진행률은 `aria-live` 없이).
   - 작업은 `done`인데 새로고침 후에도 설치 안 됨이면 "다시 받기"를 보인다.
   - `sidecar.ts`: 종료가 끝까지 실패해 `current`를 비울 때, 이전 프로세스는 stdin EOF 감시로 앱 종료 시 정리된다는 제약을 주석으로.

## T3: 만들기 화면

"만들기" 탭의 자리 표시를 실제 화면으로 바꾼다. 파일은 `src/renderer/src/features/make/` 아래에 둔다. 요청 본문 조립·표시 상태 결정·기본 출력 경로 계산은 순수 함수로 분리해 테스트한다.

### 입력
- 음원 파일을 창 안의 놓기 영역에 끌어다 놓거나 "파일 선택"(`openFile`, 필터: 음원 mp3·wav·flac·ogg·m4a)으로 고른다. 끌어다 놓은 파일 경로는 `window.thebooth.pathForFile(file)`로 얻는다. 여러 개를 놓으면 첫 번째만 쓰고 한 줄 안내. 놓기 영역 밖에 떨어뜨려도 창이 파일을 열어 버리지 않게 막는다.
- 고른 파일 이름과 폴더를 보여준다(전체 경로는 툴팁이나 작은 글씨).

### 옵션 (기본값은 CLI와 같게)
- **분리 모델**: 보컬 분리 모델(`purpose === "vocal-separation"`) 중 고른다. 기본 `htdemucs`. 별도로 **가라오케 모드 토글** — 켜면 `melband-roformer-karaoke`를 쓴다(모델 선택은 비활성화되고 "리드 보컬만 빼고 코러스는 남깁니다. 느립니다." 안내). 설치 안 된 모델은 고를 수 없게 표시하고 "준비 화면에서 받아 주세요" 안내. 모델 목록은 `GET /models`(T2와 같은 출처를 공유, 준비 화면에서 받기가 끝나면 갱신되게).
- **키**: 반음 단계 −12~+12(기본 0, − / + 버튼과 숫자). **남/여 전환**: 없음 / 남→여(+5) / 여→남(−5). 최종 반음(전환량 + 단계)을 같이 보여주고, ±12를 넘으면 실행 버튼 옆에 경고를 띄우고 실행을 막는다. 전환량 5는 상수 하나로 둔다.
- **멜로디 가이드**: 켜기/끄기(기본 끔). 켜면 음량(dB, −30~+6, 기본 −6, 슬라이더+숫자)과 추출기(FCPE 기본 / RMVPE — 설치 안 됐으면 비활성화)를 보인다. 가라오케 모드가 꺼진 채 가이드를 켜면 "깨끗한 가이드를 위해 가라오케 모드를 권장합니다" 안내.
- **가사 영상**: 켜기/끄기(기본 끔). 켜면 가사 파일(필수, `.txt`), 보조 파일(발음·번역, 선택), 언어(ja 기본, 선택지 ja·ko·en·zh 정도), 영상 저장 위치를 보인다. 가사 파일 내용은 읽지 않는다(경로만 사이드카에 넘긴다).
- **저장 위치**: MR 출력(`.mp3`)은 `saveFile`로 고르며, 입력을 고르면 기본값으로 입력과 같은 폴더의 `<이름>_MR.mp3`를 채운다(키가 0이 아니면 `<이름>_MR_+2.mp3`처럼 최종 반음 포함). 영상은 `<이름>_가사.mp4`. 사용자가 직접 고른 경로는 자동으로 덮지 않는다.
- **고급**(접힘): MR 방식(stems 기본/subtract), 분리한 보컬도 저장(선택 시 경로).

### 실행과 진행
- "만들기" 버튼 → `POST /jobs/make`. 400이면 사이드카의 한 줄 메시지를 **그대로** 폼 위에 보여준다(가공 금지). 202면 받은 `job_id`를 `useJob`으로 구독한다.
- 진행 화면: 이번 작업에 해당하는 단계만 순서대로 나열한다 — `load` 불러오기, `separate` 보컬 분리, `pitch` 음높이 추출(가이드 켰을 때), `align` 가사 정렬·`render` 영상 만들기(영상 켰을 때), `write` 저장. 지난 단계는 완료 표시, 현재 단계는 진행률 막대(진행률이 `null`이면 움직이는 막대) + 퍼센트, 마지막 `message`를 한 줄로.
- 대기 중(`queued`)이면 "앞선 작업이 끝나면 시작합니다".
- "취소" 버튼(`POST /jobs/{id}/cancel`). `cancel_requested`가 참이면 버튼을 비활성화하고 "취소 요청됨 — 지금 단계가 끝나면 멈춥니다"를 보인다.
- 실행 중에는 옵션을 바꿀 수 없게 한다. 작업 id와 폼 상태는 탭을 바꿔도 유지한다(T2와 같은 방식). 사이드카가 재시작되면 작업 id는 버리고 "처리 엔진이 다시 시작되어 진행 상황을 잃었습니다" 안내.
- 경과 시간을 보여준다(분리·정렬은 수 분 걸린다).

### 결과
- `done`: 만든 파일 목록 — MR, 보컬(있으면), 영상, ASS(Aegisub로 고칠 수 있다는 한 줄), ASS 백업(있으면). 항목마다 "Finder에서 보기"(`showInFolder`). `subtitle_overflow_count > 0`이면 "화면에 다 들어가지 않는 가사 줄이 N개 있습니다" 경고. 캐시 적중 여부는 작은 글씨로.
- `failed`: `error` 메시지를 그대로. `partial`이 있으면 "만들어진 파일" 목록과 Finder 버튼.
- `cancelled`: "취소했습니다" + `partial` 목록.
- 결과 아래 "같은 설정으로 다시" / "새로 만들기"(입력·출력 초기화) 버튼.

테스트: 요청 본문 조립(옵션 꺼짐 시 null 처리, 가라오케 토글 → model_id, 키 합산), 기본 출력 경로(같은 폴더·확장자·키 접미사, Windows 경로 구분자 포함), 단계 목록 결정, 표시 상태 결정.

## 완료 조건 / 검증 명령 (EXIT는 파이프 없이)

`app/`에서:
```
pnpm typecheck ; echo "EXIT=$?"
pnpm lint ; echo "EXIT=$?"
pnpm test ; echo "EXIT=$?"
pnpm build ; echo "EXIT=$?"
```
코드 레포 루트에서:
```
uv run ruff check . ; echo "EXIT=$?"
uv run ruff format --check . ; echo "EXIT=$?"
uv run mypy ; echo "EXIT=$?"
uv run pytest -q > /tmp/booth-pytest.log 2>&1 ; echo "EXIT=$?" ; tail -3 /tmp/booth-pytest.log
```
모두 EXIT=0. GUI 확인은 호출 세션이 한다. 새 파일이 400줄을 넘으려 하면 분해한다.
