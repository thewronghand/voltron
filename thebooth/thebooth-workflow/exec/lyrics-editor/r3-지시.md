# r3 — 리뷰 지적 반영

같은 레포·브랜치(`feat/lyrics-languages`), 누적 미커밋 변경 위에서. 메인 실측: 실제 앱 E2E 3회 연속 통과(멈춤 재현 안 됨).

1. **[MEDIUM] SSE가 '실행 중'에서 멈추면 화면이 계속 작업 중** (`SongDetail.tsx` snapshot·active): 재연결 실패 등으로 `job.snapshot`이 `running`에 머문 채 서버 작업이 끝나면, 재조회로 `song.job=null`·`last_job=done`이 와도 `job.snapshot`을 먼저 써서 `active`가 true로 남는다(버튼 비활성·busy·진행 '실행 중'). 서버 보고를 우선한다 — `song.last_job`이 같은 id로 종료 상태면 그것을 쓰고, `song.job`이 없으면 `job.snapshot`의 진행 중 상태로 active를 만들지 않는다. 테스트.
2. **[MEDIUM] 일본어 형식 자동 판별을 바꿀 수 없음**: 가사 탭 붙여넣기 단계에 형식 선택(Select, `@thewrong/ui` — `id`+`label` 연결): "자동 판별"(기본) / "원문·발음·번역 세 줄" / "한 줄이 한 블록". 일본어일 때만 보인다(다른 언어는 항상 한 줄 한 블록). 사이드카 `POST /lyrics/parse`·`PUT /songs/{id}/lyrics/editor`에 `format`(`auto`|`three_line`|`lines`, 기본 `auto`) 추가, `lyrics_editor.parse`가 따른다. editor.json에 저장·복원. 미리보기의 형식 표시는 자동일 때 "자동: …"으로. 파이썬·앱 테스트.
3. **[MEDIUM] 옛 editor.json이 새 규칙에서 블록 수가 달라지면 저장 가사와 화면이 말없이 어긋남** (`library.py` editor 복원, `LyricsEditor.tsx` previous 일치): 복원한 결정(blocks)의 개수가 현재 파싱 블록 수와 다르면 `previous`로 쓰지 말고(저장 서명을 맞추지 말고) dirty로 둔다. 테스트.
4. LOW: 루비 처리 체크가 화면에서 사라지면(형식이 한 줄이 되거나 언어가 바뀜) `ruby` 상태를 false로 되돌린다 / `library.py` `uses_ruby` 비교를 블록 수가 같을 때만(`zip(strict=True)` 전에 길이 확인).
