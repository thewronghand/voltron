## 사용자가 승인한 화면 구성
곡 상세에 **탭 두 개**: "만들기·내보내기"(지금 화면 그대로) / "가사". 가사 탭은 세 단계(단계 표시 + 이전/다음):
1. **붙여넣기**: 나무위키 가사를 붙여넣는 큰 입력칸 → 오른쪽(좁으면 아래)에 나눈 결과 미리보기(블록 번호, 원문 줄, 발음·번역 줄). **섹션 표시 줄(`[Verse 1]`·`[Chorus]` 같은 대괄호만 있는 줄)과 각주(`[1]` 같은 짧은 대괄호)를 지운다**(기존 `lyrics._extra_units` 규칙과 같게 — 함수로 뽑아 공유). 빈 줄로 구분된 단위를 블록으로, 블록은 원문 1줄 + 발음 + 선택 번역(2~3줄). 지운 개수와 블록 수 표시, 형식이 안 맞는 블록은 번호와 이유를 한국어로. '파일에서 불러오기'(txt를 열어 입력칸을 채움). 언어 Select(일본어·한국어·영어·중국어, 곡의 `lyrics_lang`).
2. **루비 확인**(일본어일 때만, 다른 언어는 이 단계를 건너뛰고 안내): 블록 카드마다 원문 줄을 한자 위 후리가나처럼 그린다(루비로 확정된 가나는 한자 위 작게, 가사로 확정된 가나는 본문). **한자 바로 뒤 가나가 루비인지 가사(오쿠리가나)인지는 글자만으로 구분할 수 없으므로** 추정해 표시하고, 불확실한 글자는 점선 밑줄 + 경고색, 그 글자를 누르면 그 위치에서 루비/가사 경계가 바뀐다(한자 묶음마다 "뒤따르는 가나 중 앞에서 몇 글자가 루비인가"를 상태로). "확인 필요만 보기" 체크(기본 켬)와 남은 개수. 카드에 발음 줄 음절 수 대조(✓/차이) 표시. '저장하고 정렬'로 곡에 저장 후 만들기(정렬) 작업 시작.
   - **추정 규칙**: 한자 묶음 뒤 가나 연속 구간마다 루비 길이 후보를 만들고, 블록 전체의 (루비 제거한 본문 가나 음절 + 루비 음절)이 발음 줄 음절 수와 같아지는 조합을 우선한다. 기존 `lyrics.py`의 음절 규칙(작은 가나 제외 `SMALL_KANA`, `_kana`·`_kanji`)을 재사용한다. 발음 줄의 음절 수는 `subtitles._is_pronunciation_syllable`과 같은 기준(한글 음절·장음 표기 처리 확인). 후보가 하나로 좁혀지면 확정(점선 없음), 여럿이면 가장 그럴듯한 것(예: 오쿠리가나로 흔한 끝 글자 `る・い・く・す・つ・む・う・た・て・し・ち・ら・れ` 등은 가사 쪽)을 기본값으로 두고 불확실 표시. 규칙은 함수 하나로, 단위 테스트(지어낸 예문)로 고정.
3. **타이밍**(정렬 결과가 있을 때): 블록 선택(이전/다음, 목록), 시간축에 **보컬 파형**(분리된 보컬로 사이드카가 만든 최소/최대 요약), 그 위에 **일본어 글자별 칸**(시작~끝). 칸 경계를 끌어 조정(이웃 칸과 겹치지 않게, 최소 길이 20ms, 블록 표시 범위 안), 선택한 경계를 키보드 ←/→ 50ms, Shift 10ms 이동. 재생(이 블록 구간, 곡 MR 또는 원곡 오디오 — 판단), 재생 위치 표시, 채움 미리보기(CSS로 글자 색이 시간에 맞춰 차오름). **발음 줄은 지금처럼 일본어 타이밍을 자동으로 따라간다**(편집 대상 아님). '이 블록 되돌리기'(자동 정렬값), '저장'.

## 저장·코어 설계 (메인 결정)
- **기존 로직 재사용**: 에디터 결과는 곡의 기존 두 파일로 저장한다 — `lyrics/lyrics.txt`(블록마다 루비를 뺀 원문 한 줄)와 `lyrics/lyrics-extra.txt`(블록마다 원문(루비 포함 그대로)·발음·번역, 빈 줄 구분). 저장 전에 `lyrics.load`로 검증하고, **각 블록의 `weights`(한자별 음절 수)가 사용자가 확정한 루비와 일치하는지** 확인한다(`_weights`의 오른쪽 탐욕 매칭이 사용자의 경계와 다르게 붙는 경우가 있으면 막거나 보고). 에디터 상태(원본 붙여넣기 텍스트, 블록별 루비 경계 결정)는 `lyrics/editor.json`에 둔다(형식 버전). 옛 곡(파일만 있고 editor.json 없음)은 두 파일에서 블록을 복원해 탭을 연다(보조 파일이 없으면 원문만).
- **곡 설정 Modal의 가사 파일·보조 파일 칸은 없앤다**(가사 탭으로 이동). 언어는 가사 탭에서. 1단계의 `PUT/DELETE /songs/{id}/lyrics`는 CLI·호환용으로 유지해도 되지만 앱은 새 API를 쓴다. CLI `--lyrics`·`--lyrics-extra`는 그대로.
- **글자 타이밍 수정**: 곡 폴더 `char_timing.json`(형식 버전)에 블록별 일본어 글자 `[start, end]` 목록을 저장하고, 블록을 **블록 텍스트(루비 뺀 원문)의 sha로 키**를 건다. `subtitles`가 블록 글자 타이밍을 만들 때(`_characters` 결과) 수정본이 있고 키가 맞으면 그것을 쓰고, 발음 줄은 그 결과로 기존 `_pronunciation`을 그대로 탄다. **재정렬해도 텍스트가 같은 블록의 수정은 유지**, 텍스트가 바뀐 블록의 수정은 버린다. 수정본이 없으면 출력은 지금과 바이트가 같아야 한다(CLI `make`는 수정본을 쓰지 않음 — 기본 경로 바이트 불변).
- **신선도**: 가사 저장 시 정렬은 stale(기존 규칙). 타이밍 수정은 정렬 결과를 바꾸지 않고 내보내기에만 반영. 곡 상세 상태에 "타이밍 수정 n블록" 표시.
- **사이드카 API**(기존 인증·오류 형식·409 규칙):
  - `POST /lyrics/parse` `{text, language}` → 블록 목록(원문·발음·번역, 각주/섹션 제거 결과, 루비 후보와 추정, 오류 블록). 곡과 무관한 순수 계산.
  - `GET /songs/{id}/lyrics/editor` → 저장된 에디터 상태(없으면 파일에서 복원).
  - `PUT /songs/{id}/lyrics/editor` `{text, language, blocks:[{ruby: [...]}]}` → 두 파일 + editor.json 저장(원자적), 곡 상세 반환. 진행 중 작업이 있으면 409.
  - `GET /songs/{id}/timing` → 블록별 표시 범위·일본어 글자·현재 타이밍(수정본 또는 자동)·수정 여부. 정렬 결과가 없거나 stale이면 400 이유.
  - `PUT /songs/{id}/timing/{block}` `{chars:[[s,e],...]}`(검증: 개수·단조·최소 길이·범위) / `DELETE /songs/{id}/timing/{block}`(자동값으로).
  - `GET /songs/{id}/waveform?points=N` → 보컬 스템에서 계산한 구간별 최소·최대(정규화), 캐시 가능(곡 폴더, 스템 키로 무효화).
  - `GET /songs/{id}/audio?kind=vocals|mix` → 재생용 오디오. `<audio>`는 Authorization 헤더를 못 보내므로 `/events`처럼 쿼리 토큰을 이 경로에만 허용한다(인증 미들웨어의 쿼리 토큰 허용 경로 목록에 추가, 다른 경로는 계속 거부 — 테스트). 형식·범위 요청(Range) 지원 여부는 판단(Electron `<audio>` 탐색이 되도록). 음원은 127.0.0.1 밖으로 나가지 않는다.
- 렌더러 CSP(`connect-src`·`media-src`)에 필요한 것만 추가.

## 테스트·검증
- Python: 나무위키 붙여넣기 파싱(섹션·각주 제거, 2~3줄 블록, 형식 오류), 루비 추정(확정/불확실, 음절 대조, 작은 가나), 에디터 저장 → `lyrics.load` 왕복으로 블록·weights 일치, 옛 곡 복원, 타이밍 수정 저장·검증·되돌리기·재정렬 시 유지/폐기, 수정본 반영 ASS(수정 없으면 기존과 동일 문자열), API 인증(쿼리 토큰은 events·audio만), 409, 파형 크기·캐시.
- 앱 vitest: 루비 경계 토글 로직, 단계 이동 조건, 타임라인 경계 드래그·키보드 이동 제약(겹침·최소 길이·범위), 저장 요청 본문.
- 가사 예문은 직접 지어낸 짧은 일본어(예: 夜空に光る星を 같은 수준)만.
