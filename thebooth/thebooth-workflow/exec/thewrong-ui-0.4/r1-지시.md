## 범위 (사용자 승인된 분류 — 이 목록 밖의 UI는 건드리지 않는다)

교체:
1. **남녀 전환 Select** (`app/src/renderer/src/features/songs/ExportForm.tsx`) — 숨은 `<label htmlFor="export-gender" className="sr-only">`와 그 위 주석을 지우고 Select에 `aria-label="남녀 전환"`을 준다. 트리거(role=combobox)의 접근성 이름이 "남녀 전환"인지 테스트로 확인한다. `w-40` 래퍼는 유지한다(0.4.0 Select도 최상위 컨테이너가 외부 className을 받지 않고 w-full). 그 주석을 "0.4.0 기준"으로 고친다. 해상도 Select의 보이는 `<label htmlFor="export-resolution">`는 그대로 둔다.
2. **range 슬라이더 2곳 → `Slider`**
   - `features/songs/BoxOpacityInput.tsx`의 `#box-opacity`(min 10, max 100, step 1) — `formatValue`로 `${value}%`.
   - `ExportForm.tsx`의 `#guide-level`(min -30, max 6, step 0.5) — `formatValue`로 `${value} dB`.
   - id·보이는 `<label htmlFor>` 연결·disabled·값 변경 동작(onSlide / guide_level_db 갱신)을 유지한다. 옆 숫자 입력칸은 바꾸지 않는다.
3. **불확정 진행 막대** (`components/ProgressBar.tsx`) — `value === null`도 라이브러리 `Progress`에 value를 생략해 렌더링한다(aria-label 유지). 앱 `styles.css`의 `@keyframes progress-indeterminate`, `.progress-indeterminate`, 그 reduced-motion 블록을 지운다(라이브러리 `ui.css`가 같은 클래스를 제공하고 `main.tsx`가 `@thewrong/ui/styles.css`를 이미 import한다). 숫자 value 경로는 그대로.
4. **곡 보관함 정렬 헤더** (`features/songs/SongList.tsx`) — 직접 만든 `sortHeader` 버튼을 지우고 Table 내장 정렬을 쓴다.
   - `title`, `added_at` 열에 `sortable: true`, header는 문자열 '제목', '추가한 날짜'.
   - Table에 `serverSideSorting`, `sortCycle="toggle"`, `initialSort={DEFAULT_SONG_SORT}`, `onSortChange`로 앱 상태 `sort`를 갱신한다. 실제 정렬은 지금처럼 `sortSongs(songs, sort)`로 계산해 data로 넘긴다(라이브러리 클라이언트 정렬은 표시 문자열로 비교해 같은 날 곡의 시간 순서를 잃으므로 쓰지 않는다).
   - `onSortChange`가 null을 주면(toggle에서는 일어나지 않아야 하지만 타입상 가능) `DEFAULT_SONG_SORT`로 둔다. key가 'title'|'added_at'가 아니면 무시한다. `any`·단언 남용 없이 좁힌다.
   - 라이브러리 순환(`sort-state.esm.js` nextSort, toggle)이 `nextSongSort`와 같은지 확인한다. 같으면 `nextSongSort`가 더는 쓰이지 않을 때 지우고 관련 테스트도 정리한다(테스트 의도가 라이브러리 순환으로 옮겨졌는지 보고).
   - 정렬된 열에만 `aria-sort`가 붙는 것을 렌더 테스트로 확인한다(기본: 추가한 날짜 descending).
5. **문장 안 밑줄 텍스트 버튼 → `<Button appearance="link">`** (모두 onClick 동작이라 `as="a"`는 쓰지 않는다)
   - `SongDetail.tsx`: 오류 문장의 '다시 불러오기', 모델 안내의 '준비 화면'
   - `SongList.tsx`: '준비 화면에서 받기', 오류 상자의 '다시 불러오기'
   - `ExportForm.tsx`: 사유 문장의 '준비 화면'
   - `RubyPreview.tsx`: '이 블록의 추정 확인 (N곳)'
   - **색은 지금처럼 주변 글자색을 따르게 한다** (사용자 결정). 라이브러리 link는 `text-primary-fg`(보라)를 넣는다. className으로 덮어 렌더 결과 class에 `text-primary-fg`가 남지 않고 의도한 색(상속 또는 지금 색 클래스: RubyPreview는 text-amber-800)이 이기는지 확인한다(`cn`이 tailwind-merge인지 `dist/lib/utils.esm.js`로 확인). 지금의 font-semibold/font-medium, text-sm 등 글자 모양도 유지한다. 덮어쓰기가 통하지 않으면 그 항목은 고치지 말고 멈춰서 보고한다.
   - 표 제목의 `hover:underline` 버튼은 바꾸지 않는다.

유지(바꾸지 않음):
- 곡 상세 탭(`SongDetail.tsx`의 tablist/tabpanel) — 0.4.0 Tabs는 선택한 패널만 마운트해 탭을 오가면 가사·타이밍 편집 중 상태와 내보내기 폼 상태가 사라진다. 사용자 결정으로 지금 구현 유지. 코드 수정 없음.
