# RoFormer 체크포인트는 모델 코드 버전을 탄다 · 남의 분리 결과는 정렬부터 의심

## 증상

1. 최신 `bs-roformer`(1.4)로 커뮤니티 체크포인트(Kim·becruily)를 `load_state_dict`하면 키가 수백 개씩 빠지거나 남는다. strict=False로 넘기면 조용히 엉뚱한 모델이 돈다.
2. audio-separator로 분리한 보컬+반주가 원곡과 안 맞았다(잔차 +1.1dB). 측정 지표가 전부 틀어졌다.

## 원인

1. lucidrains가 구조를 계속 바꿨다(0.4: attention 변경, 0.6~: hyper-connection, 1.x: linear transformer). 커뮤니티 모델은 ZFTurbo MSST가 복사해 둔 0.3.x 시절 구조로 학습됐다.
2. audio-separator는 (a) 입력을 피크 0.9로 줄여 넣어 출력도 그 음량(폭탄마는 0.567배)이고, (b) MP3 디코더 차이로 1105샘플(25ms) 앞당겨져 있다.

## 교훈

- 체크포인트를 붙일 땐 strict 로드로 **키 누락 0·잉여 0**을 먼저 확인하고, 맞는 버전을 핀 한다. 0.3.10이 두 모델 모두 정확히 맞았다.
- 다른 도구의 분리 결과와 비교할 땐 지표 전에 **상호상관으로 시간차, 최소제곱으로 이득**부터 맞춘다. 맞춘 뒤 잔차가 −80dB대로 떨어져야 정렬이 된 것이다.
- 입력 정규화도 결과에 영향을 준다(모델이 비선형). 청취로 고른 결과의 조건(피크 0.9)을 그대로 따른다.
